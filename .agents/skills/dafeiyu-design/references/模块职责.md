# 模块职责

评审一项能力时，先列出事实的所有者、执行者和能证明结果的回执。沿一次真实调用查到这三处，再决定接口放在哪层。[项目架构](../../../../文档/设计/项目架构设计.md#进程与模块)

| 遇到的问题 | 怎样核对 |
| --- | --- |
| 主 Agent 和插件子会话都要处理收信、取消或调用工具 | 用相同的运行条件比较两个入口，找出通用调度与各自的上下文、工具范围、领域进度。 |
| 交互需要缩短等待，并涉及供应商特有的模型参数 | 从用户能观察到的时机写用例，再沿模型层检查档位映射和协议编码。 |
| 插件要登记场景状态或动作 | 从对象及其前置条件追到实际执行者，核对卸载后回执归属，并检查空插件目录的普通问答。 |

书房可作为归属检查。面板能看见台灯亮灭，屏风后的角色可能只听见开关声，用户随后说“灯亮着”又产生一条有发送者的消息。沿这三个来源检查拟新增的读口是否意外扩大角色可知范围。[书房事实与感知](../../../../文档/设计/内置书房设计.md#事实归属与感知)
