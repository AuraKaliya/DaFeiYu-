# 模块职责

判断归属时，先找出谁拥有事实，谁能执行动作，以及谁能给出最终回执。

| 遇到的设计问题 | 项目取舍 |
| --- | --- |
| 主 Agent 与插件子会话都要处理收信、取消或工具调用 | 复用本体的通用运行能力。每个会话持有自己的上下文和当轮工具范围，领域任务的进展由掌握现场的一方记录。 |
| 希望某种交互节奏，又要配置供应商特有的模型参数 | 先在交互入口定义用户要获得的体验。供应商支持的档位、参数映射和协议编码由模型层解释。 |
| 新插件引入场景状态或动作 | 由插件给出对象、任务前置条件及业务回执，通过版本化接口使用本体能力。检查普通对话在空插件目录下仍可工作。 |

实现归属可从应用装配、Agent 会话、模型层和插件接口逐项核对。[架构与模块职责](../../../../AGENTS.md#架构与模块职责) · [当前架构](../../../../文档/设计/项目架构设计.md) · [插件接口](../../../../文档/使用说明/插件开发说明.md)

## 以房间感知检查边界

在内置房间方案中，面板能显示台灯当前亮灭。角色若被屏风挡住、只听见开关声，她可以报告声响和方向。用户随后告诉她“灯亮着”，这又是一条有发送者的消息。设计读能力时，房间判定感官可达性，Agent 获得对应证据，面板按显示权限取快照。由此可以检查界面上的信息有没有意外进入角色视野。[房间事实与感知](../../../../文档/设计/内置书房设计.md#事实归属与感知)
