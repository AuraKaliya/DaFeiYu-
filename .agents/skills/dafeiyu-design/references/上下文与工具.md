# Agent 上下文与工具

## 指令和证据放在哪里

| 内容 | 装配依据 |
| --- | --- |
| 人格与稳定约定 | 本体提供身份与表达方式。某入口长期适用的领域约定由该入口提供，保持简短。 |
| 当轮领域指引 | 按当前任务、事件、待答或工作状态挑选，标明由哪个领域提供。把适用指引放在当轮动态上下文中，便于追查它何时出现。 |
| 用户原话与观察 | 保留原消息、任务修订、指向对象、采样时刻、覆盖范围及未知项。引用原话、观测与插件解释时分别标明来源。 |
| 当轮工具契约 | 已知下一步需要的入口带齐参数和回执含义，其余能力按需查目录。目录、送模定义和执行校验共用技能定义。 |

先确定维护者和模型都能按序阅读的规则段，再调整措辞。依次交代职责与来源、授权与行动边界、判断与结算、输出与投递、人格与风格。人格负责面向受众的表达，切换语气时应能单独核对任务、真实性和交付条件。[规则段顺序与来源](../../../../docs/agent-loop-prompt-design.md#规则段顺序与来源)

内部来源可扩展。宿主标明真人原话、工具回执、插件采样和宿主摘要的来源与边界，适配器按目标模型的 Chat Template 选择原生角色。用 `user` 承载宿主状态时要保留来源标记，并转义外部正文。同样的 `<status>` 出现在玩家原话里仍归玩家。工具结果与原调用配对，整批闭合后再追加尾注。[装配与协议边界](../../../../文档/设计/Agent循环与上下文设计.md#context-projection-的输入和产物)

观察用于核对目标和现场条件，动作范围来自任务和用户授权。模型可根据这些事实判断要行动、补查、等待或提问。执行前由宿主和领域执行器分别核对各自负责的条件。[提示词与宿主职责](../../../../docs/agent-loop-prompt-design.md#大肥鱼的提示词与宿主职责)

需要追问时，把缺少的信息关联到依赖答复的步骤。已有授权、现场条件成立的独立工作可以继续。收到补充或改约后，沿原消息和当前修订重新核对受影响的步骤。

## 工具发现与执行权限

渐进展开的工具契约只在发现步骤追加一次，保留当时的版本和可还原的 schema。后续升级或撤权各留变化记录，便于解释模型当时看到什么。每次请求仍按协议传递当步可调用的定义，执行前按当前权限、任务与现场条件复核。用“发现后撤权”和“压缩后继续”两种情况检查这条边界。[工具与消息顺序](../../../../文档/设计/Agent循环与上下文设计.md#context-projection-的输入和产物)

## 状态注册与关注

本体启动、领域插件加载时注册各自的状态项，声明稳定键、所有者、描述、值 schema、版本和默认关注模式。登记后，事实提供方按业务条件更新，宿主按任务或事件选择展示。状态栏是代码维护的有损投影。解释一个值时，应能查明是谁在何时、对哪个对象、在多大范围内得到它，以及哪些结果仍未知。[注册与决策快照](../../../../文档/设计/Agent循环与上下文设计.md#agent-status-bar-的字段与更新时机)

每次模型决策都在合法的消息尾部读取带回合、步骤和快照号的结构化摘要，直接填出当前阻塞及其影响、最近已核实的实效、已过期的相关观察。工具后的下一步重新生成自己的尾注，旧状态保留在原步 Trace，完整状态按权限和快照号查询。原话或工具回执的时间戳固定，重试同一步时保留原时刻。

任务进度用有稳定编号、内容、枚举状态及时间记录的 TODO 项表示，完成状态以实际回执为据。环境摘要选择会改变当前判断的观察、操作累计和状态变化，给出某项观察转为显式关注的原因。

| 关注方式 | 作决定时看什么 |
| --- | --- |
| 隐式 `implicit` | 程序记录已接纳的事实，可按权限查询。出现影响任务的变化时，可提升为显式关注。 |
| 持续 `continuous` | 任务建立时按实例开启，完成、取消或替换时释放该任务的关注。多个任务关注同一对象时各自结算。 |
| 次数 `counted(n)` | 为后续相关逻辑决策展示指定次数。一次性事件取 `n=1`，预览和传输重试不额外耗次，重复回调沿原事件去重。 |

由调度器判定事件是否唤醒循环。一次唤醒沿用原事件号，把相关项放进统一状态栏。同一项也在持续关注中时只展示一份，任务结束后的终态回执仍可由事件展示一次。评审时分别核对事实是否过期、事项是否已解决、关注是否已释放。[关注模式与事件唤醒](../../../../文档/设计/Agent循环与上下文设计.md#关注模式与事件唤醒)

## 怎样精简

按这一步要作的决定选择字段和精度。摘要应保留会改变选择的差异、数据来源和查回原件的线索。涉及定位、边界或实际执行的判断从原始采样计算，再提供可读的展示值。

比较两份请求时，用同一任务下的 `model.prepared` 核对实际消息、工具定义及下一步收到的工具回执。模板摘要只能定位版本。补查是否值得，取决于返回的结果能否改变下一步判断。[实际送模与回放](../../../../文档/使用说明/构建与运行说明.md#trace-审阅与回放)
