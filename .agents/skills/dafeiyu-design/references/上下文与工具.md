# 上下文与工具

## 消息与权限

1. 选取一次真实或固定响应的回合，在 `model.prepared` 中定位系统规则、玩家原话、工具结果、插件采样与宿主尾注。逐项核对来源、适用时刻和未确认内容。[系统规则与工具契约](../../../../文档/设计/Agent循环与上下文设计.md#系统规则与工具契约)
2. 用“发现后撤权”和“压缩后继续”复查工具。对照首次披露的契约、当步实际送模的定义以及执行前授权。玩家原话包含 `<status>` 的用例可检查来源是否被误认。
3. 缺信息时写出依赖答复的那一步，再核对原授权下的独立工作是否继续。用户改约后回到原消息、当前修订和受影响的工作号检查结果。

## 状态注册与关注

从一个显式值逆向查到声明、事实拥有方、对象、采样时间、覆盖范围和有效期。在下一次决策、预览和重试时沿原快照复查，确认旧值的时刻和原件仍可解释。[冻结决策与状态查询](../../../../文档/设计/Agent循环与上下文设计.md#冻结决策与状态查询)

检验关注时取两个任务共用一个对象的案例，先完成其中一个，再重放同一事件并使另一个任务继续。分别核对事实是否过期、事件是否真正展示、该任务持有的关注是否释放。需要唤醒时保留原事件身份。[关注与唤醒](../../../../文档/设计/Agent循环与上下文设计.md#关注与唤醒)

精简上下文时，用同一任务前后的实际消息和工具比较下一步决定。保留会改变决定的差异及证据读口，审查显示精度是否影响执行格位或边界。[Trace 审阅与回放](../../../../文档/使用说明/构建与运行说明.md#trace-审阅与回放)
