# 管理中心与插件界面

把打开管理中心看作用户来观察大肥鱼。关闭或重建观察窗口只释放该视图，本体继续处理任务、收件及主动发言。改变界面时先沿一条真实数据通路核对事实的拥有方、UI 读口和实际回执，再决定如何呈现。

## 房间、板块与信箱

板块对应整个内容区。左栏上组向下排列，下组从底部向上排列，设置固定在左下。首版内置房间与设置两个板块，插件管理放在设置内。聊天位于房间右侧，切换板块时随房间收起，当前板块获得完整宽度。

房间先用纯文本展示最新状态与最近变化。核对来源、修订、取样或接收时间，区分未知、过期和已确认为空。将展示组件与宿主数据接口分开，后续造型可以复用同一批事实。旧书房图从当前素材和预览中清理。Trace 的位置采用现有默认，详细布局见[界面方案](../../../../docs/ui-framework-design.md#2-管理中心的界面组织)。

信箱由系统收取和回信。管理中心只读核对，一个信箱入口内按注册增加来源，读详情不消费信件。用户的文字始终通过右侧聊天交给主 Agent 的聊天信箱。验证时可对照打开详情前后的消费游标和回信数。

## 消息、上下文与渠道

主 Agent 有一个逻辑 Session，用户与她的消息长期保留在同一存储，每条有时间戳。直接接入主 Agent 的其他渠道共享这份历史，新消息应同步到已打开的窗口。MC 等插件子 Agent 保有自己的上下文、渠道与业务回执。检查共用循环及 SDK 时，要保留各入口的工具范围和输出归属。

用户文字、符合条件的环境事件都可驱动 Agent 循环。将模型输出中面向用户的回复或追问解析为聊天消息。打开面板、一次工具结果或内部结算本身不会产生用户发言。用固定响应核对关闭窗口期间的主动追问、重新打开后的补读，以及关闭 Trace 时的消息保留。首版聊天展示双方消息，聊天过程事件另行设计。长期记忆、压缩和送模上下文装配另有取舍。[消息与持久化](../../../../docs/ui-framework-design.md#55-主会话消息与持久化)

## 插件注册与配置

组件、窗体、板块通过宿主公开的接口注册。用独立测试插件跑通追加组件、替换开放组件、注册窗体和注册完整板块。内嵌弹层和独立桌面窗口都应能读取同一实例的状态。核对关掉其中一窗、插件忙碌而拒绝卸载、卸载成功后恢复默认组件，以及重载后拒绝旧视图回调的结果。

配置属于持久化数据。主体和各插件使用各自的配置文件，注册设置界面时同时声明有效的只读或可写状态，字段可采用默认策略。两类提供方都要验证真实读写。界面按声明展示，宿主按同一声明校验写入，分别反馈文件已保存和当前实例已采用的值。[配置与状态所有权](../../../../docs/ui-framework-design.md#8-配置与状态所有权) · [测试插件验收](../../../../docs/ui-framework-design.md#9-示例与关键流程)
