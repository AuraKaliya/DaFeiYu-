# Agent 上下文与工具

## 指令和证据放在哪里

| 内容 | 装配依据 |
| --- | --- |
| 人格与稳定约定 | 本体提供身份与表达方式。某入口长期适用的领域约定由该入口提供，保持简短。 |
| 当轮领域指引 | 按当前任务、事件、待答或工作状态挑选，标明由哪个领域提供。把适用指引放在当轮动态上下文中，便于追查它何时出现。 |
| 用户原话与观察 | 保留原消息、任务修订、指向对象、采样时刻、覆盖范围及未知项。引用原话、观测与插件解释时分别标明来源。 |
| 当轮工具契约 | 已知下一步需要的入口带齐参数和回执含义，其余能力按需查目录。目录、送模定义和执行校验共用技能定义。 |

观察用于核对目标和现场条件，动作范围来自任务和用户授权。模型可根据这些事实判断要行动、补查、等待或提问。执行前由宿主和领域执行器分别核对各自负责的条件。[提示词与宿主职责](../../../../docs/agent-loop-prompt-design.md#大肥鱼的提示词与宿主职责)

需要追问时，把缺少的信息关联到依赖答复的步骤。已有授权、现场条件成立的独立工作可以继续。收到补充或改约后，沿原消息和当前修订重新核对受影响的步骤。

## 怎样精简

按这一步要作的决定选择字段和精度。摘要应保留会改变选择的差异、数据来源和查回原件的线索。涉及定位、边界或实际执行的判断从原始采样计算，再提供可读的展示值。

比较两份请求时，用同一任务下的 `model.prepared` 核对实际消息、工具定义及下一步收到的工具回执。模板摘要只能定位版本。补查是否值得，取决于返回的结果能否改变下一步判断。[实际送模与回放](../../../../docs/run-guide.md#trace-审阅与回放)
