# 大肥鱼项目设计取舍

先明确用户要达成什么、谁掌握作决定所需的事实、哪个回执能证明结果。遇到运行问题，从原案例提炼同类任务的处理规则，再换一种表述、入口或现场条件核对适用范围。

本 Skill 供开发和分析时使用。工程约束以仓库约定为准，当前实现以源码和架构文档为准，具体开发次序查对应主题计划。[仓库约定](../../../AGENTS.md) · [设计与计划入口](../../../文档/设计文档.md)

## 何时维护

维护项目文档时先确定唯一正文所在主题。退役设计前核对现行实现、已采纳决定和兼容边界。计划逐项对照主线与验收，把已交付范围和剩余范围拆开登记。模块和工具的同一操作集中到有章节目录的中文说明，调用入口链接该章节。[状态判据与命名规则](../../../文档/使用说明/项目文档维护说明.md#判断开发进度)

日常开发与分析可以直接引用这些取舍。由用户主动发起设计取舍整理时，再回看相关讨论，提炼用户提出或明确赞同、能影响以后选择的原则。仍在比较的方案留在讨论或主题计划中。

维护时写清适用条件、会改变的设计决定和可追溯的依据。共用原则写在相应主题，领域参数和原案例写在领域页。新的取舍若修订了旧判断，就原位更新并合并重复内容。
