# 中文函数注释与代码分段规范

本规范适用于整个项目。注释应说明函数承担的系统职责，代码应按实际执行阶段组织，并保留影响正确性的关键约束。

## 适用范围

- 覆盖全部自有代码中的普通函数、成员函数、构造函数、析构函数、模板函数和内联函数，包括示例、测试及手写脚本。
- 第三方依赖、构建产物和生成代码不纳入修改。
- C/C++ 使用普通 `//` 注释；其他语言使用对应的单行注释符号。
- 含中文注释的源码使用 UTF-8。对外头文件和不继承项目字符集编译选项的独立消费者源码使用 UTF-8 BOM，让 MSVC 能识别文件编码；保留原有字符串内容及字符集编译选项。

## 函数注释

- 简单函数：在定义上方紧邻添加一行中文职责说明，适用于取值、判断、转发及简单转换等单一直接操作。
- 复杂函数：在定义上方紧邻添加两行中文注释，第一行是功能概要，第二行固定以 `步骤：` 开头，概括实际执行阶段。
- 按职责、执行阶段和控制流程判断复杂度，不设固定行数门槛。多阶段编排、状态迁移、异步协调、幂等处理及恢复流程通常采用复杂函数格式。
- 执行步骤通常概括为 2～5 个阶段，以 ` → ` 分隔；较复杂的分支按类别概括，不逐条翻译语句。
- 概要优先说明处理对象、产生的结果和维护的系统约束。通用工具函数直接说明技术职责。
- 异步流程区分提交调用与回调处理；条件分支明确按条件或状态分流，不把互斥分支写成必然顺序执行。

```cpp
// 判断任务是否已完成、失败或取消。
bool terminal(const Json& run);

// 执行宿主变更命令，并复用同一命令标识对应的持久化结果。
// 步骤：提取命令标识 → 核对并复用已有回执 → 在事务内执行命令并保存结果。
```

## 函数内分段

- 采用“空行分段，仅关键边界补注释”。不为每个阶段机械添加标题或编号。
- 相邻执行阶段之间留一个空行；阶段可包括参数与权限校验、幂等检查、分支选择、数据准备、调用或事务提交、结果处理。
- 同一组校验、同一组字段赋值和紧密关联的操作保持连续；简短函数可以没有内部空行。
- 分支、循环和回调内部也按实际阶段分段，不在每个控制语句或返回语句前机械插入空行。
- 允许将同一行的多条语句展开，以便阅读和分段；保持原有执行顺序、作用域、资源生命周期和异常处理边界。
- 函数体内仅在关键边界、不直观的设计理由或必要约束处补充中文注释。

## 声明、回调与特殊函数

- 头文件中的独立函数声明保留一行接口职责说明，执行步骤写在定义处。
- 头文件中的内联定义采用完整的简单或复杂函数注释规则。
- 简短、直接的 lambda 由所在阶段说明覆盖；承担独立复杂流程的 lambda 单独添加概要和步骤，并在内部按阶段分段。
- C ABI 函数指针说明接口职责及必要的线程、生命周期或返回值约定。
- 空实现、默认或删除的函数用一行说明默认行为或限制目的。
- 保留有价值的已有设计说明；英文说明依据实际实现翻译、整合，不丢失关键含义。版权及许可证声明保持原样。

## 术语和关键约束

- `Run`：运行任务；`Operation`：操作；`Call`：服务调用；`Job`：后台作业；`Scope`：作用域；`facts`：事实事件。
- 区分消息入队与持久化完成，不把提交成功描述为业务执行完成。
- 区分调用逻辑终止与物理执行完成，保留迟到结果处理的含义。
- 副作用为 `unknown` 表示待核对，不描述成未发生副作用。
- 准确说明状态写权限、事务、事实事件、绑定版本和作用域生命周期等实际约束，不夸大实现保证。

## 修改与验收

- 注释整理限于注释、空行、缩进、必要的语句断行及编码签名，不改变接口、执行行为或现有作用域。
- 发现疑似逻辑问题应单独记录，不混入注释整理。
- 检查全部自有函数的覆盖情况、注释准确性，以及步骤与代码分段的一致性。
- 核对代码标记及预处理指令未发生逻辑变化，并使用现有构建和相关测试验证；不为注释修改新增测试。
- 后续函数行为变化时，同步更新函数概要、执行步骤和相关边界说明。
