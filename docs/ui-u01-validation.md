# U01 原生 UI 容器验证

基线：`0e59334`。用户授权完成 U01，并要求小步开发、每步只运行必要检查。本阶段验证离线启动、Frame 授权、中文输入、焦点及资源回收；当前窗口是验证程序，不代表 U02～U09 的业务界面或插件 UI 已完成。

U01 自动验收已完成。按用户要求，最终检查采用隐藏原生窗口、真实 Frame 事件及 CDP 协议，没有继续使用 Computer Use。中文组合输入与组件焦点已验证；系统输入法候选窗、物理键盘和跨机器人工体验不计作已验收。

## 运行入口

GUI 是独立可选目标，终端不依赖 WebView2。安装微软 WebView2 Evergreen Runtime 后，可构建验证窗口：

```powershell
npm ci --prefix ui/web --ignore-scripts
cmake --preset windows-ui
cmake --build --preset windows-ui-debug
.\build\rebuild\windows-ui\bin\Debug\dafeiyu-ui-probe.exe
```

`--smoke` 隐藏窗口，运行固定离线及 Frame 探针检查后关闭，用退出码报告原生检查结果。`--interaction` 使用原生 WebView2 的 CDP 接口检查组合输入、键盘焦点和 Frame 回显，不操作系统键鼠或输入法设置。退出码 4 表示运行库不可用，1 表示容器或验收失败。协议模拟不等于 Windows 输入法候选窗的人工体验验收。

## U01a 独立离线容器

固定 WebView2 SDK 1.0.4314.35 及官方 NuGet 归档 SHA-256，按 `BUILD_GUI` 条件引入；静态加载器与 CMake 配置不进入终端目标。窗口在 STA 消息循环中创建浏览器，程序目录下的 `ui` 映射到本地 HTTPS 来源，不依赖当前工作目录或页面服务器。异步创建回调仍未完成时保留窗口责任；迟到控制器在关闭路径回收。

本机实际运行库为 157.0.4341.46。构建 Debug `dfy_ui_probe`；真实 WebView2 的隐藏导航与关闭通过，缺少本地资产时明确失败。另定向构建未开启 GUI 的终端并通过离线配置检查。官方 SDK 归档下载后核对校验值；本次构建复用其解包目录和已验证的 JSON 依赖，没有引用 `Old`。下一步增加来源与 Frame 授权校验；本单元尚未宣称完成浏览器进程退出或中文输入验证。

## U01b Frame 授权规则

[FrameScope](../ui/host/frame_scope.hpp) 仅在首次导航到宿主签发的精确地址时激活，来源、视图代次和固定方法分别核对；任何重新导航或显式撤销都会使旧授权永久失效。U01 只允许 `probe.echo`，不暴露模型或插件业务方法。固定本地资源来源包含专用的未授权反向测试来源，不能接受相似域名或其他协议。

仅构建 `dfy_ui_scope_tests` 并运行 Debug `ui.frame_scope`，1／1 通过，覆盖未激活、相似域、来源冒用、旧代次、业务方法越权、重载和销毁后重放。规则尚需下一单元与真实 Frame 事件结合验证，不能把纯规则测试当作浏览器授权已经验收。

## U01c 本地来源与事件回收

[LocalContent](../ui/host/local_content.cpp) 在导航前映射固定资源来源，限制主页面导航和弹窗，未登记页面资源由原生处理器返回本地 403。COM 事件登记由不可复制的登记对象管理，部分初始化失败及重复关闭均归还此前责任。构建每次同步页面资产，避免仅修改页面时仍运行旧文件。

定向构建 GUI 与授权规则目标，Debug `ui.frame_scope` 1／1 通过。真实浏览器探针允许一个固定的测试图片地址通过页面 CSP，再验证原生层确实拦截该请求；该请求不交给网络获取，导航及关闭成功。测试只说明页面资源边界，不声称禁用了操作系统或 Evergreen 更新器的网络。尚未验证真实 Frame 消息、中文输入或浏览器进程最终退出。

## U01d 真实 Frame 消息与导航授权

[FrameChannel](../ui/host/frame_channel.cpp) 将一个具体原生 Frame 与宿主签发的视图绑定，验证实际 Source、有界 JSON、精确字段、代次和固定方法。页面使用独立本地来源及 `allow-scripts allow-same-origin` 受限 iframe，不能取得主页面来源；同来源前提不能通过路径模拟。

只构建 Debug GUI 目标并运行真实隐藏窗口探针。中文及 emoji 的 JSON 回显、业务方法越权、旧视图、非法字段拒绝，以及改源导航触发原生授权撤销均通过。导航期间的页面消息不作为撤销证明，宿主直接核对事件处理后的授权状态。关闭或销毁后晚到回调先检查通道有效性，不再访问已释放 Frame。此处中文回显仅证明编码链路，实际输入法、焦点及重复回收仍待后续单元验证。

## U01e Vue 与输入验证页面

固定 Vue 3.5.45、Reka UI 2.11.0、Vite 8.3.8、TypeScript 5.9.3、Vue 编译插件 6.0.11 和 vue-tsc 3.3.14，以 npm 锁文件保存完整解析；本机 Node.js 24.13.0 满足依赖要求。CMake 只在 GUI 目标构建时调用类型检查及静态打包；Node 不进入运行目录。主界面和独立 Frame 为两个本地入口，产物按构建配置分别输出。

增加组合输入与可信标记计数、独立 Frame 回显，以及 Reka 对话框的焦点约束和组合期间 Escape 保护。自动探针通过 `#verify` 运行，普通打开窗口不自动撤销输入页面授权。严格 TypeScript 检查、静态构建、授权规则定向测试及实际 WebView2 隐藏探针通过；本单元只验收构建与探针，交互行为在后续单元单独验收。

## U01f 隐藏窗口输入与焦点协议验证

用户明确要求不采用 Computer Use 检查，后续改为隐藏原生窗口及内置 CDP 测试序列，不开放远程调试端口，不接受页面提供的任意脚本。已打开的验证窗口按正常关闭流程收起，不继续进行桌面交互。

协议检查覆盖主页面中文预编辑、提交文本和状态恢复，Tab／Shift+Tab、Enter 打开对话框、面板内焦点循环、组合期间 Escape 不关闭、结束组合后 Escape 关闭及焦点返回，并在独立 Frame 中再次组合输入并取得原生授权回显。浏览器内部焦点先交给控件，测试不得将隐藏窗口变成前台窗口。

检查发现 CDP 提交的组合结束事件可能被标记为不可信，原先按可信标记过滤会遗留“正在选字”。现将组合状态与可信标记分开记录；可信标记也不能单独证明真实系统输入。真实 WebView2 中 43 个串行协议步骤通过，未执行系统输入法候选窗、物理键盘或人工体验验收。该检查没有开放调试端口或连接用户浏览器。

## U01g 宿主签发与 Frame 反复回收

[ProbeHost](../ui/host/probe_host.cpp) 由原生主页面入口签发下一视图地址，并绑定实际创建的 Frame；页面不猜测代次。只有收到真实 Frame 销毁确认后才能重新打开。销毁回调归还事件、原生 Frame 接口与通道对象，统计副本不持有浏览器。测试窗口增加不激活样式，资源检查不申请键盘焦点。

新增 `--lifecycle` 隐藏验证模式，104 个协议及原生等待步骤完成 20 次 Frame 创建和销毁，逐轮确认活动、就绪与对象存活数归零；新文档重放上一代身份得到原生 `stale_view`。定向 GUI 构建、真实授权探针和 43 步输入检查再次通过。此单元确认 Frame 资源，浏览器进程组与临时目录的最终回收在下一单元处理。

## U01h 浏览器进程与临时配置回收

[BrowserProcesses 与 ProbeProfile](../ui/host/browser_lifetime.cpp) 为每次验证创建独立临时配置，只观察对应 WebView2 环境返回的进程。关闭时停止入口、归还 Frame 和浏览器接口，并继续推进 STA 消息，直到异步创建回调、CDP 调用及已观察进程的内核句柄全部结束。尚有控制器创建回调时保留环境，回调交还后重新观察可能新增的进程。

临时目录只在解析后的绝对路径仍位于本次专用根、且树内没有重解析点时删除；文件锁未解除会有界重试，失败保留并报告，不清理旧验证缓存或其他浏览器配置。最终窗口销毁延后到下一条原生消息，避免在 COM 回调栈内释放窗口。

Debug 的离线、输入、20 轮 Frame 回收和初始化中止模式均确认回调与通道归零、所属进程退出及目录清理。`--close-controller` 实际观察到关闭时仍有一个创建回调，最终归零并确认其创建的浏览器进程退出。另以固定不存在的运行库目录模拟 SDK 不可用，`--missing-runtime` 明确输出原因并返回 4，未卸载或改动本机 Evergreen。

程序向标准输出写入无正文 JSON 验收回执；`root_navigation_ms` 仅表示主文档导航完成时间，`elapsed_ms` 包含测试和收尾，不能作为完整产品启动或整体内存性能排名。正常关闭回执必须确认 `processes_exited`、`profile_cleaned` 为真，且创建回调、CDP 在途、活动 Frame 和通道对象均归零。

## U01i 浏览器离线状态启动

新增 `--offline`：在首次导航前仅对当前 WebView2 设置 CDP 离线条件，不修改系统网络。独立 Frame 先确认 `navigator.onLine` 为假，再运行编码、权限和导航探针；每次使用新配置目录，不能靠已有页面缓存通过。若协议设置失败，直接报告失败，不退回在线模式。

定向构建 GUI 并运行 Debug `ui.offline`，1／1 通过。本地 Vue 主页面、静态依赖和独立 Frame 在该离线条件下完成验证并正常回收。浏览器离线模拟与原生外部资源拦截分别验收，不将本项表述为断开了整台电脑或 Evergreen 更新器的网络。
