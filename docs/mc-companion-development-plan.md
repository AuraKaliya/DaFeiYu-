# MC 伙伴的通用交互流程

大肥鱼以同一个人格在主界面和游戏里与玩家交往。主 Agent、直接对话、内置房间和人格档案属于本体的产品能力。MC 陪玩由插件托管场景和整局状态，使用本体提供的子会话运行机制。本页记录已验证的开发基线、接下来的开发顺序和设计取舍。[当前架构](architecture.md#mc-陪玩插件) · [主面板与内置房间](main-agent-room-development-plan.md)

## 接下来的开发顺序

| 顺序 | 开发内容 | 验收条件 |
| --- | --- | --- |
| 1. 查清四格续补 | 用原固定响应复现先补两格、遮挡移除、继续补墙。按工作号查桥接接纳、剩余格的站位、支撑、视线、库存、走位和实际退出。由复现证据决定最小修复点。 | 保留已补两格和原绑定，按实际变化结算剩余两格，门洞及保护对象保持原状。仍然受阻时回执给出可核对的原因和已有实效。超时按原号回查。 |
| 2. 收敛动作契约 | 从放置的目标与授权核验入手，复用现有动作目录和步骤级门槛，使直调、普通队列和计划对同一实际目标得出一致裁定。让工具目录、参数校验、计划准入和执行逐步共用技能的参数、影响范围、资源与实效证据定义。 | 同一授权范围内的候选可按各入口支持的形式执行。待答、未获选、越界或未授权的候选给出对应原因。用等效普通采掘和补库存请求验证拒绝及对象保护跨入口生效。 |
| 3. 收敛按回执续行 | 用绕墙和已有「垫上来」路径检验同一组依赖、资源互斥、实际退出和分层结算规则。再用挖掘后继与缺口答复检验依赖证据，评估如何把 `afterPickup` 保存的后继意图接入共用流程。 | 到达、拾取、放置和答复分别由对应证据解锁。普通失败保留已有实效，只跳过相应后继，仍有效的跟随按原逻辑工作号恢复。明确纠正后等旧工作实际退出再推进新修订。停止后待机仍能收信。 |
| 4. 改善观察与响应 | 用固定世界和 Trace 对照一次观察能否提供所需证据。整理玩家、大肥鱼和原话现场的来源与时间，去除同批重复读数。若程序无法继续取证，或结果需要模型选择，再开启决策。 | 清楚的原话能启动持续任务，状态继续依靠程序推进。指向有歧义时可用针对性补查或局内追问，运行中的聊天仍能投递。按时间分段核对首答、首次动作、完工和实际发言。 |

补齐新技能时，可先审查合成的最小可执行范围和库存读回。配方、支撑面、墙体识别、绕行路线和垫高站位都按各自领域算法交付。模型理解原话并提出选择，程序按实际证据核验依赖、授权和旧工作退出，推进已接纳的计划。[动作目录](../plugins/mc/partner_skills.hpp) · [计划编排](../plugins/mc/partner_plan.cpp) · [可验证效果](../plugins/mc/partner_effect.hpp)

## 调整方向

- **本体统一运行。** 主 Agent 和插件子 Agent 共享模型调用、工具目录、上下文装配、权限、取消、信箱及 Trace。每个会话持有自己的任务上下文和工具范围。插件加载时登记有范围的阶段 Hook，各点声明可观察、改写、阻断或让出回合的边界。宿主按依赖和注册顺序执行。改写后的候选重新校验，已发生的效果随原工作回执记录。[Hook 注册与执行](architecture.md#hook-注册与执行)
- **领域上下文按用途装配。** 本体提供人格与投递语义。MC 提供原话、现场和任务状态，分别用流程指引提示决策时机、用领域经验说明怎样取证、用输出约束限定该场景需要表达的内容。工具契约负责输入、可用条件、作用范围与回执。观察预算、授权、等待、取消和防重复交付由程序核验，送模时带回已核实的状态。[装配](../plugins/mc/partner_loop.cpp) · [实际送模记录](run-guide.md#会话操作)
- **收信、求助和执行各有结算。** 软件事件经登记解析器交给通用服务。信箱按 ID 投递、按分类处理、按优先级取件、按唤醒策略决定是否开轮。日常澄清由 MC 局内追问，正式求助可走直接 ASK 或由主 Agent 提交结构化回信意图。答复截止、插件确认收件及动作当前可执行性分别结算。通用 ASK 按时接纳的答复保留到原插件确认收件，插件仍核对原任务修订、目标及现场。[信箱与 ASK](architecture.md#信箱优先级与唤醒)
- **整局由插件推进。** 从进场到离场，插件持有共同目标、原话锚点、待答和在途工作。意图层保存任务修订、依赖及可执行范围，执行层保存实际工作号与指令。移动、挖掘和放置共享前台，发言和只读观察可作后台工作。在途动作按已有计划推进或等待，遇到新消息、异常或待决策的结果再唤醒模型。短断线按原游标续读并用原工作号查回执，控制权等旧工作实际退出后交接。笔记和待办先随本局任务，后续参照其他领域的实际用例评审通用任务和记忆能力。[MC 运行边界](architecture.md#运行边界)

沿用 Codex 忙时输入对追加、排队和取消的区分。进度询问和执行中的聊天可带入事实，改约则以目标及授权修订判断。参考 dsh-mc-agent 的常驻目标、动作资源和实物检查点，以及 DeepClef 的在途聊天和真实退出回执。各场景沿同一工作生命周期核对，MC 的唤醒条件和行动授权来自本局分工。[Codex 忙时输入的既有设计参考](main-agent-room-development-plan.md#实现参考) · [MC 参考项目复核](mc-partner-capability-review.md#四个直接参考各自解决了什么)

## 验收和提交

每次交付一个可独立评审的功能点。以相同固定响应和游戏初始状态做前后对照，保留脚本、构建版本和场景标识。按玩家原话和消息号串起 `model.prepared` 的系统段、正文和可见工具，随后核对模型输出、实际调用、任务修订、工作号、程序结算、游戏读回和实际发言。离线回放复现准入与时序，隔离 Paper 核对真实方块、库存、位置和渠道效果。[运行记录和离线回放](run-guide.md) · [本地探针](../tests/mc-companion/README.md)

用同一组会话和工作身份分段记录原话收件、模型请求与返回、动作接纳、游戏实际退出、发言送达。先改善有效观察、工具成功率及已接纳工作的续行。用户实机体验用于评议理解和伙伴感，思考模式的体验对照使用同一构建和世界快照。真实模型表现仅记录，不执行自动验收。每步定向核验后单独提交并交付审查。[项目验证约定](../AGENTS.md)

## 一局游戏如何持续

| 参与方 | 持有的信息和决定权 |
| --- | --- |
| 主 Agent 与管理中心 | 持有共享分工、玩家与角色身份、会话归属。玩家从管理中心说的话带着原入口送给游戏会话；需要商量的事和玩家可见的实际发言可回查。 |
| 游戏里的大肥鱼 | 根据本局对话、当前目标和最近结果，决定是否接受分工、怎样行动、什么时候说话或等待。玩家提出委托与她接受委托分别记账。 |
| MC 插件 | 持有本局状态、现场证据和动作资源。声明本局可用技能，核验领域目标并调度游戏工作，记录进展、部分完成、实际退出或效果未知。 |
| 宿主 | 负责会话、模型请求、工具权限、通用取消、消息投递与 Trace。按原身份关联实际交付与回执。 |

### 1. 输入先记录为事实

玩家发言只需要原文、发送者、频道、游戏会话和消息号。环境输入描述实际变化，例如玩家到场、目标方块消失、角色掉落、连续移动但高度没有增加、库存更新。动作回执包含动作号、目标修订、采样时间、实测变化和未确认部分。私聊保留原来的可见范围；来源无法确认的数据保留其可信程度。

玩家入场首先意味着“人到了”。她可能过去看、开口搭话，也可能继续收拾手里的东西。宿主发布就绪状态用于操作界面，角色的第一句话和最后一句话均由她自己决定。自然语言的任何字面匹配都不直接改变控制权。

### 2. 模型在需要决定时看到足够的上下文

每次决策都让同一游戏会话看到自上次处理以来的原话和事件、与玩家已达成的约定、她当前打算、还在执行的动作、最近一次**何时**确认的实际进展，以及此刻可用的工具。进展很新就直接使用；目标指代不清、库存可能变化或读数过旧时，模型可以再观察。事件顺序有缺口时标注缺口。

新原话、与目标相关的现场改变、工作完成或受阻，都可以唤起决策。已有目标的空闲角色可在下一次机会决定续做、换方法、提议、等待或放弃目标。相同环境事件在等待期间合并，保留计数、时间跨度和最新样本；新聊天和关键变化保持可见。模型调用期间到达的消息进入下一次可用决策边界。长动作进行时，读取进展和处理聊天应有自己的入口。

例如，一次采集已经占用移动和手部操作。玩家此时说话，收件器只追加原话并通知会话。原动作继续持有这些资源，观察与发言可以并行。如果模型随后选了另一个需要移动的动作，宿主返回资源占用情况，模型可以请求暂停、替换或等待。执行前再核对世界、目标修订和工作号；同一工作重投沿用原身份。这个检查以动作是否仍获执行为依据，新的聊天序号本身不使动作失效。

本体人格提供身份和表达风格，当局约定与原话保存在事实正文。工具描述交代可执行操作、输入、影响范围和回执。以物品交付为例，自己的库存减少可用于说明丢出的数量，确认玩家捡到需要另一份实际证据。

### 3. 决定和实际执行各有身份

- **消息号**指向一次原始发言或事件，供回复、引用和去重。玩家连续说两句话不会自动创建两个任务。
- **目标及修订**记录她当前采纳的打算、适用范围和完成条件。模型可以维持、协商、修订或结束目标。收到建议本身不提升修订号。
- **动作号**对应一次交给游戏执行的工作。插件先返回已接纳或拒绝，再报告进展，最后提供实际退出及效果。模型有机会在工作尚未结束时继续听玩家说话。
- **发言号**对应一次要让玩家看见的表达，关联原频道、相关消息或目标，以及发送状态。管理中心和游戏共享这条记录。

例如，下面五条记录可以出现在同一局中。字段和值是接口讨论用例；它们没有指定模型应输出什么文本。

```json
[
  {"type":"action.progress","action":"a9","goal":"g2","revision":1,"sample":71,"broken":2,"picked_up_confirmed":1},
  {"type":"player.message","id":"m18","player":"p1","channel":"game","text":"要不我来收尾？"},
  {"type":"speech.requested","id":"s8","in_reply_to":"m18","channel":"game","text":"不要，我先做完"},
  {"type":"speech.sent","id":"s8","delivery":"d12"},
  {"type":"action.progress","action":"a9","goal":"g2","revision":1,"sample":72,"broken":2,"picked_up_confirmed":2}
]
```

这里玩家提议接手，她选择继续，原动作仍属同一目标。询问进度时，她可按已有证据回答或先核实，原动作仍可推进。玩家明确叫停时，执行器按原号停止工作，确认实际退出后待机并继续收信。断线、世界更换、宿主关闭或权限被撤销时，执行器按对应边界收尾，退出结果进入系统状态。

| 模型需要的操作面 | 输入与反馈 |
| --- | --- |
| 观察或重读 | 可给目标、对象或动作号。返回最近事实、采样时间、来源和未知项；询问当前进度不会占用角色的移动资源。 |
| 执行或调整技能 | 请求关联当前世界、目标修订和技能参数。立即返回是否接纳、工作号或拒绝原因。进展、部分效果和实际退出随后归到同一工作。 |
| 表达或交谈 | 可以自由组织文字，也可以只行动。发言携带可见频道和可选的原消息引用。若她在游戏里发问、玩家在管理中心作答，主 Agent 转交这条带原问题号的玩家输入，游戏里的她决定如何接话。 |
| 等待或延续打算 | 模型可留下想等的事件或下次复看的条件。宿主保存事件游标；历史不连续时发送缺口和可重读的快照。是否在醒来后继续以前的目标，由模型结合新情况决定。 |

### 4. 回合结束不等于事情做完

模型可以发言、调用技能、更新打算或选择等待。一个推理回合结束后，目标与在途动作仍有自己的生命周期。若她说会继续采，后续应能看到活跃目标、下一次工作、等待的条件，或她改变主意的新依据。收到更新的原话时让模型复看这些事实；旧世界的迟到结果只归原动作。取消时已经挖掉的方块和实际入包的物品仍然存在。

显式 `reply` 与可面向玩家交付的最终文本走同一个游戏投递入口。一次发言关联原消息或回合与投递身份，游戏送达由实际回执确认。显式发言在途、已经发出或结果未知时保留原票据。明确未发出时可由最终文本补发。独立消息可收到相同文字，内部结算留在系统侧。[玩家回复与结算](architecture.md#接续我已经搭的墙)

### 5. 管理中心展示她知道的事和已经发生的事

对话旁保留玩家实际能看到的发言和她主动提出的待讨论事项。点开后按消息、目标修订、动作和发言回执看关联，标出事实的来源和新旧。宿主故障、模型暂不可用、重连等由界面显示系统状态；伙伴回合故障在计划板中标为系统状态。分析“为什么这样做”时可呈现她公开说明的依据与所引用的观察；事后推测单独标注。

## 外部试玩怎样评

首轮实机围绕玩家已搭的墙，由用户先审查架构，再操作产品。试玩时记录原话、现场、实际发言和执行结果。记录允许多种合理表现，结合原上下文、游戏状态和工具回执判断。[首轮实机设计](../tests/mc-companion/README.md#首轮实机接续我已经搭的墙)

每次试玩评语至少写清**观察事实、我的判断、另一种可能解释、还缺哪项证据**。例如河边那局，玩家问为什么没动作，她用了 46 秒去采石并说会继续。记录能够证明两块圆石入包；我的判断是这次回应与玩家的疑问联系偏弱，且后续承诺没有持续目标支持。另一种合理理解是玩家在鼓励她自主找事做；究竟哪里耗时，还需要分段时间记录。评价不按某句话、固定调用顺序、是否服从或是否显得讨喜打分。

功能回归保留消息归属、工具权限、取消和效果、发言去重、断线与资源回收等确定性语义。固定响应或传输替身提供输入。伙伴探针以实际送模请求、工具结算和独立协议玩家收到的消息作对照，圆石固定探针继续覆盖采集和交付链路。[项目验证约定](../AGENTS.md)
