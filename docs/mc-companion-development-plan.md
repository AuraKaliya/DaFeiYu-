# MC 伙伴开发计划

大肥鱼以同一个人格在主界面和游戏里与玩家交往。主 Agent、直接对话、内置房间和人格档案属于本体。MC 插件持有游戏事实、局内目标和动作状态，使用本体托管的子会话。桥接持有独立的 Mineflayer 角色，负责采样、实际执行和回执。首批游戏基线是 Java 版 1.21.4，其他服端和版本按运行时能力分别验证。[当前架构](architecture.md#mc-陪玩插件) · [桥接入口](../plugins/mc/bridge/start.cjs)

### 游戏 API 封装与工具

桥接按游戏机制提供有界读写操作，工具按 Agent 要完成的事情组织。可以在一个工具内组合多次读取或协议操作，例如先查两侧容量再转移箱内物品。将常用观察保留在 `observe`，把配方、容器和地标等专项数据做成可按需展开的只读查询。执行工具沿用统一技能定义，分别标明独立调用、顺序队列和计划节点支持的形态。共用协议操作可从多个入口复用，各入口按实际用途披露。[现有工具与入口](#首批样例) · [Mineflayer 4.39.0 API](https://github.com/PrismarineJS/mineflayer/blob/4.39.0/docs/api.md)

| 创造模式与管理操作（独立评审） | 按实际服端能力与配置，分别讨论创造取物、批量世界编辑和服务端命令。记录作用范围与游戏结果。 | 管理入口有清楚的权限和可用状态，普通陪玩覆盖生存模式的常用任务。 |

### 事件源、归并与 Agent 唤醒

桥接把可核验的游戏信号记录成有界事实。插件根据当前目标、待答、在途工作和授权，决定推进可确定的步骤、登记待判断事项或继续观察。每条事实可查世界和出生代次、来源、对象、游标、采样时刻、前后值、证据覆盖及未知项，按需关联原话、任务修订和工作号。库事件表示一次触发，阈值或持续变化要由实际样本支持。下表的源是开发依据，具体回调随锁定版本和服端能力核对。[Mineflayer 事件](https://github.com/PrismarineJS/mineflayer/blob/4.39.0/docs/api.md#events) · [Pathfinder 2.4.5 事件](https://github.com/PrismarineJS/mineflayer-pathfinder/blob/2.4.5/readme.md#events)

| 事件源与状态 | 形成的事实 | 唤醒及验收条件 |
| --- | --- | --- |
| 连接和世界（补齐） | `spawn`、`respawn`、`game`、`end`、`kicked` 及世界读回形成进入、换图、离线、恢复和断档。 | 先检查世界与控制绑定，关闭旧入口并结算旧工作。短断线从原游标恢复，新世界只接纳新绑定。 |
| 玩家在场及可见性（补齐） | `playerJoined`、`playerUpdated`、`playerLeft` 及实体观察区分在线、进入同场、临时看丢和确认离场。 | 配对玩家进入、离开、进入会合范围或结束持续失联时交给当前任务。验证轮询一批同时包含离开和返回。 |
| 玩家原话与信箱（补齐） | 从现有 `playerChat` 包和可验证的频道来源取得配对玩家原话。主 Agent 委托、追问或批准答复、取消和事项到期各保留来源和编号。 | 保留原话及顺序，核对自己的发言回显及身份未知消息。待答和授权变化按原事项处理。一般插话时原工作仍可推进。 |
| 位置、站位和运动（补齐） | `move`、`forcedMove` 与有界 `physicsTick` 采样形成抵达、被推移、持续掉队、高差、落地或长时间没有目标相关进展。 | 普通转头、短时绕行和横向移动按动作完成条件分别判定。跟随现有异常合并可推广到其他动作。 |
| 路线和区块（补齐） | `path_update`、`path_reset`、`goal_reached` 与区块加载、方块变化关联，形成路径可达、暂缺数据、持续无路或原路径失效。 | 超时和部分路径先按现有证据处理，达到稳定窗口或条件改变才产生新决策。动态目标按实际距离与站位核验。 |
| 方块、设施与工作目标（补齐） | `blockUpdate`、`blockEntityData` 和定点复查提供目标消失、支撑变化、目标格空出、设施可用及观察覆盖改变。 | 同类批量变化保留受影响格和最后样本。目标区之外的变化只更新快照，相关变化才能解锁后继。 |

按下面的依赖安排可独立交付的功能点。新增某项游戏能力时，沿相应读口、动作、工具和证据交付，其他 API 可以在后续阶段继续扩展。每次提交说明引用的开发点、实际行为、验证入口和余下范围。整体验收以当轮授权范围为准。[项目开发与审查约定](../AGENTS.md#开发与审查)

| 建议顺序 | 本阶段交付与依赖 |
| --- | --- |
| 1. 补齐普通动作的读口和实效 | 首步用现有工作号读回普通移动的在途进展和实际抵达，覆盖有进展、无路与读数未知。随后接入采掘、入包、独立掉落查询及受阻判定。 |
| 2. 补齐领域事件及唤醒 | 和进展并行可先接入只读的血量或氧气样本，定义同类事件归并、升级和恢复。再用一个已接纳目标验证等待条件、危险与空闲独立预算和忙时送模。 |
| 3. 补齐逐条待答及实物交付 | 先核对原话到实际发言的票据和回执。独立交付生存丢物与拾取归属后，用一条完整的备料委托把在途进展、续行、交付、回复和扰动对照串起来。 |
| 4. 扩展储物、生产与建设 | 按容器、配方、长时间生产和建设分别交付。复用窗口互斥、库存证据、等待唤醒和按实效推进的计划。 |
| 5. 扩展生活、交通与联机 | 按游戏活动扩展生存、载具、远行、交易和共同协作。特权能力、跨局恢复和其他独立议题依各自评审范围安排。 |

| 场景 | 跨方向通过条件 |
| --- | --- |
| 备两块泥土交给玩家 | 零库存开局。采集中插话仍读到原工作进展，实际入包后继续原委托。在原玩家附近按约定数量丢出，分别核对投掷、指定玩家拾取及一次结果发言。逐项加入旧位置、缺失掉落观察和迟到回执，结果各自可解释。 |
| 卡在坑里或水里 | 区分有路径、持续无位移、缺净空和氧气未知。对同一次受阻合并读数，现场变化后复核。固定样本耗尽空闲额度后仍可处理危险事实，授权允许的恢复动作及求助分别可核对。 |
| 接续两处开口或四格墙 | 沿原话绑定目标、清楚记录待答，已授权的其他步骤继续。占用造成部分完成后只补剩余格，改约和迟到旧答复按原修订结算。 |
| 把物品入箱或放进熔炉 | 读工作站与物料，用实测数量结算部分转移或产出。等待期间可对话。窗口关闭或玩家接管，等原工作退出后再交给下一步。 |
| 同批原话及短断线接管 | 两条独立原话各有待答和结算结果。显式发言、最终文本及迟到回执沿原投递身份。旧实例实际退出前保留互斥，恢复时核对世界、游标和原工作。 |

## MC 技能封装与能力目录

### API 封装、工具与 Skill 的职责

| 层次 | 职责 |
| --- | --- |
| API 封装 | 在游戏桥接内封装方块、实体、移动、库存及配方等操作。一次工作对应可核验的效果，内部可多次读取和执行。只读操作返回数据、来源和采样时间。变更按原工作号执行、取消和读回实效。 |
| 插件工具 | 在当前回合提供观察、动作、编排和沟通入口。复用技能定义和步骤准入，核对任务修订、目标、权限及资源。程序处理已声明的依赖，记录接纳、进度、实际退出和效果。宿主提供通用工具、投递及 Trace。 |
| 插件 Skill | 随插件提供一类任务的适用条件、证据选择、工具组合、完成条件和受阻处理。Agent 根据当前任务和实效选择是否采用。工具权限和动作准入按本轮上下文及程序校验确定。 |

动作保留各入口支持的参数与操作，通过共用流程接纳、下发和结算。接纳时核对参数、任务范围和权限。依赖满足、资源可用时重验关键条件，再按分类交给执行器。放置核对目标格与支撑面，采掘核对目标与保护范围，合成核对配方和库存。结算以实际退出和读回证据推进对应后继，保留已完成部分。超时或效果未知时按原工作号回查，避免换号重复执行。已在途且仍有效的工作继续推进，观察与发言沿各自入口处理。[动作目录](../plugins/mc/partner_skills.hpp) · [计划编排](../plugins/mc/partner_plan.cpp) · [游戏回执校验](../plugins/mc/world_protocol.cpp)

每项技能的契约写清用途、分类、参数类型及单位、枚举和范围、返回结果、影响范围、所占资源、执行前置条件及重验时机。变更技能还写清部分完成、停止、效果未知和原号回查的语义。共用部分从现有技能定义提取，各入口补充自身接受的形态及限制。提示词用来引导何时查证、行动或追问，授权、对象保护和游戏条件由程序校验。

### 取证、动作准入与任务续行

- **确定动作范围。** 原话指定对象时，沿原消息引用已核验的对象，并在执行前重读。玩家委托结果并授权角色选择时，按材料、数量和允许区域选择现场候选。替代材料、额外数量或变更受保护对象以对应授权为前置。准星读取只增加可用证据，观察次数限制只作用于查询。
- **核对证据与条件。** 观察保留对象、来源、采样时间、当前世界、覆盖范围和未知项。搜索供选取候选，`verify` 读回供核验具体格。现场证据沿 `observation.id` 引用，原话指向沿消息号引用。提交时校验参数、任务和证据归属。依赖满足后，在实际执行前复核目标、材质、支撑、库存和必要的安全条件。可达性以能取得的现场检查及实际寻路回执为准。 [观察入口](../plugins/mc/partner_skills.hpp#L86) · [现场格核验](../plugins/mc/partner_task.cpp#L358)
- **给出具体受阻原因。** 工具回执指出缺证据、待批准、依赖未完成、现场受阻或效果未确认，并携带相关问题、观测或工作引用。缺哪项条件就补哪项。重复观察复用仍适用的结果，现场条件造成的阻塞在相关条件变化后复核。效果未确认沿原工作号查回执。 [计划结果](../plugins/mc/partner_plan.cpp) · [工作回执](../plugins/mc/game_work.hpp)
- **让新输入触发相关步骤复核。** 位置或对象补充归入原任务，重新核验依赖它的步骤。替代方案获批后仍检查当前世界、修订和保护范围。改约按新修订调整受影响的工作，冲突动作等旧工作实际退出，已发生效果沿原工作号保存。追问到期保留相关动作的授权要求，已经放弃的备选随其待答事项结算。 [局内追问](../plugins/mc/partner_question.cpp) · [任务修订与唤醒](../plugins/mc/partner_loop.cpp)

### 插件 Skill 的组织方式

已实现的 `skills` 提供能力目录和分类展开。首个 Skill 采用插件现有领域指引的装配方式，随插件版本发布。它提供「就近取材」的流程说明，包括何时查库存、如何选择原话指向或自身现场、怎样核对入包，以及受阻后可补的证据和需要玩家决定的事项。帮助说明随相关任务和可见工具提供，更细的工具参数由实际契约和目录提供。每次审查以 `model.prepared` 的实际快照为准。 [现有指引装配](../plugins/mc/partner_loop.cpp#L39) · [参考项目与提示词设计](agent-loop-prompt-design.md#大肥鱼的提示词与宿主职责)

`skills` 的 `procedures` 列出 Skill 名称。展开 `dig_break` 可读取「就近取材」的完整指引。当前取材原话、地面取材任务和正在执行或结算的采掘会在有相应工具的回合获得同一份指引。只有发言工具的结算回合按已有回执给出反馈。 [取材指引和目录](../plugins/mc/partner_loop.cpp)

Agent 用 Skill 选择方法和处理新的不确定条件。已明确的后继用计划依赖表达，例如实际入包后合成，或落块确认后尝试到达该站位。完成条件由游戏读回核验。场景需要新能力时先定位缺的是观察、动作封装还是入口契约，再补对应能力。

### 目录要回答的四个问题

| 问题 | 目录表达 |
| --- | --- |
| 已实现吗 | 按技能和变体标明实际支持范围及效果。例如现有合成覆盖原木或菌柄到相应木板。分类出现只表示可查到该类。 |
| 此轮可见吗 | 以实际送模快照为准，分别标明独立工具、普通队列和计划节点此轮可见的内容。主委托和结算使用各自的工具范围。 |
| 可从哪个入口提交 | 分别列直调、普通队列及计划支持的形态与此入口已知的限制。程序从已保存意图生成的后继单独注明来源，沿原任务和权限继续。 |

### 渐进式披露

`skills` 按分类列目录，每次可申请展开最多三类。`planNodes` 标明各分类的计划形态，`contracts` 分别记录 `direct`、`sequence` 和 `plan` 入口。当轮可见性取自实际送模的工具范围，顺序队列同时校验当前分类。展开分类可读与 `queue_actions` 同源的计划及顺序参数，并查看已知的目标绑定或入包依赖。只有实际扩大独立工具范围的展开才请求后续回合。任务绑定也能使移动与放置相关工具进入后续回合。

后续从同一目录生成分层视图。默认回合保留常用直调工具的完整参数、队列操作与依赖写法，以及可用节点的简要说明。任务所需、已有待继续节点和显式展开的分类在适当回合获得完整参数。列表查询只读已有状态，重复展开复用既有范围。新增有效展开沿用下一轮的快照和现有唤醒条件。已接纳计划和程序生成的后继沿任务及工作身份续行。

## 调整方向

- **本体统一运行。** 主 Agent 和插件子 Agent 共享模型调用、工具目录、上下文装配、权限、取消、信箱及 Trace。每个会话持有自己的任务上下文和工具范围。插件加载时登记有范围的阶段 Hook，各点声明可观察、改写、阻断或让出回合的边界。宿主按依赖和注册顺序执行。改写后的候选重新校验，已发生的效果随原工作回执记录。[Hook 注册与执行](architecture.md#hook-注册与执行)
- **领域上下文按用途装配。** 本体提供人格与投递语义。MC 提供原话、现场和任务状态，分别用流程指引提示决策时机、用领域经验说明怎样取证、用输出约束限定该场景需要表达的内容。工具契约负责输入、可用条件、作用范围与回执。观察预算、授权、等待、取消和防重复交付由程序核验，送模时带回已核实的状态。[装配](../plugins/mc/partner_loop.cpp) · [实际送模记录](run-guide.md#会话操作)
- **收信、求助和执行各有结算。** 软件事件经登记解析器交给通用服务。信箱按 ID 投递、按分类处理、按优先级取件、按唤醒策略决定是否开轮。日常澄清由 MC 局内追问，正式求助可走直接 ASK 或由主 Agent 提交结构化回信意图。答复截止、插件确认收件及动作当前可执行性分别结算。通用 ASK 按时接纳的答复保留到原插件确认收件，插件仍核对原任务修订、目标及现场。[信箱与 ASK](architecture.md#信箱优先级与唤醒)
- **整局由插件推进。** 从进场到离场，插件持有共同目标、原话锚点、待答和在途工作。意图层保存任务修订、依赖及可执行范围，执行层保存实际工作号与指令。移动、挖掘和放置共享前台，发言和只读观察可作后台工作。在途动作按已有计划推进或等待，遇到新消息、异常或待决策的结果再唤醒模型。短断线按原游标续读并用原工作号查回执，控制权等旧工作实际退出后交接。笔记和待办先随本局任务，后续参照其他领域的实际用例评审通用任务和记忆能力。[MC 运行边界](architecture.md#运行边界)

沿用 Codex 忙时输入对追加、排队和取消的区分。进度询问和执行中的聊天可带入事实，改约则以目标及授权修订判断。参考 dsh-mc-agent 的常驻目标、动作资源和实物检查点，以及 DeepClef 的在途聊天和真实退出回执。各场景沿同一工作生命周期核对，MC 的唤醒条件和行动授权来自本局分工。[Codex 忙时输入的既有设计参考](main-agent-room-development-plan.md#实现参考) · [MC 参考项目复核](mc-partner-capability-review.md#四个直接参考各自解决了什么)

## 一局游戏如何持续

| 参与方 | 持有的信息和决定权 |
| --- | --- |
| 主 Agent 与管理中心 | 持有共享分工、玩家与角色身份、会话归属。玩家从管理中心说的话带着原入口送给游戏会话；需要商量的事和玩家可见的实际发言可回查。 |
| 游戏里的大肥鱼 | 根据本局对话、当前目标和最近结果，决定是否接受分工、怎样行动、什么时候说话或等待。玩家提出委托与她接受委托分别记账。 |
| MC 插件 | 持有本局状态、现场证据和动作资源。声明本局可用技能，核验领域目标并调度游戏工作，记录进展、部分完成、实际退出或效果未知。 |
| 宿主 | 负责会话、模型请求、工具权限、通用取消、消息投递与 Trace。按原身份关联实际交付与回执。 |

### 1. 输入先记录为事实

玩家发言只需要原文、发送者、频道、游戏会话和消息号。环境输入描述实际变化，例如玩家到场、目标方块消失、角色掉落、连续移动但高度没有增加、库存更新。动作回执包含动作号、目标修订、采样时间、实测变化和未确认部分。私聊保留原来的可见范围；来源无法确认的数据保留其可信程度。

玩家入场首先意味着“人到了”。她可能过去看、开口搭话，也可能继续收拾手里的东西。宿主发布就绪状态用于操作界面，角色的第一句话和最后一句话均由她自己决定。自然语言的任何字面匹配都不直接改变控制权。

### 2. 模型在需要决定时看到足够的上下文

每次决策都让同一游戏会话看到自上次处理以来的原话和事件、与玩家已达成的约定、她当前打算、还在执行的动作、最近一次**何时**确认的实际进展，以及此刻可用的工具。进展很新就直接使用；目标指代不清、库存可能变化或读数过旧时，模型可以再观察。事件顺序有缺口时标注缺口。

新原话、与目标相关的现场改变、工作完成或受阻，都可以唤起决策。已有目标的空闲角色可在下一次机会决定续做、换方法、提议、等待或放弃目标。相同环境事件在等待期间合并，保留计数、时间跨度和最新样本；新聊天和关键变化保持可见。模型调用期间到达的消息进入下一次可用决策边界。长动作进行时，读取进展和处理聊天应有自己的入口。

例如，一次采集已经占用移动和手部操作。玩家此时说话，收件器只追加原话并通知会话。原动作继续持有这些资源，观察与发言可以并行。如果模型随后选了另一个需要移动的动作，宿主返回资源占用情况，模型可以请求暂停、替换或等待。执行前再核对世界、目标修订和工作号；同一工作重投沿用原身份。这个检查以动作是否仍获执行为依据，新的聊天序号本身不使动作失效。

本体人格提供身份和表达风格，当局约定与原话保存在事实正文。工具描述交代可执行操作、输入、影响范围和回执。以物品交付为例，自己的库存减少可用于说明丢出的数量，确认玩家捡到需要另一份实际证据。

### 3. 决定和实际执行各有身份

- **消息号**指向一次原始发言或事件，供回复、引用和去重。玩家连续说两句话不会自动创建两个任务。
- **目标及修订**记录她当前采纳的打算、适用范围和完成条件。模型可以维持、协商、修订或结束目标。收到建议本身不提升修订号。
- **动作号**对应一次交给游戏执行的工作。插件先返回已接纳或拒绝，再报告进展，最后提供实际退出及效果。模型有机会在工作尚未结束时继续听玩家说话。
- **发言号**对应一次要让玩家看见的表达，关联原频道、相关消息或目标，以及发送状态。管理中心和游戏共享这条记录。

例如，下面五条记录可以出现在同一局中。字段和值是接口讨论用例；它们没有指定模型应输出什么文本。

```json
[
  {"type":"action.progress","action":"a9","goal":"g2","revision":1,"sample":71,"broken":2,"picked_up_confirmed":1},
  {"type":"player.message","id":"m18","player":"p1","channel":"game","text":"要不我来收尾？"},
  {"type":"speech.requested","id":"s8","in_reply_to":"m18","channel":"game","text":"不要，我先做完"},
  {"type":"speech.sent","id":"s8","delivery":"d12"},
  {"type":"action.progress","action":"a9","goal":"g2","revision":1,"sample":72,"broken":2,"picked_up_confirmed":2}
]
```

这里玩家提议接手，她选择继续，原动作仍属同一目标。询问进度时，她可按已有证据回答或先核实，原动作仍可推进。玩家明确叫停时，执行器按原号停止工作，确认实际退出后待机并继续收信。断线、世界更换、宿主关闭或权限被撤销时，执行器按对应边界收尾，退出结果进入系统状态。

| 模型需要的操作面 | 输入与反馈 |
| --- | --- |
| 观察或重读 | 可给目标、对象或动作号。返回最近事实、采样时间、来源和未知项；询问当前进度不会占用角色的移动资源。 |
| 执行或调整技能 | 请求关联当前世界、目标修订和技能参数。立即返回是否接纳、工作号或拒绝原因。进展、部分效果和实际退出随后归到同一工作。 |
| 表达或交谈 | 可以自由组织文字，也可以只行动。发言携带可见频道和可选的原消息引用。若她在游戏里发问、玩家在管理中心作答，主 Agent 转交这条带原问题号的玩家输入，游戏里的她决定如何接话。 |
| 等待或延续打算 | 模型可留下想等的事件或下次复看的条件。宿主保存事件游标；历史不连续时发送缺口和可重读的快照。是否在醒来后继续以前的目标，由模型结合新情况决定。 |

### 4. 回合结束不等于事情做完

模型可以发言、调用技能、更新打算或选择等待。一个推理回合结束后，目标与在途动作仍有自己的生命周期。若她说会继续采，后续应能看到活跃目标、下一次工作、等待的条件，或她改变主意的新依据。收到更新的原话时让模型复看这些事实；旧世界的迟到结果只归原动作。取消时已经挖掉的方块和实际入包的物品仍然存在。

显式 `reply` 与可面向玩家交付的最终文本走同一个游戏投递入口。一次发言关联原消息或回合与投递身份，游戏送达由实际回执确认。显式发言在途、已经发出或结果未知时保留原票据。明确未发出时可由最终文本补发。独立消息可收到相同文字，内部结算留在系统侧。[玩家回复与结算](architecture.md#接续我已经搭的墙)

### 5. 管理中心展示她知道的事和已经发生的事

对话旁保留玩家实际能看到的发言和她主动提出的待讨论事项。点开后按消息、目标修订、动作和发言回执看关联，标出事实的来源和新旧。宿主故障、模型暂不可用、重连等由界面显示系统状态；伙伴回合故障在计划板中标为系统状态。分析“为什么这样做”时可呈现她公开说明的依据与所引用的观察；事后推测单独标注。

## 外部试玩怎样评

首轮实机围绕玩家已搭的墙，由用户先审查架构，再操作产品。试玩时记录原话、现场、实际发言和执行结果。记录允许多种合理表现，结合原上下文、游戏状态和工具回执判断。[首轮实机设计](../tests/mc-companion/README.md#首轮实机接续我已经搭的墙)

每次试玩评语至少写清**观察事实、我的判断、另一种可能解释、还缺哪项证据**。例如河边那局，玩家问为什么没动作，她用了 46 秒去采石并说会继续。记录能够证明两块圆石入包；我的判断是这次回应与玩家的疑问联系偏弱，且后续承诺没有持续目标支持。另一种合理理解是玩家在鼓励她自主找事做；究竟哪里耗时，还需要分段时间记录。评价不按某句话、固定调用顺序、是否服从或是否显得讨喜打分。

功能回归保留消息归属、工具权限、取消和效果、发言去重、断线与资源回收等确定性语义。固定响应或传输替身提供输入。伙伴探针以实际送模请求、工具结算和独立协议玩家收到的消息作对照，圆石固定探针继续覆盖采集和交付链路。[项目验证约定](../AGENTS.md)
