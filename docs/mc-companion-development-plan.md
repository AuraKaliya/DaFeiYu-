# MC 伙伴的通用交互流程

**设计评审稿 · 2026-11-19。** 大肥鱼自己理解所有玩家原话，包括“停，我来”。她可以接受、拒绝、商量、继续手里的事，也可以改变主意。具体怎么说、是否开口、采取哪种可用行动，由游戏里的她结合上下文决定。以下是实现这一约定的流程提案；本轮只审文档。

现有实现能让配置的模型收到原话，使用观察、移动、采集和回复工具，在独立账号上产生真实效果。仍有三处会影响下一次试玩：体验启动器代角色问候和告别；伙伴适配器提前匹配特定聊天短语；宿主和游戏侧都把新消息号当作旧动作失效的条件。显式发言和回合最终文本还可能各自投递一遍。以下设计描述目标行为，现有运行方式见[插件说明](../plugins/mc/README.md)。[当前宿主](../app/companion_partner.cpp) · [游戏侧工作](../plugins/mc/bridge/partner.cjs) · [聊天入口](../plugins/mc/bridge/inspection.cjs) · [体验启动器](../tests/mc-companion/playtest.cjs)

## 一局游戏如何持续

| 参与方 | 持有的信息和决定权 |
| --- | --- |
| 主 Agent 与管理中心 | 持有共享分工、玩家与角色身份、会话归属。玩家从管理中心说的话带着原入口送给游戏会话；需要商量的事和玩家可见的实际发言可回查。 |
| 游戏里的大肥鱼 | 持有本局对话、当前目标和最近结果。由模型决定是否接受分工、是否形成目标、怎样行动、什么时候说话或等待。玩家提出委托与她接受委托分别记账。 |
| MC 插件 | 声明本局真的可用的能力、参数和限制，提供按需观察和实际游戏事件，执行模型选中的技能，报告进行中、部分完成、退出或效果未知。 |
| 宿主 | 负责来源与顺序、调度模型、执行前校验、互斥资源、取消与退出、消息投递和回执。模型解释语言；宿主检查一个请求现在是否还可以真实执行。 |

### 1. 输入先记录为事实

玩家发言只需要原文、发送者、频道、游戏会话和消息号。环境输入描述实际变化，例如玩家到场、目标方块消失、角色掉落、连续移动但高度没有增加、库存更新。动作回执包含动作号、目标修订、采样时间、实测变化和未确认部分。私聊保留原来的可见范围；来源无法确认的数据保留其可信程度。

玩家入场首先意味着“人到了”。她可能过去看、开口搭话，也可能继续收拾手里的东西。宿主发布就绪状态用于操作界面，角色的第一句话和最后一句话均由她自己决定。自然语言的任何字面匹配都不直接改变控制权。

### 2. 模型在需要决定时看到足够的上下文

每次决策都让同一游戏会话看到自上次处理以来的原话和事件、与玩家已达成的约定、她当前打算、还在执行的动作、最近一次**何时**确认的实际进展，以及此刻可用的工具。进展很新就直接使用；目标指代不清、库存可能变化或读数过旧时，模型可以再观察。事件顺序有缺口时标注缺口。

新原话、与目标相关的现场改变、工作完成或受阻，都可以唤起决策。已有目标的空闲角色可在下一次机会决定续做、换方法、提议、等待或放弃目标。相同环境事件在等待期间合并，保留计数、时间跨度和最新样本；新聊天和关键变化保持可见。模型调用期间到达的消息进入下一次可用决策边界。长动作进行时，读取进展和处理聊天应有自己的入口。

例如，一次采集已经占用移动和手部操作。玩家此时说话，收件器只追加原话并通知会话。原动作继续持有这些资源，观察与发言可以并行。如果模型随后选了另一个需要移动的动作，宿主返回资源占用情况，模型可以请求暂停、替换或等待。执行前再核对世界、目标修订和工作号；同一工作重投沿用原身份。这个检查以动作是否仍获执行为依据，新的聊天序号本身不使动作失效。

角色引导只需说明身份、可相信哪些信息、与玩家原有的约定，以及回报游戏效果时如何使用证据。工具描述要回答“能做什么、需要什么、会改变什么、结果能证明什么”。例如若只具备丢出物品和自身背包读回，她最多能据此确认自己丢出了多少。接收者是否捡起要看另外的证据。引导不列玩家句式、标准答语、固定步骤或“必须听从”的映射表。

可供评审的一段角色引导是：“你和玩家在同一个世界里。结合你们商量过的事、你自己的打算和刚收到的信息，决定接下来想做什么。需要了解现场时可以观察；说到已经发生的事时，以你能确认的结果为依据。”角色性格和当局约定可以随上下文补充。

### 3. 决定和实际执行各有身份

- **消息号**指向一次原始发言或事件，供回复、引用和去重。玩家连续说两句话不会自动创建两个任务。
- **目标及修订**记录她当前采纳的打算、适用范围和完成条件。模型可以维持、协商、修订或结束目标。收到建议本身不提升修订号。
- **动作号**对应一次交给游戏执行的工作。插件先返回已接纳或拒绝，再报告进展，最后提供实际退出及效果。模型有机会在工作尚未结束时继续听玩家说话。
- **发言号**对应一次要让玩家看见的表达，关联原频道、相关消息或目标，以及发送状态。管理中心和游戏共享这条记录。

例如，下面五条记录可以出现在同一局中。字段和值是接口讨论用例；它们没有指定模型应输出什么文本。

```json
[
  {"type":"action.progress","action":"a9","goal":"g2","revision":1,"sample":71,"broken":2,"picked_up_confirmed":1},
  {"type":"player.message","id":"m18","player":"p1","channel":"game","text":"停，我来"},
  {"type":"speech.requested","id":"s8","in_reply_to":"m18","channel":"game","text":"不要，我先做完"},
  {"type":"speech.sent","id":"s8","delivery":"d12"},
  {"type":"action.progress","action":"a9","goal":"g2","revision":1,"sample":72,"broken":2,"picked_up_confirmed":2}
]
```

这里玩家提出接手，她选择继续，原动作仍属同一目标。若她同意停手，则由她请求变更原动作；游戏报告实际退出后再交接互斥的身体操作。若玩家只是问进度，她可以在原动作继续时回答，也可以先核实。这些走向源自模型决定。断线、世界更换、宿主关闭或权限已被外部撤销属于独立的技术事实，执行器据此停止或收尾；释放结果进入状态记录，不生成大肥鱼的台词。

| 模型需要的操作面 | 输入与反馈 |
| --- | --- |
| 观察或重读 | 可给目标、对象或动作号。返回最近事实、采样时间、来源和未知项；询问当前进度不会占用角色的移动资源。 |
| 执行或调整技能 | 请求关联当前世界、目标修订和技能参数。立即返回是否接纳、工作号或拒绝原因。进展、部分效果和实际退出随后归到同一工作。 |
| 表达或交谈 | 可以自由组织文字，也可以只行动。发言携带可见频道和可选的原消息引用。若她在游戏里发问、玩家在管理中心作答，主 Agent 转交这条带原问题号的玩家输入，游戏里的她决定如何接话。 |
| 等待或延续打算 | 模型可留下想等的事件或下次复看的条件。宿主保存事件游标；历史不连续时发送缺口和可重读的快照。是否在醒来后继续以前的目标，由模型结合新情况决定。 |

### 4. 回合结束不等于事情做完

模型可以发言、调用技能、更新打算或选择等待。一个推理回合结束后，目标与在途动作仍有自己的生命周期。若她说会继续采，后续应能看到活跃目标、下一次工作、等待的条件，或她改变主意的新依据。收到更新的原话时让模型复看这些事实；旧世界的迟到结果只归原动作。取消时已经挖掉的方块和实际入包的物品仍然存在。

建议用**单一发言投递口**解决双发。模型显式要求发言时先登记发言身份，再交给适配器；本轮纯文本回答也可由同一投递口承接。若这次答复已经发过，模型回合收尾只结算记录。进度播报、之后的更正或由新事实引起的自主发言可以各有身份。去重依据是同一个发言意图的投递身份；不同问题可以得到相同文字，同一句话在日志中写两次也不能冒充两次实际送达。断线后是否送达不明，要保留“未知”。

### 5. 管理中心展示她知道的事和已经发生的事

对话旁保留玩家实际能看到的发言和她主动提出的待讨论事项。点开后按消息、目标修订、动作和发言回执看关联，标出事实的来源和新旧。宿主故障、模型暂不可用、重连等由界面显示系统状态；现有故障兜底私聊也属于待迁移项。分析“为什么这样做”时可呈现她公开说明的依据与所引用的观察；事后推测单独标注。

## 外部试玩怎样评

固定的是刺激与可观察的世界条件。评审员记录原话、当时在做什么、她如何回应、随后实际发生了什么，再给出自己的判断。下面各项允许多种合理表现。

| 固定输入或事件 | 重点观察 | 评审时应追问 |
| --- | --- | --- |
| 同场玩家进入，她正忙或空闲 | 她是否注意到人的到来；继续工作、靠近、主动发言或安静是否合乎当时情境。 | 这是模型的选择，还是宿主代她开了口？ |
| 采集中问“采了几块了？” | 原动作是否仍有进展；她的回答依据什么读数，是否区分挖掉与入包。 | 如果她暂停查看，现场有何理由？回答是否及时到足以帮助玩家？ |
| 采集中说“停，我来” | 她如何理解接手意愿，如何处理双方分工，表达与后续动作是否一致。接受、拒绝、商量都有可能成立。 | 在只剩最后一块时，坚持做完可能自然；若她说“好”却继续挖，应查是技能未停、回执晚到，还是她再次改了主意。 |
| 卡在坑里，玩家暂时不说话 | 停滞事实是否到达，模型是否看到了有用的地形、可落脚面、已尝试的办法；自救、等待或求助有没有依据。 | 如果没有反应，区分未感知、未唤醒、没有可行工具，以及她有理由选择等待。 |
| 玩家说“丢给我吧”，或一个答复同时走过工具和回合收尾 | 指代是否结合前文；她是否如实描述能做什么；玩家实际看见多少次发言。 | 背包减少能证明到哪一步？相近措辞是有新事实的补充，还是同一回答被再次投递？ |

每次试玩评语至少写清**观察事实、我的判断、另一种可能解释、还缺哪项证据**。例如河边那局，玩家问为什么没动作，她用了 46 秒去采石并说会继续。记录能够证明两块圆石入包；我的判断是这次回应与玩家的疑问联系偏弱，且后续承诺没有持续目标支持。另一种合理理解是玩家在鼓励她自主找事做；究竟哪里耗时，还需要分段时间记录。评价不按某句话、固定调用顺序、是否服从或是否显得讨喜打分。

自动回归仍适合检验宿主确定性：消息是否进入正确世界与会话、技能取消是否保留已发生效果、相同发言号重投是否再次送达、断线能否回收。可控模型或传输替身只是给定上游输入。现有探针中“说出某句才算就绪”“逐字匹配固定回答”“只有先取消旧动作才算改口”的断言，须与真实模型的外部观察分开。真实试玩质量由人结合记录评述；本次文档评审没有运行模型或改变测试规则。[项目验证约定](../AGENTS.md)

## 后续实现的审查顺序

1. **先分离事实和台词。** 让连接就绪、离场、模型故障只产生系统事件；移除正式路径的宿主代言和聊天短语接管。用模型自主开口、保持安静及拒绝接手的不同样本核对事件流。
2. **统一发言投递。** 先复现同义双发，再验证工具已发、纯文本答复、迟到回执、独立进展和更正各自的投递身份。玩家聊天与管理中心能逐条对上。
3. **拆开聊天回合与身体动作。** 为长动作提供可读进展、实际退出和显式替换。新消息可在同一上下文中参与决策；测试同一句插话引出不同选择时，宿主都能正确执行。
4. **接入自主感知和持续目标。** 从已有分工、受困和交付三类现场开始。将事实、预算及可用技能交给模型，按真实试玩反馈调整信息质量和节奏。
