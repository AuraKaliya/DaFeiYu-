# 插件 C ABI v1 契约

本契约对应 [公开头文件](../sdk/include/dafeiyu/plugin_abi.h)。头文件、[纯 C 查询 DLL](../plugins/examples/query/query.c)、[C++ 查询测试](../tests/sdk_abi.cpp)及 [PluginModule 查询校验](../plugins/runtime/module.cpp)已实现。宿主服务、实例生命周期、活动调用计数和事件桥接尚未实现；相关条款是后续实现必须满足的约定，不表示现有宿主已支持插件运行。

## 平台、导出与布局

- 首版仅支持 Windows x64，使用 VS2022 的 C11、C++20 验证。其他架构在头文件中拒绝，未承诺其他工具链兼容。
- 唯一查询导出名为 `dfy_plugin_query`，对应 `DFY_QUERY_EXPORT`。插件编译时定义 `DFY_PLUGIN_BUILD`；宿主通过导出名取得 `dfy_query_fn`，本体不链接插件导入库。
- C++ 声明包在 `extern "C"` 内，使用 `DFY_CALL`（`__cdecl`）。在 x64 上采用默认 x64 调用约定，不支持替换为 `__vectorcall`。参见 [C 链接](https://learn.microsoft.com/en-us/cpp/cpp/extern-cpp?view=msvc-170)和 [调用约定](https://learn.microsoft.com/en-us/cpp/cpp/cdecl?view=msvc-170)。
- 头文件对 ABI 结构使用 `pack(push, 8)` / `pack(pop)`，不改变包含方原有设置；C/C++ 验证均在外层 `pack(1)` 下包含头文件并检查恢复结果。参见 [pack 规则](https://learn.microsoft.com/en-us/cpp/preprocessor/pack?view=msvc-170)。

| 类型 | 大小 / 对齐（字节） | 关键位置 |
|---|---|---|
| `dfy_string_view` | 16 / 8 | `data` 0，`length` 8 |
| `dfy_error` | 260 / 4 | `length` 0，`text` 4，容量 256 字节 |
| `dfy_event` | 24 / 8 | `struct_size` 0，`kind` 4，`session_id` 8，`turn_id` 16 |
| `dfy_host_api` | 40 / 8 | `context` 8，`subscribe` 16，`unsubscribe` 24，`diagnostic` 32 |
| `dfy_plugin_api` | 48 / 8 | 版本与架构前缀 16 字节，`create` 16，`start` 24，`stop` 32，`destroy` 40 |

v1 布局固定，不按编译器枚举宽度传递状态，不传 `bool`、`size_t`、STL、C++ 对象或异常。`struct_size` 必须等于上述 v1 大小，`abi_version` 为 1，插件表的 `architecture` 为 `DFY_ARCH_X64`（逻辑值 1），`reserved` 必须为 0。所有函数指针均为必需项，不能为空。布局或函数签名变化必须使用新 ABI 版本，不能在 v1 下悄悄增加尾部字段。

## 查询与错误

`dfy_plugin_query(requested_abi, &api, error)` 不创建实例、不注册订阅，也不进行业务初始化。成功返回 `DFY_OK` 和 DLL 内只读静态表；重复查询不改变业务状态。失败必须把 `api` 输出清空；不支持的版本返回 `DFY_ABI_MISMATCH`，空输出指针返回 `DFY_INVALID_ARGUMENT`。表和其中函数指针仅在模块仍被宿主持有时有效，不得释放或在卸载后访问。

宿主在调用 `create` 前核对版本、大小、架构、保留字段及全部函数指针；插件在使用宿主服务前同样核对宿主表。版本 1 不接受只提供部分服务的宿主表。清单的 `abi_version` 必须与请求和返回表一致，`manifest_version` 只控制清单格式。查询入口的参数布局、错误缓冲格式与导出名保持稳定，未来版本显式协商，不能只凭清单跳过接口表检查。

| 状态 | 值 | 含义 |
|---|---|---|
| `DFY_OK` | 0 | 本次操作成功 |
| `DFY_INVALID_ARGUMENT` | 1 | 必需参数缺失或参数不符合契约 |
| `DFY_ABI_MISMATCH` | 2 | 请求版本或接口元数据不兼容 |
| `DFY_BUSY` | 3 | 当前状态不允许操作，或仍有活动调用 |
| `DFY_NOT_FOUND` | 4 | 当前实例不存在对应订阅 |
| `DFY_UNSUPPORTED` | 5 | 实现明确不提供该能力 |
| `DFY_FAILED` | 6 | 业务处理失败 |

所有返回状态的函数接受可选 `dfy_error*`。调用方分配缓冲，调用期间供被调用方写入；成功时将 `length` 置零，失败可写入至多 256 字节的有效 UTF-8，也可用零长度只返回状态。不得写越界、截断 UTF-8 字符或要求调用方释放任何内存。文本按长度读取，不要求末尾零；未计入长度的字节无意义。调用方先校验长度再使用，错误文本不应包含凭据、请求头或整份配置。未知非零状态一律按失败处理。

每个模块自行捕获自己的 C++ 异常并转为状态，`destroy` 和 `diagnostic` 也不得抛出异常。该约定不提供原生崩溃隔离；同进程插件仍须可信。

## 字符串与资源归属

- `dfy_string_view` 是 UTF-8 字节视图，长度不含额外终止符；长度非零时指针必须指向足够的可读内存，零长度允许空指针。配置必须为非空 JSON 对象文本，字段含义由插件校验。
- 配置视图只保证在 `create` 调用期间有效，插件保留值必须自行复制。宿主可以让自己的有效配置快照与实例一起存活，但插件不得依赖这个额外寿命。
- `dfy_event*` 只在当前事件回调中有效；诊断文本只在 `diagnostic` 调用期间有效。需要保留的内容由接收方复制。
- `dfy_host_context*` 是当前实例绑定的不透明宿主句柄，插件只可原样回传，不得解引用、伪造或释放。宿主服务表的地址和上下文必须稳定到插件停止、撤销注册并销毁完成。
- `dfy_plugin_instance*` 由插件创建和销毁，宿主不得解引用或释放。插件分配的资源由插件释放，宿主分配的错误缓冲、事件和配置内存由宿主管理。

## 生命周期与失败恢复

全部 ABI 入口、宿主服务和事件回调在同一宿主线程串行执行。首版不允许插件自建后台工作线程，也不提供会话操作、模型调用或工具执行服务。

| 操作 | 前提与成功结果 | 失败处理 |
|---|---|---|
| `create` | 提供稳定宿主表和配置视图，成功输出唯一非空实例 | 输出空句柄并自行回收部分分配；不能留下宿主订阅 |
| `start` | 对已创建实例调用一次，成功后可接收事件 | 宿主关闭事件入口，调用 `stop` 处理部分启动 |
| `stop` | 可处理未启动、活动、启动失败或上次停止失败的实例；成功进入已停止状态 | 保留实例、DLL 和宿主服务，维持入口关闭，只允许再次停止及清理所需服务 |
| `destroy` | 仅在停止成功且宿主已撤销全部注册后调用一次 | 无可恢复返回状态，不得抛错；返回后句柄立即失效 |

`stop` 成功后的重复调用必须返回 `DFY_OK`；已经停止的实例不重新 `start`，重新加载应创建新实例。停止失败可以在外部条件修复后显式重试，不能强制销毁、重新启动或继续卸载。

宿主后续必须给所有进入插件的调用及回调计数。卸载时若有活动调用，立即返回忙碌且不调用 `stop`；否则先关闭新入口，再停止。停止成功后撤销全部订阅和登记项，确保没有仍会调用插件或依赖其资源的回调，再销毁实例，最后释放宿主持有的模块引用。宿主服务表、上下文和配置所有者应覆盖这一清理过程。当前第 06 步不实现此计数或卸载流程。

## 宿主服务与事件

- `subscribe` 只能在当前实例的 `start` 或活动阶段调用；失败输出订阅标识零，成功返回当前上下文内唯一的非零标识。实例尚在启动时不投递事件，启动成功后才开放通知。
- `unsubscribe` 可在启动、活动、停止及停止重试过程中清理当前实例的订阅，其他实例或未知标识返回 `DFY_NOT_FOUND`。取消立即阻止尚未执行的通知，但回调和 `user` 资源必须保留到已开始的调用返回；自取消不能使当前调用使用悬空资源。
- `diagnostic` 在上下文存活期间可尽力输出，不承诺写出成功，也不产生递归事件。创建、停止、销毁期间可用于报告问题。
- 订阅只属于宿主绑定的当前实例；SDK 不接收插件自行指定的所有者 ID。插件可以传入自己的 `user` 指针，宿主只在回调时原样传回，不负责释放。

事件按订阅顺序同步通知；分发中新订阅下次生效，取消后尚未调用的订阅本次跳过。一个回调返回失败不阻断其他观察者、不回滚会话历史。回调不能重入问答或清空，也不能在执行中卸载自身；SDK 不提供这些操作的入口。

`dfy_event.struct_size` 为 24；`kind` 的 1、2、3、4 分别表示问答开始、完成、失败和会话清空，与宿主内部 C++ 枚举需显式映射。会话和回合标识沿用 [会话契约](../README.md#会话事件与同步重入保护)，清空的回合号为零。未知事件种类应忽略并返回成功，不读取未知数据。

## 当前样例与验证范围

`dfy_query_example` 只有查询能力：提供完整非空函数表，但 `create` 明确返回 `DFY_UNSUPPORTED` 且不产生实例。生命周期函数是查询样例的占位实现，不是可安装运行的 observer 插件；完整实例与事件桥接仍分别在第 08、10 步建设。

`sdk.abi` 在 C/C++ 两侧检查布局和打包设置，实际通过固定导出名查询 DLL，验证版本拒绝、重复查询、失败输出和调用方错误缓冲。07a 提供 [平台模块引用封装](../platform/include/dafeiyu/dynamic_library.hpp)，07b 的 [PluginModule](../plugins/runtime/include/dafeiyu/plugin_module.hpp)复用它完成查询校验；`plugins.module` 使用可控真实 DLL 验证返回状态、畸形表和失败回收，查询过程不调用生命周期函数。平台搜索方式参见 [LoadLibraryExW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw)。

`PluginModule` 不读取或回显查询错误正文，只报告状态码及宿主识别的契约错误；错误长度越界和成功时携带错误均被拒绝。成功接口复制到宿主保存，但函数地址仍依赖 DLL 引用；关闭前必须结束所有借用和调用，接口关闭后不可访问。非法指针、越界写入和跨 ABI 异常不属于可恢复的状态失败，仍受同进程可信插件边界约束。
