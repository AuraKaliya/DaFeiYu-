# Minecraft 游戏陪伴插件

本页说明当前可运行版本。伙伴将绑定玩家的在场变化和原话按序交给模型；发言和是否停手均由模型决定。[通用交互设计与实施进度](../../docs/mc-companion-development-plan.md)

默认伙伴模式按原游戏游标处理绑定玩家的聊天和在场变化，保存局内目标及最近实际回执。插件使用 `dfy.agent@1` 托管的独立子会话，沿用本体所选模型配置。模型可以发言、执行、继续或等待，插件根据玩家消息、验证过的现场变化和任务状态唤醒下一轮。`mc.companion/world` 返回角色 UUID、出生代次、维度、坐标、背包圆石总数及最近游戏信号的年龄。世界撤销时可读到 `null`，连接失败时工具返回失败。

在 D 盘等指定运行目录准备 Node 22 或以上环境，并按 `bridge/package-lock.json` 安装依赖。若将依赖装在源码目录外，设置 `NODE_PATH` 指向对应的 `node_modules`。为自己的连接在该运行目录创建 JSON 配置，例如隔离的本机测试服使用：

```json
{"channel":"companion","host":"127.0.0.1","port":25579,"username":"DfyCompanion","auth":"offline"}
```

从项目根运行 `node plugins/mc/bridge/start.cjs <配置文件>`。个人服务器连接可用 `auth: "microsoft"` 选择大肥鱼自己的玩家账号，登录缓存位于配置文件旁的 `profiles` 目录。开发验收使用本机测试身份。通道短名必须与 DLL 的独立设置一致，默认值为 `companion`。

要在适配器接收玩家原话，可在本地连接配置中给出 `owner`（玩家 UUID）和 `bridgeKey`（随机 32 字节的小写十六进制）。私有 `chat.read` 查询还须绑定该键和角色当前世界；普通世界查询不返回聊天。适配器只接受源于该 UUID 的游戏协议消息，线上要求通过签名校验。系统广播和角色自己的文字不构成玩家指令。保留窗口外重读会返回缺口，每批有消息数与字节上限。

地标使用 `"places":{"hillside":{"label":"山脚","dimension":"overworld","x":12,"y":-60,"z":0}}` 的形状。观察工具提供世界、玩家和背包，并可按坐标网格查看玩家或角色附近已加载的方块。移动可用地标、玩家或附近坐标。采集接受游戏注册表中的方块名和数量，也可锁定一格坐标。放置使用背包里的实际建材，指定一个空格，门的坐标取下半格。回执记录核实的目标格和材料读数。

基础范围包含 `observe`、`reply`、`skills` 和 `task_update`。用 `skills` 可了解十二类动作的当前实现和可用性。选定至多三类之后，下一轮送模才提供对应的详细契约。已有分类为观察、交流、查询、移动、挖掘与破坏、放置。[完整分类与契约](partner_skills.hpp)

构建目标 `dfy_mc_companion` 会在对应配置下生成 `mc.companion` 包目录。使用原终端的 `/plugins install "<包目录>"`、`/plugins load mc.companion` 显式装载，或由共享应用服务接入。普通模型问答保持独立。定向验收见 [MC 探针](../../tests/mc-companion/README.md)。

在用户数据目录的 `plugins/mc.companion/settings.json` 保存与适配器相同的 `channel` 和 `bridgeKey`。用 `dafeiyu --chat <模型配置>` 打开终端，加载插件后输入 `/companion open mc.companion`。等状态显示 `listening` 后可正常聊天或委托。每次技能调用绑定原世界和事件号。玩家在场、离场和原话分别进入模型。工作进行中收到新事件时，由同一配置的模型决定是否提前停止该项工作；随后在决策边界处理新事实。玩家可见文字来自实际发言工具，内部回合收尾不会变成第二句聊天。本机离线服请用普通聊天，`/tell` 的协议数据缺少可验证的玩家 UUID。

真人体验启动器为每局创建运行目录，调用 `dafeiyu --mc-partner CONFIG PACKAGE RUN_DIR`。该目录保存 `board.txt`、`game-actions.jsonl` 与 `DFY_TRACE` 指定的模型和工具日志。终端可用 `/companion board 会话号 [任务号]` 查阅伙伴对话。模型回合故障显示为计划板上的系统状态。凭据由现有模型层从配置中的环境变量读取。[启动与验收](../../tests/mc-companion/README.md#首次真人体验) · [日志审阅与回放](../../docs/run-guide.md)

## 本体委托与确认

`/companion consult "目标或问题"` 给主 Agent 一轮与当前伙伴通信的权限。主 Agent 可以委托、询问当前任务的进度，或读取已收到的回执。信箱接纳后可用 `/companion board 会话号 [任务号]` 查原请求及后来回执。插件独立处理委托，源自本体的请求会使用受限工具范围，采集需要玩家另行批准。进度查询使用已核实的游戏采样，可以在子会话运行时返回。

游戏动作可在候选参数中请求确认。`approval=game` 在游戏向配对玩家询问，`approval=main` 交由主 Agent 选择本体终端或游戏内投递。终端用 `/companion confirm 编号 修订 approve|deny`，游戏内通过普通聊天回复 `确认 编号` 或 `拒绝 编号`。插件记录首个符合身份和时效的答复，后续答复返回原裁定。当前确认期限为 25 秒。批准后仍需依据原世界、玩家和最新游标通过动作校验。本体委托的采集强制进入同一确认流程。

在聊天终端使用 `/companion wake manual` 可改为主动审查，然后用 `/companion review` 交给主 Agent。`/companion wake auto` 恢复到件后在主会话空闲时触发。问题已送、玩家已批准和动作确实发生可以分别查到相应记录。[架构与信箱规范](../../docs/architecture.md)

## 固定圆石场景

旧采石流程使用适配器设置 `"mode":"scenario"` 和终端命令 `/companion scenario mc.companion`。下面的查看、显式审批和自采归属判定用于这一场景。

要使用采集返程，另配置本世界的 `riverside` 会合地标。当游戏角色私聊询问时可回复“采 16 块带回来”，也可在受信终端用 `/companion approve 会话号 问题号 修订 请求号 数量` 成立同一委托。包按原消息绑定接单，角色使用背包中的合适镐，在原地标附近只挖看得见、够得着的圆石，按授权上限执行并回会合区。当前接入支持明确数量 1～64。

对于本地可控服务器，可在**适配器**配置中加 `observer`，其 `directory` 是只读观察端输出目录的绝对路径，`world` 是该服务器世界 UUID，`dimension` 是对应游戏维度。观察记录只用于判断实际拾取与带回。未配置或证据断档时仍可移动、采集，管理中心或终端只能据实展示已知库存和归属范围。查看、采掘和返程的验收分开保存。[本地验收说明](../../tests/mc-companion/README.md)

终端的 `/companion where 会话号` 可直接采用足够新的进展，或说明最后一次确认的位置并开启读取。`/companion where 会话号 meet` 用于现场会合，会返回新读取的编号，已有在途查询可以复用。读取期间游戏角色继续当前动作，查询本身不调用模型。

## 回顾一项委托

“停，我来”与其他玩家原话使用同一入口。宿主操作者可通过终端 `/companion stop 会话号` 显式请求回收。回收状态根据实际退出更新。

使用 `/companion board 会话号` 查看最近的玩家委托及可查任务号，使用 `/companion board 会话号 任务号` 回顾指定的查看。可从到岸回执沿采集委托、原问题和答复修订追到玩家原话与山脚观察。刚授权时显示“已授权，暂无投递回执”，投递后再显示游戏是否接单。G14 的介入与答复也按原任务关联。

共享应用的 `companion_board(session, task, after_message)` 在原宿主线程返回可信值副本。业务快照每次完整返回，游标只筛选该任务的主子消息，消息修订及缺口以整个会话的有界窗口为准。当前查看之外保留最近八项被接替的查看，超出范围时给出裁剪水位。查询不启动模型、刷新游戏或投递命令。
