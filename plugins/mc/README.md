# Minecraft 游戏陪伴插件

默认伙伴模式让绑定玩家的普通聊天进入游戏会话。宿主使用所选 DeepSeek 或 Qwen 配置，模型可以直接回复，也可以调用观察、移动、采集和回复工具。`mc.companion/world` 返回角色 UUID、出生代次、维度、坐标、背包圆石总数和最近游戏信号的年龄。世界撤销时可读到 `null`，连接失败时工具返回失败。总库存只描述当前持有量。

在 D 盘等指定运行目录准备 Node 22 或以上环境，并按 `bridge/package-lock.json` 安装依赖。若将依赖装在源码目录外，设置 `NODE_PATH` 指向对应的 `node_modules`。为自己的连接在该运行目录创建 JSON 配置，例如隔离的本机测试服使用：

```json
{"channel":"companion","host":"127.0.0.1","port":25579,"username":"DfyCompanion","auth":"offline"}
```

从项目根运行 `node plugins/mc/bridge/start.cjs <配置文件>`。个人服务器连接可用 `auth: "microsoft"` 选择大肥鱼自己的玩家账号，登录缓存位于配置文件旁的 `profiles` 目录。开发验收使用本机测试身份。通道短名必须与 DLL 的独立设置一致，默认值为 `companion`。

要在适配器接收玩家原话，可在本地连接配置中给出 `owner`（玩家 UUID）和 `bridgeKey`（随机 32 字节的小写十六进制）。私有 `chat.read` 查询还须绑定该键和角色当前世界；普通世界查询不返回聊天。适配器只接受源于该 UUID 的游戏协议消息，线上要求通过签名校验。系统广播和角色自己的文字不构成玩家指令。保留窗口外重读会返回缺口，每批有消息数与字节上限。

地标使用 `"places":{"hillside":{"label":"山脚","dimension":"overworld","x":12,"y":-60,"z":0}}` 的形状。观察工具提供所在维度、位置、绑定玩家位置、地标、背包、注视方块及可见候选。移动可用地标、玩家或附近坐标；移动本身关闭挖掘和垫方块。采集接受游戏注册表中的方块名和数量，也可锁定一格坐标。回执分别记录客户端核对的方块变化和背包净增减。

构建目标 `dfy_mc_companion` 会在对应配置下生成 `mc.companion` 包目录。使用原终端的 `/plugins install "<包目录>"`、`/plugins load mc.companion` 显式装载，或由共享应用服务接入。普通模型问答保持独立。定向验收见 [MC 探针](../../tests/mc-companion/README.md)。

在用户数据目录的 `plugins/mc.companion/settings.json` 保存与适配器相同的 `channel` 和 `bridgeKey`。用 `dafeiyu --chat <模型配置>` 打开终端，加载插件后输入 `/companion open mc.companion`。等状态显示 `listening` 后可正常聊天或委托。宿主将原世界和玩家消息号附在每次技能调用上，并把最终答复送回原玩家。新原话会中断正在执行的旧回合，再由模型结合前文和游戏读回决定下一步。本机离线服请用普通聊天，`/tell` 的协议数据缺少可验证的玩家 UUID。

真人体验启动器为每局创建运行目录，调用 `dafeiyu --mc-partner CONFIG PACKAGE RUN_DIR`。宿主将对话写入 `RUN_DIR/board.txt`，体验服适配器将技能参数、原消息号和游戏结果写入 `RUN_DIR/game-actions.jsonl`。终端可用 `/companion board 会话号 [任务号]` 查阅伙伴对话。缺少凭据或模型回合失败时会在游戏里给出提示。凭据由现有模型层从配置中的环境变量读取。[启动与验收](../../tests/mc-companion/README.md#首次真人体验)

## 固定圆石场景

旧采石流程使用适配器设置 `"mode":"scenario"` 和终端命令 `/companion scenario mc.companion`。下面的查看、显式审批和自采归属判定用于这一场景。

要使用采集返程，另配置本世界的 `riverside` 会合地标。当游戏角色私聊询问时可回复“采 16 块带回来”，也可在受信终端用 `/companion approve 会话号 问题号 修订 请求号 数量` 成立同一委托。包按原消息绑定接单，角色使用背包中的合适镐，在原地标附近只挖看得见、够得着的圆石，按授权上限执行并回会合区。当前接入支持明确数量 1～64。

对于本地可控服务器，可在**适配器**配置中加 `observer`，其 `directory` 是只读观察端输出目录的绝对路径，`world` 是该服务器世界 UUID，`dimension` 是对应游戏维度。观察记录只用于判断实际拾取与带回。未配置或证据断档时仍可移动、采集，管理中心或终端只能据实展示已知库存和归属范围。查看、采掘和返程的验收分开保存。[本地验收说明](../../tests/mc-companion/README.md)

终端的 `/companion where 会话号` 可直接采用足够新的进展，或说明最后一次确认的位置并开启读取。`/companion where 会话号 meet` 用于现场会合，会返回新读取的编号，已有在途查询可以复用。读取期间游戏角色继续当前动作，查询本身不调用模型。

## 回顾一项委托

在游戏聊天中由绑定玩家说“停，我来”，或在终端输入 `/companion stop 会话号`，会结束本次陪伴控制。在途工作退出前状态为“已请求停止”，只有来自原游戏代次的回执才能确认释放。断线则显示“游戏控制释放未核实”。此前已经核实的入包数量仍可在计划板查看。再次陪玩时启动新的适配器连接并打开新的陪伴会话。

使用 `/companion board 会话号` 查看最近的玩家委托及可查任务号，使用 `/companion board 会话号 任务号` 回顾指定的查看。可从到岸回执沿采集委托、原问题和答复修订追到玩家原话与山脚观察。刚授权时显示“已授权，暂无投递回执”，投递后再显示游戏是否接单。G14 的介入与答复也按原任务关联。

共享应用的 `companion_board(session, task, after_message)` 在原宿主线程返回可信值副本。业务快照每次完整返回，游标只筛选该任务的主子消息，消息修订及缺口以整个会话的有界窗口为准。当前查看之外保留最近八项被接替的查看，超出范围时给出裁剪水位。查询不启动模型、刷新游戏或投递命令。
