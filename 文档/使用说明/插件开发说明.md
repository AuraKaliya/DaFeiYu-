# 插件开发说明

供编写 Windows x64 可信原生 DLL 的开发者使用。安装 SDK 组件后，先在 PowerShell 进入安装前缀下的 `sdk`。本页示例命令在该目录执行。需要 VS2022 x64 C++ 工具、C11 或 C++20、CMake 3.28 及以上。

**目录**　[独立构建示例](#独立构建示例) · [插件注册与包布局](#插件注册与包布局) · [接入事件、工具或子会话](#接入事件工具或子会话) · [验证与排错](#验证与排错)

## 独立构建示例

### 构建观察包

`examples/observer` 通过相对路径使用 `include` 中的公开头。其 CMake 文件可以单独配置。

```powershell
cmake -S .\examples\observer -B .\build-observer -G "Visual Studio 17 2022" -A x64
cmake --build .\build-observer --config Release
```

生成包位于 `build-observer/Release/example.observer`，包含清单、观察 DLL 和默认配置。安装与加载步骤见[验证与排错](#验证与排错)。

### 构建状态面板包

在已安装的 SDK 目录中，用相同的公开头编译纯 C 工具生产方。

```powershell
cmake -S .\examples\status -B .\build-status -G "Visual Studio 17 2022" -A x64
cmake --build .\build-status --config Release
```

生成包位于 `build-status/Release/example.status`。加载后可用终端的 `/task` 读回 `idle` 或 `focus`，核对无参只读工具与需要确认的幂等变更。结果可先于退出到达，票据仅在实际退出后释放。[安装与加载步骤](#验证与排错)

安装目录没有 `examples/observer` 或 `examples/status` 时，确认已安装 SDK 组件。在源码树开发时，这两份示例源文件分别位于 `plugins/examples/observer` 和 `plugins/examples/status`，随整个工程构建。

## 插件注册与包布局

包包含 `plugin.json`、入口 DLL、可选默认 JSON 配置和必要私有文件。清单采用版本 1，声明插件 ID、名称、版本、ABI、包内入口及可选默认配置。私有 DLL 依赖放在入口 DLL 同目录；宿主加载时使用该目录和 Windows 系统目录的受控搜索。

路径必须位于包内，不接受链接或重解析点。默认配置随包发布，用户配置保存在宿主独立的用户数据目录。实际生效配置是创建实例时的只读快照；目录刷新不替换运行实例，重新加载产生新实例身份。

发布 Release 包，使用与宿主兼容的 x64 工具链和运行库。Debug DLL 仅用于开发验收，需要本机相应开发运行库。源码中的中文注释和公开头文件使用 UTF-8；此 SDK 头和纯 C 示例带 BOM，以便独立 MSVC 消费者识别。

插件清单可以声明 `"dependencies": ["example.provider"]`。宿主加载前检查所选包的传递依赖及环路，直接提供方须已显式加载。启动成功后绑定实际实例，该关系进入 Hook 排序及卸载检查。

使用公开头 `include/dafeiyu/plugin_abi_v2.h`，编译插件时定义 `DFY_PLUGIN_BUILD` 以导出 `dfy_plugin_query_v2`。通过 v2 引导返回生命周期和实际支持的能力表。C++ 插件在模块内将异常转换为 ABI 状态。[引导、分配与停止责任](插件接口说明.md#v2-引导与生命周期)

### 声明公开设置

插件可在包内 `ui/manifest.json` 登记公开的只读文本设置。`ui_schema_version` 取 1，`plugin_id` 与本包一致，`contributions` 中的 `kind="settings"` 条目以 `fields` 列出顶层配置键、`type="string"` 和 `access_mode="read_only"`。每个加载代次最多公开 32 个字段，每项 UTF-8 文本最多 4096 字节。公开副本和来源在合并包默认值与用户覆盖时固定。登记失败只影响设置视图，业务实例仍按自己的生命周期启动。源码树中的 `tests/fixtures/public_settings/ui/manifest.json` 可用于对照清单格式。

## 接入事件、工具或子会话

从要提供的行为选择能力，并按公开头声明的精确名称和版本注册或查询。工具操作的每次变更必须取得宿主授予的当轮权限。字段布局、跨线程限制和失败责任统一查[插件接口说明](插件接口说明.md#能力目录)。

| 开发任务 | 接入步骤与核对点 |
| --- | --- |
| 观察事件或处理特定交付 | 观察包先查询订阅与读取。宿主显式授予组成员或处理记录后才承担对应责任。拿到数据后在引用有效期复制或保留，停止时明确关闭或退出。[订阅、处理与组](插件接口说明.md#数据事件与处理) |
| 注册只读或可变更工具 | 以 `example.status` 对照描述、提交、轮询和释放。用同一票据分别验证业务结果、实际退出与回收。[工具与 Hook](插件接口说明.md#工具hook-与陪伴声明) |
| 信箱互通和后台推进 | 启动时接入信箱，发送者从 1 连续编号。出站容量不足时保留原编号和正文，在活动步骤重投。用同一实例区分入箱接纳、业务答复和真实退出。[信箱与子会话](插件接口说明.md#信箱子会话与状态) |
| 为子会话提供领域事实 | 包可提供 `agent/status.json`，声明本插件命名空间、版本、默认关注及可读工具。首帧提交基线，后续提交增量；沿原工作号回查事实、实效和退出。源码示例为 `plugins/mc/resources/agent/status.json`。[事实帧与工作回执](插件接口说明.md#事实帧与工作回执) |
| 注册陪伴角色或控制 Hook | 角色先登记状态工具及用途，再触发显式开局。Hook 声明阶段、依赖和会话范围，按宿主给出的当前权限处理。[角色与 Hook](插件接口说明.md#工具hook-与陪伴声明) |

## 验证与排错

编译后检查生成包内的 `plugin.json` 和入口 DLL。清单声明了默认配置时，再核对相应的 JSON 文件。需要从本地目录安装时，在含 `dafeiyu-cli.exe` 的 Runtime 中打开终端，依次执行 `/plugins install "生成包的绝对路径"`、`/plugins load <id>` 和 `/plugins list`，核对目录和实例状态。默认桌面管理中心可在设置页加载或卸载已安装的包。独立 SDK 提供编译所需的文件。

卸载返回忙碌时，核对在途调用、处理记录和外部使用者。停止接纳与实际退出分别取证，沿原实例查询后再重试，停止成功且宿主注册已静止时才销毁。ABI 布局或能力协商失败时，核对 x64、表大小、版本、必需函数及保留字段。定向 CTest 名称与发布检查见[接口验证](插件接口说明.md#验证与排错)。
