# 构建与运行说明

适用于 Windows 10／11 x64 的使用者与构建者。以下安装包命令从解压后的程序目录执行，构建命令从源码仓库根目录执行。

## 快速开始

从完整的运行目录双击 `dafeiyu.exe`，主面板会连接或启动同目录的 `dafeiyu-host.exe`。默认打开 DeepSeek 配置，普通问答可在初始空插件目录使用。使用其他配置、独立数据目录或纯终端构建时，按下列章节选择入口。[桌面管理中心说明](桌面管理中心说明.md#桌面主面板)

## 从源码构建

安装 VS2022 的 x64 C++ 工具、CMake 3.28 或更高版本和前端所需的 Node.js 24.13 及以上 24.x 版本（含 npm）。双击 `build-scirpt/build-debug.cmd` 或 `build-scirpt/build-release.cmd` 即可编译。首次构建会按锁文件安装前端依赖。双击 `build/bin/Debug/dafeiyu.exe` 或 `build/bin/Release/dafeiyu.exe` 打开桌面管理中心。窗口会连接或启动同目录的 `dafeiyu-host.exe`。

```powershell
.\build-scirpt\build-debug.cmd -Target dfy_model -Jobs 8
.\build-scirpt\build-release.cmd
.\build\bin\Release\dafeiyu.exe
```

根目录的 `CMakePresets.json` 随项目提交。项目预设默认并行调度 4 个构建任务，自有 MSVC C++ 目标各用至多 2 个编译进程。单次运行的 `-Jobs` 优先于所选构建预设的 `jobs`。

本机需要单独设置时，将个人预设模板（`build-scirpt/CMakeUserPresets.json`）复制到项目根目录作为 `CMakeUserPresets.json`。已有个人预设时可合并模板条目。编辑 `jobs`、`DFY_MSVC_COMPILE_JOBS` 或本机工具链路径后，运行 `.\build-scirpt\build-debug.cmd -Profile local-windows`（Release 同理）。模板使用单独的 `build/local-windows/`，本机文件由 Git 忽略。

脚本用 `-Profile <名称>` 选择配置预设。默认 `windows` 构建桌面与后台。需要终端时运行 `.\build-scirpt\build-debug.cmd -Profile windows-cli`，然后启动 `build/rebuild/windows-cli/bin/Debug/dafeiyu-cli.exe`。测试配置 `windows-tests` 构建 CLI，包含本体和原生托盘测试。`windows-ui` 增加 WebView2 集成测试，其一键入口定向构建桌面。运行全量测试前按下文「离线验证」构建全部目标。

从根目录直接使用 CMake 也能构建相同的程序。

```powershell
cmake --preset windows
cmake --build --preset windows-release
```

默认预设启用桌面，关闭 CLI。纯终端配置显式选 `BUILD_GUI=OFF`、`BUILD_CLI=ON` 并使用独立构建目录。`windows-tests` 采用这一组合。

生成独立运行目录：

```powershell
cmake --install build --config Release --prefix "$PWD/build/package/DaFeiYu"
```

## 模型、目录与日志

在 Windows 用户或系统环境变量中配置对应服务的凭据，更新后新开终端：DeepSeek 使用 `DEEPSEEK_API_KEY`，Qwen 使用 `DASHSCOPE_API_KEY`。配置文件只保存环境变量名称，不保存密钥。运行期间不自动读取其他进程刚修改的环境。

在运行目录打开桌面或为它选择 Qwen 配置。

```powershell
.\dafeiyu.exe
.\dafeiyu.exe --main-panel .\config\qwen.example.json
.\dafeiyu.exe --data "D:\应用数据\用户设置"
```

需要命令行时，选择带 CLI 的构建。终端支持交互、配置检查和单次调用。从 PowerShell 或文件重定向输入时，首行可以带 UTF-8 编码签名，`/status` 等本地命令仍由宿主处理。

```powershell
.\dafeiyu-cli.exe --chat .\config\qwen.example.json
.\dafeiyu-cli.exe --check-config .\config\deepseek.example.json
.\dafeiyu-cli.exe --complete .\config\qwen.example.json .\prompt.txt
```

`prompt.txt` 使用 UTF-8。配置检查只检查文件格式，真实服务可用性由实际请求验证。可以复制示例配置，修改服务地址、模型、凭据环境变量名称或超时，再用 `--chat` 指定副本。

不带参数时，程序从自身所在目录寻找默认配置；从其他工作目录启动也不影响默认资源定位。明确给出的相对配置、包或数据路径以当前工作目录为准。

普通终端与桌面管理中心按用户数据目录连接同一个后台主会话。桌面可用 `--main-panel CONFIG --data DIR` 指定模型和数据目录。终端可用 `--chat CONFIG` 指定配置，并支持 `--data DIR`、`--plugins DIR` 与 `--trace DIR`。没有后台时会启动一个，已有后台会核对这三个位置及模型配置路径。在终端输入 `/exit` 或关闭终端后，后台继续处理在途工作。通过管道提交问题并关闭输入时，终端仍可收取本次回答。专用游戏宿主继续独占其数据目录。可以从托盘选择「退出大肥鱼」，或运行 `dafeiyu-host.exe --stop-host DATA`。[桌面运行说明](桌面管理中心说明.md#桌面主面板)

后台、管理窗口和普通聊天终端默认在数据目录的 `logs/` 写入软件运行日志。默认目录为 `%LOCALAPPDATA%\DaFeiYu\logs`，指定 `--data` 时随数据目录切换。每次启动有独立的 JSONL 文件，可按组件、PID、UTC 毫秒和进程内序号核对启动、构建和准备退出的返回码。此日志独立于按需开启的 Agent Trace。

每段最多 1 MiB，换段保留完整记录。目录按最近写入时间保留最多 64 段、合计 16 MiB。正在写的段受系统句柄保护，新开段和正常关闭时会重新核对预算。无法建立目录或写盘时，进程诊断输出报告错误码，业务仍按实际结果结束。

`dafeiyu-cli.exe --help` 列出本构建支持的入口。

## 会话与人格

本体默认采用内置的「大肥鱼」人格。可在本体用户数据目录放置 UTF-8 的 `persona.json`，重启后直接对话、房间点名和 MC 陪玩使用同一档案。终端默认目录是 `%LOCALAPPDATA%/DaFeiYu`，也可用 `--data` 指定。MC 体验入口的该目录为 `RUN_DIR/user`。档案有三个字段。`id` 使用不超过 32 字节的小写字母、数字、点、连字符或下划线，`revision` 是正整数，`instructions` 是不超过 2048 字节的人格正文。修改正文时可递增修订号，Trace 同时记录正文摘要。工具权限和游戏目标由各自入口和插件决定。

```json
{
  "id": "dafeiyu.home",
  "revision": 1,
  "instructions": "你叫大肥鱼。平常简短自然地说话，和对方一起做事。"
}
```

游戏专用宿主使用 `dafeiyu-cli --mc-partner CONFIG PACKAGE RUN_DIR`。插件包、连接设定及开局步骤见源码仓库 `文档/使用说明/MC伙伴使用说明.md`。

| `回想 周报`、`回想 会话号/消息号` | 按完整主题取最近仍适用或尚未整理的获准原话，或按原件号查指定原话，包括已被更正的历史说法。回忆包含原文、原时间、渠道和跨启动可用的引用号 |

| `/knowledge inspect 条目 [版本]`、`/knowledge publish 条目 版本`、`/knowledge withdraw 条目 当前修订` | 审阅候选、发布当前基线上的版本，或撤下当前发布。 |
| `/knowledge grant 条目 版本 插件 task\|business\|avatar 对象 渠道\|- off\|read\|relay` | 向实际已绑定的子库按版本授权。任务和独立业务的渠道填 `-`。 |
| `/mail wake auto`、`/mail wake manual` | 切换插件信箱的自动唤醒 |
| `/mail review` | 主会话空闲时主动审查一个信箱队首 |
| `/ask answer 编号 "答案"` | 向已在终端实际呈现的 ASK 提交原答复 |
| `/run 包ID/工具ID "目标" [--workspace "目录"]` | 空闲时把一个已加载的只读工具明确授予本轮，返回运行标识 |
| `/run-confirmed 包ID/工具ID "目标" [--workspace "目录"]` | 授予本轮一个指定工具，具体状态变更等待人工确认 |
| `/confirmations` | 查询本轮待确认动作、参数、请求号和修订 |
| `/approve 请求号 修订`、`/deny 请求号 修订` | 登记对原动作的批准或拒绝 |

| 私聊“物流交接和馆藏交接的两次称重能相互印证吗？” | 两个渠道的读口提供结构化采样后，可以给出两个完整任务名，重名时改用原读回回执号。答复可分别引用投递回执与采样原件，继续追问原件可展开当时的工具输出。[渠道采样格式与判断依据](../设计/本体记忆与知识库设计.md#两个业务渠道的现场采样) |

| `/task-status 请求号` | 在同一宿主进程内查回原接纳和仍保留的运行状态 |

| `/diagnostic export "文件"` | 将当前或最近运行的无正文诊断保存为新文件 |
| `/status` | 查看当前回合；空闲时查看最近一轮的状态、耗时和通知接纳结果 |
| `/cancel` | 取消当前问答，保留此前已提交上下文 |
| `/clear` | 空闲时清空当前上下文 |
| `/exit` | 离开当前终端，常驻本体继续处理已接纳任务 |

个人记忆的主题最多 128 个 UTF-8 字节，斜线留给原件号。首版收录完整短句，JSON 编码后的原文上限为 2048 字节。收录时本体把引用号放进私聊请求的 `memory.original`；也可以在收录后直接用 `/memory last` 取得。回想用于新发起的单独私聊。主动收信、房间点名和合并来信的回合使用独立的上下文。撤权会取消可能持有旧材料的在途私聊，之后的模型请求使用新的授权修订；用户的本地聊天历史仍可按原消息号查看。

网络等待期间仍可处理本地管理命令。新的普通问答会明确报告忙碌，不会进入隐藏队列。取消先确定问答结果，已经送出的远程调用仍须等待系统调用退出；取消不承诺撤销服务端已执行的请求。默认不自动重发失败请求。

普通问答在完整成功后成对提交。工具运行将已结算的调用和结果成对保留，后续回答失败或取消时仍可关联已执行的工作。`/run` 只接纳已加载实例中的具体只读工具，包含空白的目标用双引号括起。普通对话可以带入一封经审查的待收信件，若同轮信件关联一项 ASK，仅授予处理原事项所需的工具。当前上下文正文总量上限为 1 MiB，达到限制后可 `/clear` 开始新的上下文。可供模型继续的上下文由当前本体管理，已持久化的主聊天可在相同数据目录重启后查阅。重定向输入正常结束时，程序会等待已经接纳的回答完成。

批准前核对 `/confirmations` 显示的工具及参数。回执表示已登记决定，实际执行和退出继续通过 `/status` 查询。最近 64 条决定的值回执在当前进程内可重复查询，动作退出后也可重发原命令。使用 `/cancel` 明确取消当前运行。

`/status` 不调用模型、不推进或重试业务。`Question` 是问答结果，`Model call` 是后台调用事实，`exit=confirmed` 才表示宿主确认调用退出；取消期间可能同时显示 `Question=cancelled`、`Model call=running` 和 `exit=waiting`。时间均为单调时钟相对模型提交的毫秒偏移；后台可能在宿主完成回合接纳前开始，横线表示该阶段尚未发生，最终耗时不会随再次查询增长。

通知中的 `accepted (queued only)` 只表示通道接纳，不能证明插件已经处理。开始、终态或清空通知未接纳会独立提示一次，不改变问答或清空结果，也不会自动补发。`/status` 保留开始和终态回执及成功接纳的事件身份，便于关联会话／回合／模型请求。终端只保留最近一轮的固定大小快照，`/clear` 不清除该诊断；进程结束后丢弃。诊断不包含提示词、回答、凭据或异常正文。

导出需要明确的新文件路径，并拒绝覆盖。使用 `dafeiyu-cli.exe --review-diagnostic "文件"` 离线查看历史缺口、实际退出、效果计数及公开版本。只读回顾无需启动模型或加载插件。

`/run` 与 `/run-confirmed` 均可在目标后追加 `--workspace "目录"`。路径按发起终端的工作目录解析，宿主核实项目目录并把 Windows 系统、采样时间和可读时区随本轮决策提供。

`dfy.session.event@1` 记录 `kind`、`session`、`turn`、`messages`，种类为 `turn_started`、`turn_completed`、`turn_failed`、`turn_cancelled`、`session_cleared`。成功事件在历史提交后接纳，观察者延后运行，事件诊断不含对话正文或凭据。

构建标签随二进制记录编译器、平台和配置。构建者核对源状态后可在配置 CMake 时用 `-DDFY_APPLICATION_COMMIT=完整提交号` 声明源码版本。未提供时显示未知，运行时从二进制读取标签。

## 插件管理

插件是同进程可信原生 DLL。默认包目录为程序目录下的 `plugins`；安装和发现都不会自动运行插件。分发目录的 `examples/plugins/example.observer` 是独立观察示例，默认不装入包目录。

从运行目录启动终端后，可以安装并读取独立的状态面板示例。面板模式随当前实例存活，初始为 `idle`。

```text
/plugins install "examples/plugins/example.status"
/plugins load example.status
/run example.status/read "读取状态面板的当前模式"
```

下一轮可交代大肥鱼切换到专注模式并验证。

```text
/task example.status/read example.status/set_focus focus "把状态面板切换到专注模式"
```

首次读取完成后，用 `/confirmations` 查看待审调用，按显示的请求号和修订输入 `/approve` 或 `/deny`。批准后，`/verification` 显示重读结果是否与期望值一致。该路径要求同一插件实例的两个无参工具、三次单独的顺序调用和原变更的实际退出。目标为空、没有初读、读取不匹配或证据丢失时不能结算为成功。可将 `set_focus focus` 换为 `set_idle idle` 切回空闲。

需要重发或重新接入时，用 `--request 1` 开始给任务编号，后续的新编号依次递增。相同请求号及相同参数返回原运行，参数冲突会被拒绝。`/task-status 1` 可查原接纳。当最近运行已换成其他任务时，旧请求仍可在最近 16 项回执内查到原身份，详细状态可能已超出保留范围。

以下安装命令中的 `D:\DaFeiYu` 请替换为实际运行目录：

```text
/plugins list
/plugins install "D:\DaFeiYu\examples\plugins\example.observer"
/plugins refresh
/plugins load example.observer
/plugins unload example.observer
/plugins remove example.observer
```

默认用户设置位于 `%LOCALAPPDATA%\DaFeiYu\plugins\<id>\settings.json`，为 JSON 对象。包内默认设置和用户设置按顶层键覆盖。移除包会保留该用户设置，不把它复制进其他包。

需要独立运行环境时指定目录：

```powershell
.\dafeiyu-cli.exe --chat .\config\deepseek.example.json --plugins "D:\应用数据\插件" --data "D:\应用数据\用户设置"
```

本地安装只接受普通本地目录，拒绝链接、重解析点、已有 ID 和覆盖更新；默认上限为 4096 个子项、512 MiB 文件数据及 32 层目录。完整检查和暂存复核后才发布，坏包单独报告，不阻止本体问答。

卸载明确区分完成、正在停止、忙碌、仍被使用和失败保留。等待下一事件的观察插件可正常停止；仍在执行的调用或仍被其他实例使用的代码不会被强行释放。宿主建立了运行时依赖时，可以使用 `/plugins unload <id> --linked` 请求先停止使用者。

`remove` 先尝试卸载，未完成时保持包文件。已有移除残留先分批清理；仍有未处理批次或清理失败时，当前包保持可见并明确显示“Package kept”。旧残留结束后，当前包先退出发现目录，再清理文件。只读或权限问题会显示具体残留路径；修复后再次执行相同 `/plugins remove <id>` 继续。不要把“正在停止”或“清理未完成”当作已经全部释放。

需由原生观察触发变更时，宿主须配置数据契约及标量条件。命中后进入原动作的待审批流程，宿主继续核对当前授权和读回。

## Trace 审阅与回放

MC 体验宿主在 `RUN_DIR/trace/events.jsonl` 保存模型请求、原始响应、改写结果和运行退出摘要。重复使用运行目录时，后续日志保存在新的 `trace-N` 子目录。启动输出中的 `DFY_TRACE` 给出实际文件位置。普通终端会话可用 `--chat CONFIG --trace DIR` 开启同一格式。文件包含本局对话与工具正文。模型记录用 `thinking` 标记模式，DeepSeek 返回的 `reasoningContent` 随本地记录保存，用于还原同一工具链的实际上下文。玩家可见输出仍取正文和实际发言回执。

要复查当步状态，请在 `model.prepared` 中对齐 `input.messages` 与 `messageEvidence` 的下标。末条来源为 `host_status`、协议为 `dafeiyu.agent_status/1` 时，`snapshot` 指向该步的原版。若模型调用 `status_read`，用 `callId` 将 `tool.exited` 与下一次送模中的 `tool` 回执配对。离线回放使用记录的状态和原事件时间，可核对供应商编码指纹。

在 `model.prepared` 中，`personaProfile` 标识本体人格，`promptTemplate` 标识额外场景规则的版本或摘要。`input.messages` 与 `input.tools` 保留本轮实际送模的正文和工具定义，可与 `model.exited`、`tool.exited` 及游戏回执交叉核对。比较体验时分别计算收件到首次实际发言、收件到动作接纳、接纳到游戏退出，并单列动作接纳后无实效或仅部分完成的情况。

工具记录区分候选、接纳和退出，保存原调用编号以及有效参数和实际结果。

主 Agent 路径中的 `mail.dispatched` 记录真正收取信件的 `session` 和 `run`。该回合的 `model.prepared` 显示本轮工具及实参范围。`reply.intent` 将 `mail_reply` 的 `callId` 与原事项身份、信件序号和运行身份关联。回合退出时没有意图会记录 `reply.review_required`，可用 `/mail review` 主动取回待复审结果。

使用 `dafeiyu-cli --review-trace FILE` 列出运行及关联的玩家消息，附加 `SESSION RUN` 查看原始记录和同一子请求的游戏回执。读取时校验文件版本和连续序号。未正常关停时仍可读取已落完整的行，并提示记录缺尾。

使用 `dafeiyu-cli --replay-trace FILE SESSION RUN` 离线重跑一轮已退出的直接运行。正式 Agent 协调器读取起始上下文，用固定模型响应、已记录的响应和参数改写以及工具结果重跑，逐次核对送模消息、工具定义、调用、回执和最终结果。工具回执可包含 MC 业务确认后的游戏实效。若新游戏消息导致原回合的下一次送模被拒，回放会按原记录重现停止。执行只读取本地文件和内存替身。取消、Agent 宿主审批、规划、观察绑定和最终答复 Hook 改写仍通过原日志审阅。

游戏消息、动作、追问和玩家实收的字段对照，见源码仓库 `文档/使用说明/MC轨迹查看器说明.md`。

## 离线验证

开发中按影响范围构建并运行相关测试。例如，使用 `windows-tests` 构建预设可定向构建 `dfy_event_store_tests`，再用 `ctest --preset windows-tests -R '^events\.store$'` 运行。完整离线验收使用包含桌面目标的 `windows-ui` 配置，分别构建两种模式的全部目标。

```powershell
cmake --preset windows-ui
cmake --build build/rebuild/windows-ui --config Debug --parallel 4
ctest --test-dir build/rebuild/windows-ui -C Debug --output-on-failure
cmake --build build/rebuild/windows-ui --config Release --parallel 4
ctest --test-dir build/rebuild/windows-ui -C Release --output-on-failure
```

构建 Release 程序及示例后，可在 PowerShell 7 中运行独立安装目录检查。

```powershell
.\scripts\verify-agent-package.ps1 -Build .\build\rebuild\windows-ui
```

开发、回归和最终验收使用固定模型响应或传输替身，可结合真实线程、Windows 管道、符号链接、DLL 和隔离 Paper。真实模型的选择与理解按「仅记录，不执行」归档。MC 夹具的命令与证据见源码仓库 `文档/使用说明/MC本地验收说明.md`。
