# 桌面管理中心说明

面向运行 Windows 桌面管理中心的用户。最后两章供验证原生容器和隐藏 WebView2 的开发者使用。构建与选择模型见[构建与运行说明](构建与运行说明.md)。

## 桌面主面板

双击或在 PowerShell 中运行 `.\dafeiyu.exe`。默认使用同目录的 `config/deepseek.example.json`。也可通过 `--main-panel` 后的 JSON 文件路径指定已有配置。需要独立数据目录时，运行 `dafeiyu.exe --main-panel CONFIG --data DIR`。模型凭据沿用配置的环境变量。

第一次打开会启动同目录的 `dafeiyu-host.exe`。相同用户数据目录和配置的窗口共用一个本体。可用 `dafeiyu-host.exe --host-status` 查看实例编号，在「设置 → 后台运行」选择「退出大肥鱼」并确认，或用 `dafeiyu-host.exe --stop-host` 请求本体退出。指定了独立数据目录时，终端查询和退出命令后面也要加上该目录。若已有实例使用另一份配置，面板会显示连接原因。

确认退出后，连接当前版本后台的窗口会等待原进程正常结束，再自行关闭并回收各自的 WebView2 进程和临时目录。普通关闭窗口只离开该观察视图。

交互桌面上的每个后台实例在 Windows 通知区域显示一个鱼形图标。左键唤回该实例的管理中心，全部关窗后再次点击会重新打开。右键可打开该实例的日志目录或确认退出。在纯终端构建中，打开管理中心会收到桌面程序缺失的通知，退出使用 Windows 确认框。图标的注册、恢复、菜单操作和注销可在该数据目录的 `logs` 中核对。

升级前的后台仍会沿用启动时的程序目录。如果点击「打开管理中心」没有弹窗，可从同一托盘打开日志目录。最近的 `tray.open_panel` 若显示 `failed` 且 `systemError` 为 `2`，表示后台找不到桌面程序。从旧托盘选择「退出大肥鱼」，再打开新版桌面目录中的 `dafeiyu.exe`。

收尾较慢时，「设置 → 后台运行」会显示最近核实的会话与回合或插件卸载阶段。等待超过 10 秒即可看到查看日志或关窗的提示。若后台意外终止，窗口会保留原进程号、退出码和诊断入口，刷新后仍可查阅。

在「设置 → 诊断」查看当前窗口的日志状态和目录，或点击「打开日志目录」交给系统打开。写入失败和系统打开失败分别显示错误码。此入口使用窗口启动时的数据目录，独立于后台连接和 Agent Trace。

## 聊天、房间与信箱

管理中心左栏上方为「房间」，底部为「设置」。房间中央的「书房 · 书桌旁」由当前应用实例的房间和身体快照提供，右侧是聊天。窄窗可切换「房间状态」与「聊天」。进入设置后内容区使用完整宽度，返回房间可继续编辑原草稿。打开或刷新时会读取位置，首次读回丢失会自动补查。

「最新状态」提供身体坐标、行为、实例与修订，以及主会话的回合结果、实际退出和待发项。「最近变化」从本窗首次读到的值开始，显示变化前后、来源修订及接收时间。任一来源持续失联时保留最后读数并标明过期，收到新快照后恢复。两个来源独立核对。

状态显示「可以聊天」后，输入消息并发送。回复期间仍可编辑草稿，或用输入框下方的「停止回复」停止本轮。「正在收尾」表示原工作仍在退出。空闲时选择「重置上下文」并确认，下一轮会使用新的模型上下文。已经保存的聊天记录、当前草稿和待发项继续保留。

主面板按本地时间显示持久消息，首次打开读取最新 24 条。点击列表顶部的「查看更早消息」可以一直翻到首条。每个窗口独立记录阅读位置，刷新会重新读取已展开的范围，连接恢复后会补齐错过的消息和回执。后台在全部窗口关闭后继续处理已接纳的回合，随后生成的答复可在重新开窗时查阅。重启本体后，使用同一数据目录仍可查阅原记录。

回复期间，输入区默认「本轮补充」。选择「追加本轮」后可查看它何时进入下一次实际模型请求。取消或超限留下的补充可以加入草稿，再由用户发送。选择「下一轮」再发送，原话会加入待发列表。正常完成后按顺序逐条发送，停止或失败后列表显示「已暂停」。可以移除其中一条，也可以选择「继续发送」。聊天记录在原话旁标明未带入、队列移除等结果。看到「投递结果待核对」时，可点击「复查原回执」查询当初的提交。

同一窗口刷新会保留草稿。发送、追加和排队在首次点击时取得各自的提交号。刷新或重连先查原提交，确认同一逻辑会话没有该记录时才按原号和原参数补投。手动再次发送相同文字会生成另一条独立消息。关窗会回收该窗口的浏览器临时目录。

展开「房间信箱」后选择来源查看近期信件与取件时间。查看和刷新不会取走信件或唤醒模型。来源失联时页面标出上一次读数，插件重新加载会产生新的实例代次。

## 设置与插件

在「设置」查看本体当前的供应商和请求超时。超时以毫秒输入，取值 1～600000。保存后页面分别显示已保存修订与当前生效修订，正常退出并重启同一数据目录的本体后采用新值。如果另一窗口已修改，先刷新读取新值，再决定是否重新编辑。

在插件列表刷新已安装的包，选择要加载或卸载的实例。按操作回执核对运行代次、实际加载或卸载结果。正在停止时等待原操作退出。包声明公开的设置按代次显示，当前支持只读文本。安装和移除包可从普通终端的插件命令执行。[插件管理](构建与运行说明.md#插件管理)

## 房间首屏预览

在同一 GUI 构建的可执行文件旁运行 `dafeiyu.exe --room-preview idle` 或 `dafeiyu.exe --room-preview busy`。右上角可以切换两份固定样本。空闲时可直接输入；忙时可选择追加本轮或排到下一轮，独立停止入口保留排队消息。对话旁展开待决定事项可查看依据。输入、决定和停止只改变当前预览样本，切换样本会复位。预览不开启 Application，宿主关闭该页面的 Web 消息入口。

定向 CTest 为 `ui.room_preview_idle` 和 `ui.room_preview_busy`，均使用隐藏 WebView2 和固定浏览器协议检查真实页面。

## 运行环境

需要 Windows x64 和 Microsoft Edge WebView2 Evergreen Runtime。运行目录已包含前端静态资产及 MSVC Release 运行库，不需要 Node.js、源码目录或页面服务器。

若提示 WebView2 Runtime 不可用，从 [微软官方下载页](https://developer.microsoft.com/en-us/microsoft-edge/webview2#download-section) 获取 x64 Evergreen Standalone Installer；提前下载该完整安装器后可离线安装。Edge 浏览器与 WebView2 Runtime 是不同组件。本验证包不自动安装或修改系统运行库。

## 打开容器验证页

运行 `dafeiyu.exe --container-probe`。验证窗口通过本地管道连接使用默认模型配置的后台本体，可刷新查看当前或最近退出的运行状态。输入区和独立来源页面用于验证组合输入、对话框和 Frame 消息。组合结束次数与浏览器可信标记分开显示。

关闭窗口会继续回收创建回调、Frame 和浏览器进程，然后清理本次独立临时配置。临时配置位于系统临时目录的 `DaFeiYu-U01` 下，不复用用户浏览器配置。

## 自动验证

自动模式使用不激活的隐藏窗口。交互验收窗口由 Windows 桌面合成器隐藏，以便 WebView2 生成可接收浏览器键盘事件的首帧。宿主核对隐藏标记及前台窗口。输入使用固定浏览器协议。

| 参数 | 验证内容 |
|---|---|
| `--smoke` | 本地资产、外部资源拒绝、Frame 编码与授权 |
| `--offline` | 浏览器离线模拟状态下，从全新配置加载本地页面并完成 Frame 检查 |
| `--interaction` | 等待首帧后验证中文组合输入、Tab／Shift+Tab、Enter、Escape、焦点返回与独立 Frame 回显 |
| `--lifecycle` | 20 轮 Frame 创建、销毁、对象归还及旧身份拒绝 |
| `--close-early` | 环境创建中请求关闭，等待回调责任归还 |
| `--close-controller` | 控制器创建中请求关闭，等待实际进程退出 |
| `--missing-runtime` | 使用固定不存在的独立运行库路径验证不可用反馈，预期退出码 4 |

启用 `BUILD_TESTING` 的 GUI 构建可运行 CTest `ui.run_status`。它在构建目录内创建独占临时配置，传入真实状态面板包，用固定模型响应检查空闲、待审、无效请求拒绝和读回成功。真实主文档只发起查询，提交和批准由原生验收序列执行。独立 Frame 的越权检查由 `ui.smoke` 覆盖。

例如，在 PowerShell 中等待离线检查并保存回执：

```powershell
$probe = Start-Process .\dafeiyu.exe -ArgumentList '--offline' -WindowStyle Hidden -Wait -PassThru -RedirectStandardOutput result.json -RedirectStandardError errors.log
$probe.ExitCode
```

普通成功检查返回 0，失败返回 1，非法参数返回 2，运行库不可用返回 4。JSON 回执的 `processes_exited` 与 `profile_cleaned` 应为真，`pending_callbacks`、`active_frames`、`live_channels` 应为零，`protocol_pending` 应为假。运行失败会保留未能安全清理的配置并报告，不通过强制卸载伪造成功。

中文验证使用真实 WebView2 中的浏览器协议模拟，覆盖组件事件和提交结果；不包括物理键盘、Windows 输入法候选窗或不同机器上的人工体验。浏览器离线模拟只作用于本验证环境，不会关闭电脑网络。

### 主面板与后台的离线回归

非交互窗口站中的后台仍可通过本地管道查询状态并正常退出。`ui.tray_headless_host` 在独立桌面启动正式的 `dafeiyu-host --host`，核对托盘注册失败、后台进程身份和退出码。无交互桌面验收（`tests/desktop/ui_tray_headless_host.cpp`）

`ui.main_panel` 用空插件目录和固定响应，经真实本地命名管道，在隐藏 WebView2 中核对来源、原消息号、独立停止、实际退出与清空后的模型输入。窄窗口验收覆盖排队、移除、刷新、暂停和继续发送。主面板验收（`apps/desktop/tests/ui_main_panel.cpp`） · 待发队列验收（`apps/desktop/tests/ui_dialogue_queue.cpp`） · 刷新边界验收（`apps/desktop/tests/ui_dialogue_recovery.cpp`）

`ui.resident_windows` 依次打开三个独立桌面进程，在前两次关窗后核对后台进程号和实例号，在第三个窗口确认退出后等待原后台进程实际结束。跨进程验收（`tests/desktop/ui_resident_windows.ps1`）

`ui.history_windows` 由两个独立的正式面板观察 19 轮固定问答，覆盖断连续读、同文投递、全部关窗后答复入库、翻到首条、刷新和重启后按原号复查。窗口验收（`apps/desktop/tests/ui_history_panel.cpp`） · 关闭与重启顺序（`tests/desktop/ui_history_windows.ps1`）

`ui.resident_exit` 核对确认退出后两个窗口的自行关闭和资源回收。`ui.resident_progress` 用保持在途的固定响应核对页面显示的原回合与长等待提示。`ui.resident_unexpected` 结束测试自己启动的后台，核对真实退出码、刷新后的页面反馈和日志目录操作。跨进程用例（`tests/desktop/ui_resident_exit.ps1`） · 固定页面用例（`apps/desktop/tests/ui_main_panel.cpp`）
