## v2 引导与生命周期

- 支持 Windows x64，使用 `extern "C"` 和 `__cdecl`；固定导出为 `dfy_plugin_query_v2`，宏为 `DFY_V2_QUERY_EXPORT`。v1 的头文件、宏、导出与签名保持不变，两份头文件可以同时包含。
- `dfy_plugin_query_v2(requested_abi, &api, error)` 只接受主 ABI 2，返回 DLL 内只读静态 `dfy_v2_plugin_api`；查询不创建实例、不登记资源、不产生业务副作用，重复成功查询返回同一张表。
- 所有查询在同一宿主线程进行。调用方必须保持模块引用，表及其中函数地址借用至模块引用释放，不能自行释放或在释放后访问；错误和名称视图仅在调用期间借用。
- 结构使用 `pack(push, 8)` / `pack(pop)` 并恢复包含方原设置。只用固定宽度整数、字节视图及 C 函数指针，不跨 DLL 传递 STL、异常或 C++ 对象。

| 类型 | 大小／对齐（字节） | 关键位置 |
|---|---|---|
| `dfy_v2_string_view` | 16／8 | `data` 0，`length` 8 |
| `dfy_v2_error` | 260／4 | `length` 0，`text` 4，容量 256 |
| `dfy_v2_api_header` | 8／4 | `struct_size` 0，`interface_version` 4 |
| `dfy_v2_plugin_api` | 24／8 | `struct_size` 0，`abi_version` 4，`architecture` 8，`reserved` 12，`query_interface` 16 |

引导表大小必须精确为 24，主 ABI 为 2，架构为 `DFY_V2_ARCH_X64`（1），保留字段为零，`query_interface` 必须非空。该布局固定，新增能力不往引导表追加字段。

### 精确协商

`query_interface(name, interface_version, &table, error)` 按名称和精确版本查询 DLL 实际实现的能力。名称为非空 UTF-8 字节视图，调用方保证指定长度内的内存可读、文本有效；不要求零结尾，按字节及大小写精确匹配，不自动截断或规范化。能力版本为非零 uint32。

每张能力表以 `dfy_v2_api_header` 成员开头。`struct_size` 表示完整能力表大小，`interface_version` 表示该能力的精确版本，独立于主 ABI、插件和事件契约版本。调用方先核对查询状态、错误长度和非空输出，再核对该能力版本规定的精确表大小与版本，之后才访问其余字段；不能仅因表较大就推断兼容。返回表同样是只读静态借用，不能由调用方释放。

引导表查询插件提供的静态接口。实例创建时，宿主把自己的能力查询函数作为 `dfy.lifecycle@1.create` 的第一个参数传入。未知能力或版本应明确返回不支持，不能用未实现的占位成功表响应。

### 创建、停止与实际退出

`include/dafeiyu/lifecycle_abi_v2.h` 定义 `dfy.lifecycle@1`。`create(host, config, &instance, error)` 在有效绑定内接收宿主查询函数与配置视图。插件复制需要保留的数据，分别管理双方分配的资源。`start` 失败可能留下部分启动的工作。`request_stop` 成功表示已受理，`poll_stop` 以 `STOP_PENDING` 或 `STOPPED` 报告实际进展。仅在插件任务已退出、注册已静止后，宿主调用一次 `destroy`。调用仍在途或停止失败时保留实例和 DLL，按原对象重试。

### 状态与错误缓冲

| 状态 | 值 | 含义 |
|---|---|---|
| `DFY_V2_OK` | 0 | 调用成功，错误长度为零；查询返回非空表，`retain` 返回有效持有句柄 |
| `DFY_V2_INVALID_ARGUMENT` | 1 | 必需输出为空；能力名称指针为空、长度为零或能力版本为零 |
| `DFY_V2_ABI_MISMATCH` | 2 | 引导查询不支持请求的主 ABI |
| `DFY_V2_BUSY` | 3 | 操作正在推进或当前状态不允许该调用 |
| `DFY_V2_NOT_FOUND` | 4 | 在协议规定的范围内未找到对象、条目或能力声明 |
| `DFY_V2_UNSUPPORTED` | 5 | 能力名称或精确版本不支持，或有效来源不允许共享 |
| `DFY_V2_INVALID_HANDLE` | 6 | 引用服务拒绝空来源、部分为零、未知域／编号、过期或已释放的引用 |
| `DFY_V2_RESOURCE_EXHAUSTED` | 7 | 引用服务不能再签发引用，包括容量或标识空间耗尽 |
| `DFY_V2_INVALID_CONTEXT` | 8 | 生产宿主服务没有有效的当前线程调用绑定 |
| `DFY_V2_FAILED` | 9 | 已隔离的未分类宿主失败，不携带跨模块异常对象 |

输出指针必需，所有失败查询均将可写的表输出清空。先校验必需参数，再检查版本是否支持；能力版本不支持使用 `UNSUPPORTED`，不混同主 ABI 不兼容。未知非零状态均按失败处理，不读取失败结果中的表。

`error` 可为空。非空时由调用方分配；成功将 `length` 置零，失败可写入至多 256 字节的完整 UTF-8，也可用零长度只返回状态。文本不要求零结尾，超长诊断应省略或在完整字符边界截断；调用方先检查长度，不能读取未计入长度的字节。任何函数均不得让异常跨越 C ABI。

## 句柄、操作与通知

### 句柄身份与持有责任

`dfy_v2_handle` 是三个 uint64 组成的 24 字节、8 字节对齐标识：`domain`、`id`、`generation` 分别位于 0、8、16。三项全零是唯一空句柄；有效句柄三项均非零。它不含对象地址，不能解引用、持久化、跨进程使用或自行拼装。

- `domain` 标识宿主的签发域，不是插件 ID 或资源所有者。签发域在进程内不复用，宿主重建也使用新域；生产 域分配器（`modules/runtime/include/dafeiyu/runtime_ids.hpp`）和 C++ 引用表（`modules/runtime/include/dafeiyu/handle_registry.hpp`）分别负责签发域和持有记录。
- `id` 标识一条持有引用记录，不是事件、类型或业务对象身份。`generation` 区分同一编号的复用；完整三元组不得再次签发，代次耗尽时停用该编号，不能回绕。消费者只原样传回并按完整值比较引用身份，不根据编号推导对象或权限。
- 原样赋值只复制标识，是同一引用的别名，不增加所有权或延长寿命。借用者不得释放借来的引用；跨回调、挂起或排队保存时，须在借用仍有效时取得独立持有引用，或复制数据到自身存储。
- 句柄不能替代资源归属、实例代次、使用凭证和 DLL 代码依赖登记。各能力还须验证对象种类及允许的操作，并核对调用实例及其权限。

### 宿主引用服务

`dfy_v2_reference_api` 的接口标识为 `dfy.references`，版本 1；表大小 24、对齐 8，`header`、`retain`、`release` 偏移为 0、8、16，两函数必须非空。这是宿主提供的服务，不能把插件的 `query_interface` 当作宿主服务发现入口。

| 操作 | 成功与失败责任 |
|---|---|
| `retain(source, &owned, error)` | 对仍有效且允许共享的来源签发一个不同的持有引用，指向同一对象；输出的完整句柄与来源不同，后续须单独释放。来源可为调用期间借来的引用。失败将输出全零，不消耗来源或产生残留引用 |
| `release(owned, error)` | 仅移交并释放该持有引用；成功后该三元组立即失效，调用方清空本地副本，所有旧别名均不可再用。其他持有引用独立有效。失败保持原引用及回收责任不变；无效引用失败不影响其他记录 |

`retain` 的输出指针必需，缺失返回 `INVALID_ARGUMENT`；调用方须使用不承载另一未释放引用的输出存储。空来源或失效来源返回 `INVALID_HANDLE`；有效但不允许共享的来源返回 `UNSUPPORTED`，不能假定订阅、构造器、使用凭证或插件实例均可复制。容量或标识耗尽返回 `RESOURCE_EXHAUSTED`。`release` 对全零空值成功，对部分为零及失效引用返回 `INVALID_HANDLE`；重复释放同一个非空三元组不是幂等成功。错误缓冲沿用上述调用方所有权规则。

引用服务限同一宿主线程，且不得同步调用业务处理者或抛出跨 ABI 异常。服务表和签发宿主须覆盖引用的全部使用及释放；借用服务表不能使宿主自身延寿。生产 C++ 包装层应移动转交，需共享时显式保留。

释放引用不等于业务成功、取消、停止成功或异步资源回收完成。最后一个只读普通数据引用可以触发宿主数据回收；需要等待的任务或外部资源继续由宿主跟踪，不能因为局部引用消失而丢失清理责任。操作终态通过下述状态表读取。

### 借用期与数据视图

`dfy_v2_bytes_view` 大小 16、对齐 8，`data` 与 `length` 偏移为 0、8。它是不拥有数据的只读二进制视图，允许包含零字节；长度非零时指针必须指向至少该长度的可读区域，长度为零时不解引用指针。视图不提供释放操作，不能跨分配方调用 `free` 或 `delete`。

| 借用类别 | 有效期与延长方式 |
|---|---|
| 调用借用 | 输入名称、参数视图、服务参数及借来的句柄只到该调用或回调返回；接收方不能直接保存地址供稍后使用 |
| 持有引用借用 | 返回接口须指定依赖哪个持有引用；只读普通数据及其地址在该引用有效期间稳定。释放该引用后原视图失效，即使其他独立引用仍存活，也必须从新引用重新取得视图 |
| 模块借用 | 引导查询表和 DLL 函数地址只在相应模块引用有效时可用，保留数据引用不能延长这些地址的寿命 |

`retain` 只延长其对象的持有寿命，不自动延长来源视图或调用参数。延长数据使用时先保留引用，再通过该新引用读取视图；需要任意修改或独立于宿主存活时复制数据。宿主完全拥有的普通数据不因来源或消费插件的 DLL 卸载而失效，包含插件析构或恢复代码的资源则仍需单独登记模块依赖。

`test.borrow@1` 只用于验收：C DLL 在调用内读取宿主的 `A\0B`，调用宿主 `retain`，成功后把新引用转交调用方；它不缓存服务表、不释放借入引用、不提供生产值访问能力。隔离宿主只有两个引用槽位，证明错误拒绝及寿命责任可由纯 C 与 C++20 共同表达，生产注册表另行管理。

### 操作状态与读取

#### 受理、操作引用与终态

提交操作的具体入口由各能力定义，不提供通用的 `submit(kind, void*)` 或消费者结算入口。受理成功须返回有效的操作持有引用；拒绝受理时清空输出，不留下调用方的引用或未登记工作。受理仅表示宿主已经承担推进和收尾责任，不能解释为结果已成功。操作可以在首次读取前已经完成，消费者始终通过状态与对应能力的结果接口判断。

操作引用沿用上述持有规则。`retain` 取得指向同一次操作的独立引用，各引用观察同一个操作记录；句柄数值不充当操作身份。释放任意一份乃至全部客户端引用都不取消操作，也不丢弃宿主尚未完成的工作或清理责任。操作记录须覆盖有效持有引用的读取；宿主工作责任与客户端引用分别结束后才能回收相应记录。

状态用固定宽度 uint32 表达，枚举值如下；零值是失败输出使用的无效状态。

| 状态宏 | 值 | 含义 |
|---|---|---|
| `DFY_V2_OPERATION_PENDING` | 1 | 尚未确定正式终态，不区分排队、执行、等待或收尾阶段 |
| `DFY_V2_OPERATION_SUCCEEDED` | 2 | 按该能力约定确定成功结果 |
| `DFY_V2_OPERATION_FAILED` | 3 | 按该能力约定确定失败结果 |
| `DFY_V2_OPERATION_CANCELLED` | 4 | 已确定取消结果，不等同于仅收到取消请求 |

唯一状态迁移为 `Pending → Succeeded / Failed / Cancelled`。终态一经确定不可改写，包括重复结算为同一状态；消费者只有读取权限。提交边界与取消请求的关系见下文取消契约。

操作终态只证明该操作声明的完成条件。业务结果确定不代表相关清理结束，读取到流结束不代表消费任务退出；关闭、回收与 DLL 释放条件由各生命周期能力分别声明，不能仅凭任意操作进入终态就释放模块。

#### 宿主状态服务与快照

接口标识为 `dfy.operation.state`，精确版本为 1；它是宿主服务，不是插件静态查询应提供的能力。服务表和宿主必须覆盖调用期，操作引用在调用期间有效，全部调用限同一宿主线程。宿主按实例和对象种类提供读取。

| 类型 | 大小／对齐（字节） | 关键位置 |
|---|---|---|
| `dfy_v2_operation_snapshot` | 4／4 | `state` 0，快照无指针且属于调用方 |
| `dfy_v2_operation_state_api` | 16／8 | `header` 0，必需函数 `read` 8 |

`read(operation, &snapshot, error)` 只复制当前状态，不等待、不推进工作、不派发回调，也不增加或消耗持有引用。快照是独立副本：后续结算不改变旧快照；释放操作引用或消费 DLL 后仍可读取该副本。它不含结果载荷或借用地址，业务结果和失败原因由对应能力提供独立的类型化读取接口。

- `snapshot` 必需，缺失返回 `INVALID_ARGUMENT`；其余失败也将非空输出置为全零。输出与可选错误缓冲必须是独立、可写的调用方存储。
- 空、部分为零、跨域、未知编号、过期或已释放的引用返回 `INVALID_HANDLE`；有效但不是操作对象的引用返回 `INVALID_ARGUMENT`。拒绝不改变原操作或其他引用。
- 查询成功统一返回 `OK`，`error.length` 为零，包括读取到 `Failed` 或 `Cancelled`。`error` 仅描述本次查询失败，不承载原操作失败原因。
- 服务表使用精确大小及版本，调用前须检查 `header` 和非空 `read`；成功快照只允许上述四个状态，零或未知状态应视为契约错误，不能解释成成功或等待中。
- 取消和通知使用独立版本化能力，不向本表追加字段或改变 `read` 的副作用和返回含义。已有 v1、v2 引导表及引用服务布局保持不变。

`test.operation@1` 仅是纯 C 消费夹具：在调用期间借用显式传入的宿主状态表和操作引用，校验服务布局后读取快照；不保存地址，不发布 `dfy.operation.state`。隔离宿主只有一份受管理工作和两个引用槽，以手动结算验证契约，不提供生产注册表、线程调度或取消／完成竞争实现。

### 取消请求与原因读取

独立宿主能力 `dfy.operation.cancel@1` 提供 `request` 与 `read`，不改写状态表布局。表 `dfy_v2_operation_cancel_api` 为 24 字节、8 字节对齐，`header/request/read` 偏移为 0/8/16；两个函数均必需。`dfy_v2_cancel_snapshot` 为 4 字节、4 字节对齐，唯一字段 `reason` 位于 0，是调用方持有的副本。

所有调用限同一宿主线程；服务和操作引用须覆盖调用期。不阻塞、不推进消费者或清理、不隐式取消其他等待者。操作是否支持取消在创建时确定，`read` 和 `request` 对不支持的操作均返回 `UNSUPPORTED`；取消某个等待者的通知使用通知表的 `revoke`。

`request(operation, reason, &disposition, error)` 按必需输出、原因、有效操作引用、取消支持性顺序检查。输出缺失或原因非法返回 `INVALID_ARGUMENT`；无效引用返回 `INVALID_HANDLE`，有效但对象种类错误返回 `INVALID_ARGUMENT`。失败清空非空输出，保持操作及首个原因不变；`error` 可空，成功长度为零。所有输出存储与错误缓冲相互独立。

| 原因宏 | 值 | 含义 |
|---|---|---|
| `DFY_V2_CANCEL_USER` | 1 | 调用方主动请求取消 |
| `DFY_V2_CANCEL_OWNER_STOP` | 2 | 所有者停止流程请求取消 |
| `DFY_V2_CANCEL_DEADLINE` | 3 | 期限策略请求取消 |

原因 0 和未知值不接受；这些值只记录原因，不创建计时器、不自动传播所有权，也不扩大调用权限。能力装配时须另行校验实例及访问关系。第一个有效请求的原因在该操作内保持不变，独立引用观察同一个原因。

| 成功回执宏 | 值 | 本次效果 |
|---|---|---|
| `DFY_V2_CANCEL_RECORDED` | 1 | Pending 且未请求过，记录首个原因 |
| `DFY_V2_CANCEL_ALREADY_REQUESTED` | 2 | Pending 且已有请求，保留原原因 |
| `DFY_V2_CANCEL_ALREADY_SETTLED` | 3 | 已有正式终态，不写入新原因也不修改结果 |

回执零值无效。已终态优先于已有请求，终态后的重复调用均返回 `ALREADY_SETTLED`。回执成功只说明请求已处理，不承诺结果是 `Cancelled`。`read(operation, &snapshot, error)` 只读首个原因，尚未请求时成功返回零；失败清空输出，空输出返回 `INVALID_ARGUMENT`，引用及支持性规则同上。

取消请求与结果结算分开：业务在自己的提交边界检查请求并决定能否取消；已经发生的业务提交不能被取消回执回滚。取消请求之后仍可能成功或失败，先确定的正式终态永不改写。取消原因在终态后仍可查询，直到相应引用释放；任何终态都不替代实际退出与资源回收判断。

隔离宿主与纯 C `test.cancel@1` 验证三种原因、重复请求、完成先到及取消先到、不支持拒绝、错误布局和参数、过期句柄、独立引用以及请求后仍可成功／失败；不提供通知撤销或生产取消传播。

### 完成通知与撤销

宿主能力 `dfy.operation.notify@1` 的 `dfy_v2_operation_notify_api` 大小 32、对齐 8，`header/subscribe/read/revoke` 偏移为 0/8/16/24。`dfy_v2_completion_fn` 是 8 字节 C 函数指针，签名为 `void callback(void* user, dfy_v2_handle operation)`，使用 `DFY_V2_CALL`。`dfy_v2_notification_snapshot` 大小 4、对齐 4，仅有偏移 0 的 uint32 `state`。所有服务入口和通知在同一宿主线程调用，禁止异常跨越 C ABI。

`subscribe(operation, callback, user, &registration, error)` 接收有效操作引用及非空回调，`user` 可以为空。成功取得一个不可共享的登记持有引用；`retain` 对它返回 `UNSUPPORTED`。失败清空输出，不保存回调或留下登记、引用和容量占用。操作已经完成也只登记待调度通知，不在 `subscribe` 内重入消费者。多个登记各自独立，每个未撤销登记最多通知一次，同一操作按登记顺序安排可执行通知；回调期间新登记的通知留到后续宿主推进。

| 通知状态宏 | 值 | 边界 |
|---|---|---|
| `DFY_V2_NOTIFICATION_PENDING` | 1 | 等待操作终态或已经排队，尚未进入回调 |
| `DFY_V2_NOTIFICATION_RUNNING` | 2 | 正在回调，回调代码与上下文仍被使用 |
| `DFY_V2_NOTIFICATION_DELIVERED` | 3 | 一次回调已经返回，且该登记不会再次调用 |
| `DFY_V2_NOTIFICATION_REVOKED` | 4 | 回调未开始且已被撤销，该登记不会再调用 |

零或未知状态无效。`read(registration, &snapshot, error)` 读取调用方状态副本，不驱动工作；失败清空输出。`revoke(registration, error)` 对 Pending 同步阻止未来回调并进入 Revoked，对 Running 返回 `DFY_V2_BUSY`（值 3）且不变更登记，对 Delivered/Revoked 幂等成功。未知、过期或释放后的引用返回 `INVALID_HANDLE`，有效但对象种类错误返回 `INVALID_ARGUMENT`；必需输出或回调缺失同样返回 `INVALID_ARGUMENT`。容量不足返回 `RESOURCE_EXHAUSTED`。失败无部分变更，所有 `error` 可空并沿用既有缓冲规则。

撤销只作用于这条等待登记，不请求取消底层操作或影响其他等待者。释放登记引用也不隐式撤销；宿主仍承担未交付登记的责任。登记方必须先确认 Delivered/Revoked 或成功撤销，再结束其 `user` 资源和回调代码的使用期；活动回调自撤销得到 Busy 后，应在回调返回宿主后再处理释放。

宿主为登记保持独立的操作引用；回调得到一个仅在本次调用内有效的操作借用，其数值不必与提交登记时相同。原调用方释放操作引用不影响登记，回调可在有效借用期内 `retain` 操作以供稍后查询。回调进入前操作已经有终态；回调返回前不得释放它的借用支撑。服务表、用户上下文和 DLL 代码依赖必须覆盖排队、调用及必要收尾；状态达到 Delivered/Revoked 后该登记不得残留可能进入 DLL 的入口。

## 数据、事件与处理

下列生产能力的字段布局见 `include/dafeiyu/data_abi_v2.h`。所有调用在同一宿主线程的有效绑定中进行；无绑定返回 `INVALID_CONTEXT`。输出指针为必需，错误诊断可空；失败清空输出，句柄按独立持有规则释放。版本号精确匹配，不因表较大而隐式接受。

| `dfy.structures` | 2／24 字节 | `descriptor`、`field`；包含组合或显式 null，缺失另报 |

`dfy_v2_type_info` 与两版字段信息均为 32 字节；版本 2 字段 flags 位于偏移 20，`max_bytes` 位于 24。`dfy_v2_value_view` 为 24 字节，data 位于 8。数组约束／实际信息分别为 24／32 字节，映射约束／实际信息分别为 32／40 字节；以上对齐均为 8，并恢复包含方原打包设置。

分类编号：Bool 1、Int64 2、UInt64 3、Float64 4、String 5、Bytes 6、Structure 7、Null 8、Array 9、Map 10、Enum 11、Union 12。旧数据能力拒绝新增种类及可选／可空字段，返回 `UNSUPPORTED`；版本 2 的 kind 和 flags 是可扩展标记，消费者必须拒绝未知标记。结构、容器、枚举、联合与 null 的通用 `read` 仅返回分类，data 全零，不隐式创建引用；实际内容通过对应专用能力读取。

字段 `OPTIONAL=1` 与 `NULLABLE=2` 独立：已声明但缺失返回 `NOT_FOUND=4`，显式 null 返回有效值引用且 kind 为 8，空字符串／字节／容器仍是各自真实类型。索引越界、引用对象种类不符、对非结构值调用 `structure` 等返回 `INVALID_ARGUMENT`。

枚举是非空闭合成员集，底层只允许完整 Int64 或 UInt64；成员名及整数各自唯一，未知数字和符号不匹配在构造时拒绝。`field_type` 和 `descriptor` 返回独立枚举描述引用；`describe` 返回名称、版本、整数种类和成员数。`member` 返回声明顺序的名称借用与带种类整数副本，`read` 返回选中索引及数字副本；不得将索引当作稳定取值。枚举信息／成员／选择分别为 32／40／32 字节，成员数字偏移 16、选择数字偏移 8。枚举数据计 8 字节、1 节点；枚举成员与名称纳入父结构的展开描述预算。

嵌套描述按完整名称与精确契约版本识别，定义比较包含顺序、类型和全部约束；同名同版本冲突、根身份回返均拒绝。深度硬上限为 64，展开字段数上限 65536，展开名称正文上限 4 MiB；共享子描述按每次出现计算。普通值构造另核定正文和逻辑节点预算，节点硬上限 1048576，根和显式 null 各占一个节点，缺失占零。

数组和映射的版本 1 C 能力仅允许六种基础元素／值，独立用 `ELEMENT_NULLABLE=1` 允许 null；数量上限 65536，零表示只允许空容器。String／Bytes 有单项与整体正文约束，数字的单项字节约束必须为零。两类容器的版本 2 均支持完整组合内容，数组 `element_type`（偏移 32）与映射 `value_type`（偏移 40）返回独立匿名约束；空容器也能反射完整类型。宿主按实际内容逐项累计正文和节点，映射另外计入每个键的节点与字节；版本 1 C 容器／约束读取对组合声明返回 `UNSUPPORTED`，包括其中的 null。两类容器的匿名元素／值约束均计入父描述展开预算。

映射键是有效 UTF-8，允许空键及内嵌零；按完整字节精确匹配，不折叠大小写或 Unicode 规范化。构造拒绝重复键，枚举按字节序返回；未知键为 `NOT_FOUND`，空指针加非零长度非法。`entry` 同时返回借用键与独立值引用：键借用依赖传入映射引用，引用签发失败时两个输出都清空。

数据子引用使用宿主别名持有：保留叶字段或容器元素仍保持原载荷、读请求结果和事件存储预算，不能提前释放中间引用来绕过计量。最后一份数据持有释放后才归还相应预算；单独取得类型描述只保留不可变描述，不保留事件正文。借用视图在其指定引用释放后失效，即使另一个引用仍使底层对象存活，也必须重新读取。

`dfy.constraints` 让调用方独立持有字段或联合分支的完整内容约束。`describe` 复用版本 2 字段元数据；`named_type` 对结构、枚举或联合返回对应描述，`array`／`map` 返回容器约束副本。约束引用保持父描述，名称视图依赖传入约束引用；这条描述持有链不计入事件数据预算。非对应种类访问返回 `INVALID_ARGUMENT`。

约束版本 1 的容器信息只接受标量元素；版本 2 可返回完整分类，并以 `element` 获取数组元素或映射值的独立匿名约束。匿名 `name.length` 为零、`OPTIONAL` 为零，`NULLABLE` 独立保留；可反复查询命名类型或内层容器约束。该表大小 56，`element` 偏移 48；调用方须精确查询版本 2，不把原表大小作为新能力授权。

联合是非空闭合分支集，显式 UInt64 标签唯一，零及最大值均合法，未知标签在值构造时拒绝。`branch` 按声明顺序返回标签与独立约束引用，分配失败时两个输出均清零；`read` 返回索引及稳定标签；`content` 保持实际内容及原事件预算。分支可空与外层字段可空独立，带标签 null 不是外层 null。描述信息／选择分别为 32／16 字节，分支数偏移 24、标签偏移 8。联合根占 1 节点、标签占 8 字节，再加实际内容；全部分支均参与描述预算。

真实 C 验收入口：嵌套与标量容器（`tests/plugins/plugin_nested.cpp`）、枚举（`tests/plugins/plugin_enums.cpp`）、联合（`tests/plugins/plugin_unions.cpp`）、组合数组（`tests/plugins/plugin_arrays.cpp`）、组合映射（`tests/plugins/plugin_maps.cpp`）、定向读取（`tests/plugins/plugin_targets.cpp`）、组读取（`tests/plugins/plugin_group_reads.cpp`）、组通知（`tests/plugins/plugin_group_notifications.cpp`）、观察包（`plugins/examples/observer/observer.c`）、完整观察链路（`tests/plugins/observer.cpp`）。顺序域的开始与退出使用显式处理能力。

### 订阅与类型化读取

`include/dafeiyu/event_abi_v2.h` 提供 `dfy.subscriptions@1` 和 `dfy.reader@1`。`subscribe` 签发不可共享的独立接收方。`close` 选择排空或取消，`read` 复制队列状态。释放引用不能代替关闭。`next` 返回完整读取请求，`result` 在未结算时返回 `BUSY`。仅 `Event` 的结果携带非零事件身份，`Closed` 携带关闭模式。`payload` 持有事件及读取记录占用的预算。

### 组成员接入

`dfy.groups@1` 声明见 `include/dafeiyu/group_abi_v2.h`，表大小 32 字节，`join`／`leave`／`read` 偏移 8／16／24。成员状态为 16 字节、8 字节对齐，state／close_mode／queued 偏移 0／4／8；状态 1／2／3 分别表示 Open／Draining／Closed，关闭模式沿用 Drain 1／Cancel 2。所有调用限同宿主线程的有效绑定。

宿主通过运行时绑定授予一个组，未授权不提供能力。`join` 返回不可共享的成员接收方，复用 `dfy.reader`、操作取消和通知；失败清空输出且不留下成员或宿主资源。`leave` 只退出本成员，重复调用成功，既有完成读取和数据不会重写。引用释放不等于退出，宿主保留责任直至明确退出或停止；`read` 不推进读取，退出后返回 Closed 及本地关闭方式、queued 0。共享组的关闭和发布不属于此授权。

组成员接收方不适用于旧 `dfy.subscriptions` 的关闭／状态接口，错误种类返回 `INVALID_ARGUMENT`。成员、控制器或引用容量不足返回 `RESOURCE_EXHAUSTED`，停止接纳或授权组关闭时加入为 `BUSY`；域、版本及输出校验沿用其他宿主能力规则。观察包 0.7.0 已通过真实 C 加入、退出、状态、延后消费及安全卸载验收。可选组由运行时传入实例，未授权时保留独立订阅；加入失败不降级，已领取事件不自动重放。

### 显式处理

`include/dafeiyu/processing_abi_v2.h` 定义 `dfy.processing@1`：56 字节表含 `read`、`start`、`complete`、`finish`、`cancel`、`payload`。48 字节快照包含 phase、result、exit、cancel_reason 四个 uint32，以及事件域／序号、顺序域／序号四个 uint64；order_domain 位于偏移 32。C11／C++20 均检查布局及外层打包恢复。

宿主显式启用有界处理队列并提交真实事件后才提供处理引用；普通观察读取不自动进入业务参与者集合。控制引用不可复制，释放它不结束宿主工作。`start` 未获顺序资格返回 BUSY，成功只确认实际开始；`complete` 固定唯一业务终态，仍保留顺序占用；消费者确认实际不会再执行本项后，才调用 `finish`。取消仅登记意图，运行中处理仍阻止卸载。

快照的 result 和 exit 使用各自的操作状态，退出成功不表达业务成功。载荷引用保持整个处理记录及其预算，数据可在处理退出后保留。错误上下文、外部实例、过期身份和非法终态均明确拒绝，失败清空输出。验证见 宿主控制测试（`modules/plugin_host/tests/plugin_processing.cpp`）、真实 C 消费者（`sdk/tests/fixtures/query_v2/processing.c`） 和 跨 DLL 验收（`tests/plugins/plugin_processing_dll.cpp`）。

既有 `dfy.operation.state`、`dfy.operation.cancel`、`dfy.operation.notify` 的生产对象当前为完整读请求；不能将处理控制引用或任意值当作通用操作句柄。新能力使用独立版本化表，未向冻结表追加字段。

## 信箱、子会话与状态

`include/dafeiyu/mailbox_abi_v2.h` 定义 `dfy.mailbox@1`。启用信箱的实例可在绑定线程调用 `attach`，使用宿主确定的身份取得两个定向地址，重复接入返回原地址。实例开始停止时撤销两条路线。

`post` 在出站信箱上使用从 1 连续递增的发送序号。分类使用完整结构类型名及精确版本，正文为 UTF-8 文本，交付时由宿主复制到结构的 `text` 字段。首次接纳返回 `DFY_V2_MAILBOX_ACCEPTED`，窗口内的相同重投返回 `DFY_V2_MAILBOX_REPEATED` 及同一个事件身份。超出回执窗口或跳号时返回对应状态，事件身份为零。接纳只证明本进程队列已收件。

`poll` 非阻塞读取队首载荷引用，空箱返回 `NOT_FOUND`。引用耗尽时首件保留在信箱。消费者可用结构及值服务读取，并通过引用服务释放。读取后的持有可以覆盖信箱关闭，由原宿主引用域管理。

`dfy.mailbox.text@1` 提供已收信件的分类、版本和文本。调用方取得并释放独立载荷引用。`dfy.event.routes@1` 注册事件名、版本和闭合字段契约，实例从 1 连续提交事件序号。解析器在宿主后续推进时根据原事件生成路由。`dfy.mailbox.rules@1` 登记本插件的主信箱分类、优先级与按类别唤醒方式，声明位于 `include/dafeiyu/routed_event_abi_v2.h`。

### 活动与子会话

在 `dfy.activity@1` 的 `step` 中推进收件、原生工作或子会话。`dfy.agent@1` 的 `submit` 复制有界输入并排队，宿主在离开原插件调用后派发相同执行器。每个子会话独立保存上下文，工具范围限本实例当前注册。插件通过 `status` 查询原回合，发出 `cancel` 或 `close` 后仍由宿主推进实际退出。忙碌实例拒绝直接卸载。`include/dafeiyu/agent_abi_v2.h` · `include/dafeiyu/activity_abi_v2.h`

### 事实帧与工作回执

插件可另行查询 `dfy.agent.facts@1`。首次用 `DFY_V2_FACT_BASELINE` 并在 `input.prompt` 提交 `{"set":{"goal":"取材"},"closed":[]}`。后续沿同一作用域递增序号，重复提交原帧可取回原请求号。断序返回 `DFY_V2_NOT_FOUND` 和所需序号，可补齐缺口或提交新基线。工作用原代次、原工作号和连续修订分别登记接纳、实效和退出，后到的实收可在退出后追加。切回原提交入口须等当前回合退出。再次提交增量时，宿主使用当前镜像重建基线。`include/dafeiyu/agent_abi_v2.h` · 回退回归（`tests/plugins/plugin_mailbox_dll.cpp`）

协商 `dfy.agent.facts@2` 后，插件可在实际派发前调用 `settle_ordered` 登记原工作与本代次递增的首次接纳序号。容量不足时先结算已有工作，同一原件重试用原序号。采用有序接纳的代次，后续新工作继续使用有序入口。实效仍待查时可沿原号多次更新。领域方核实最后一份实效后，在该版实效上设置 `DFY_V2_WORK_FINAL_EFFECT`，实际退出单独登记。宿主至多保留 128 个活动工作，每个保留 16 版，满额时归档已退出且实效最终的工作。最近 128 个归档支持原号重传，窗口外旧序号会被拒绝。

**为决策提供状态。** 包可附带 `agent/status.json`，使用 `dafeiyu.status_definitions/1` 登记本插件名前缀下的键、版本、说明、默认关注模式及对象值 schema。`readWith` 可指定本插件的一个只读工具 ID。该能力获准的子回合可用 `status_read({"snapshot":"原快照号"})` 读取原版。宿主复核原实例、作用域和注册有效性。MC 包示例（`plugins/mc/resources/agent/status.json`） · 宿主接入（`apps/host/src/subagents.cpp`）

带绑定的事实帧使用 `set.decisionStatusSamples` 提交当前完整采样数组。每项提供 `key`、`version`、`subject`、正整数 `fact` 和对象 `value`，可附带 `sampledUtcMs` 与 `validUntilUtcMs`。增量帧省略该字段会沿用上个集合，显式空数组或 `closed` 中的同名字段会清空当前集合。旧快照按原版保留。宿主从领域消息剥离传输字段，再以自己的来源生成决策尾注。帧校验（`apps/host/src/binding_facts.cpp`） · 键和值校验（`modules/agent/src/decision_status.cpp`）

`set.decisionStatusAttention` 同样提交完整集合，每帧最多 32 项。每项用本插件已声明的 `key`、`version` 和 `subject` 定位对象。任务期关注使用 `"mode":"continuous"` 和原任务标识 `task`。多个任务可独立关注同一项，结束时从集合移除相应登记。按次数关注使用 `"mode":"counted"`、原事件正整数 `event`、所关注的采样号 `fact` 和正整数 `count`。一个绑定内同一来源的原事件号固定对应这份登记。首次展示将原号放入 `wakeEvents`，在该项实际送模并取得有效文本或工具响应后扣一次。被裁剪、缺少原采样或请求失败时保留次数。原状态按 `snapshot` 查询。计次与重传（`modules/agent/src/decision_attention.cpp`） · 模型响应结算（`modules/agent/src/run_loop.cpp`）

`read_receipt` 按原会话、代次和阶段接纳号读回数据。调用方传入缓冲区，可先以零容量取得所需字节数。活动记录带原正文，归档记录带阶段和正文 SHA-256，超过保留窗口返回 `DFY_V2_NOT_FOUND`。读取沿用原实例权限，期间不触发模型、工具或游戏工作。宿主索引（`apps/host/src/binding_facts.cpp`） · 跨 DLL 用例（`sdk/tests/fixtures/query_v2/mailbox_fixture.c`）

关闭子会话后，可沿原实例和原会话号补报已登记工作的实效、退出或只读查证。宿主保留至多 16 份工作索引，活动和退役绑定共用该额度。新绑定首次登记工作时可回收已全部最终结算的退役索引。全为未决时会话问答仍可使用，新增工作返回容量不足，已有工作继续结算。插件实例卸载后撤销该实例的回执路由。子会话生命周期（`apps/host/src/subagents.cpp`）

## 工具、Hook 与陪伴声明

`dfy.tools@1` 由插件提供，工具描述及参数由宿主复制。调用接纳后按原票据 `poll`，结果与实际退出分别读取。`request_cancel` 提交协作取消，已产生的效果保留。仅在 `exited` 后 `release` 成功才释放票据与代码依赖。

### 控制与文本改写

`describe` 在启动后枚举，最多 32 项。声明主会话、所属子会话或其他子会话范围。宿主加载时完成依赖与循环校验，按稳定拓扑顺序发布各点；依赖已满足的处理器遵循插件和处理器的注册顺序。实际调用持有顺序快照与原实例代码。运行诊断记录接纳时的公开登记版本，包含顺序、依赖、包版本和注册范围。`include/dafeiyu/hook_abi_v2.h`

`dfy.hooks@1` 的 `decide` 在宿主线程同步决定 `ALLOW` 或 `DENY`。`CONFIRM` 用于工具接纳，原子会话的后续模型请求可按规定返回 `YIELD`。等待由当前运行的确认账本管理，批准后按原工具和精确参数再校验。工具结果阶段的决定控制后续调度，已发生的效果继续由原票据记录。

| 文本阶段 | `field` |
| --- | --- |
| `INPUT` | `prompt` |
| `MODEL_REQUEST` | `system` |
| `MODEL_RESPONSE` | `content` |
| `TOOL_ARGUMENTS` | 模型可见的工具名，`value` 为原 JSON 参数 |
| `REPLY` | `answer`，仅用于最终投递 |

`rewrite` 使用宿主提供的缓冲区写 UTF-8，`DFY_V2_TEXT_HOOK_UNCHANGED` 保留原字段，零长度表示显式清空。独立改写者同时提出不同值时，该字段失败。只有声明 `CHAIN` 并依赖当前全部改写者的处理器才能接续。宿主重新验证改写后的模型或工具输入，参数授权及批准从最终候选计算。字段转换回调同步返回，后台工作由活动接口调度。

`describe` 枚举到末尾返回 `NOT_FOUND` 并清空输出。`decide` 输入仅在当前调用有效，错误或非法决定由宿主裁定控制失败。

### 状态转移 Hook

`dfy.hook.transition@1` 的 `describe`、`apply` 使用同一宿主线程，作用域按事件发送者或回合所有者核定。`point` 区分事件采集、解析、分发、信箱上下文、ASK 生命周期、回复接纳与确认、回合退出。`permissions` 逐次给出能否拒绝或改写，`written` 全一表示沿用原文。

### 陪伴角色、路由与执行

活动的可信插件可额外发布 `include/dafeiyu/companion_abi_v2.h`。宿主在原实例的调用保护内复制局部状态工具名与状态主题，并向同一代工具目录验证只读范围。此声明只提供发现信息，开局和委托仍由宿主显式接纳。缺少此接口的 v2 工具包沿用原生命周期。

`dfy.companion.routes` 是独立的可选表。已配对实例可为 `player.inbox` 或 `visit.inspect` 返回本包当前登记的局部工具名，缺少用途返回 `NOT_FOUND`。宿主重新核对工具所属代次和只读／变更类别。

`dfy.companion.skills@1.at` 从零枚举局部技能，末尾返回 `NOT_FOUND`。`dfy.companion.partner@1` 提供 `listen`、`stop`、`status`，开启、停止请求与实际状态各自查询。`dfy.companion.partner.execution@1.status` 补充信箱可读性、执行模式及状态，文本在本次调用内借用。

## v1 兼容契约

冻结版用于核对早期查询及同步订阅消费者。公开头为 `include/dafeiyu/plugin_abi.h`，v2 的生产入口、函数签名和能力查询单独提供。

### 平台、导出与布局

- 首版仅支持 Windows x64，使用 VS2022 的 C11、C++20 验证。其他架构在头文件中拒绝，未承诺其他工具链兼容。
- v1 的唯一查询导出名为 `dfy_plugin_query`，对应 `DFY_QUERY_EXPORT`。插件编译时定义 `DFY_PLUGIN_BUILD`；宿主通过导出名取得 `dfy_query_fn`，本体不链接插件导入库。
- C++ 声明包在 `extern "C"` 内，使用 `DFY_CALL`（`__cdecl`）。在 x64 上采用默认 x64 调用约定，不支持替换为 `__vectorcall`。参见 [C 链接](https://learn.microsoft.com/en-us/cpp/cpp/extern-cpp?view=msvc-170)和 [调用约定](https://learn.microsoft.com/en-us/cpp/cpp/cdecl?view=msvc-170)。
- 头文件对 ABI 结构使用 `pack(push, 8)` / `pack(pop)`，不改变包含方原有设置；C/C++ 验证均在外层 `pack(1)` 下包含头文件并检查恢复结果。参见 [pack 规则](https://learn.microsoft.com/en-us/cpp/preprocessor/pack?view=msvc-170)。

| 类型 | 大小 / 对齐（字节） | 关键位置 |
|---|---|---|
| `dfy_string_view` | 16 / 8 | `data` 0，`length` 8 |
| `dfy_error` | 260 / 4 | `length` 0，`text` 4，容量 256 字节 |
| `dfy_event` | 24 / 8 | `struct_size` 0，`kind` 4，`session_id` 8，`turn_id` 16 |
| `dfy_host_api` | 40 / 8 | `context` 8，`subscribe` 16，`unsubscribe` 24，`diagnostic` 32 |
| `dfy_plugin_api` | 48 / 8 | 版本与架构前缀 16 字节，`create` 16，`start` 24，`stop` 32，`destroy` 40 |

v1 布局固定，不按编译器枚举宽度传递状态，不传 `bool`、`size_t`、STL、C++ 对象或异常。`struct_size` 必须等于上述 v1 大小，`abi_version` 为 1，插件表的 `architecture` 为 `DFY_ARCH_X64`（逻辑值 1），`reserved` 必须为 0。所有函数指针均为必需项，不能为空。布局或函数签名变化必须使用新 ABI 版本，不能在 v1 下悄悄增加尾部字段。

### 查询与错误

`dfy_plugin_query(requested_abi, &api, error)` 不创建实例、不注册订阅，也不进行业务初始化。成功返回 `DFY_OK` 和 DLL 内只读静态表；重复查询不改变业务状态。失败必须把 `api` 输出清空；不支持的版本返回 `DFY_ABI_MISMATCH`，空输出指针返回 `DFY_INVALID_ARGUMENT`。表和其中函数指针仅在模块仍被宿主持有时有效，不得释放或在卸载后访问。

宿主在调用 `create` 前核对版本、大小、架构、保留字段及全部函数指针；插件在使用宿主服务前同样核对宿主表。版本 1 不接受只提供部分服务的宿主表。清单的 `abi_version` 必须与请求和返回表一致，`manifest_version` 只控制清单格式。v1 查询入口的参数布局、错误缓冲格式与导出名保持稳定；v2 经独立入口显式协商，不能只凭清单跳过接口表检查，也不能将新表布局塞进 v1 返回类型。

| 状态 | 值 | 含义 |
|---|---|---|
| `DFY_OK` | 0 | 本次操作成功 |
| `DFY_INVALID_ARGUMENT` | 1 | 必需参数缺失或参数不符合契约 |
| `DFY_ABI_MISMATCH` | 2 | 请求版本或接口元数据不兼容 |
| `DFY_BUSY` | 3 | 当前状态不允许操作，或仍有活动调用 |
| `DFY_NOT_FOUND` | 4 | 当前实例不存在对应订阅 |
| `DFY_UNSUPPORTED` | 5 | 实现明确不提供该能力 |
| `DFY_FAILED` | 6 | 业务处理失败 |

所有返回状态的函数接受可选 `dfy_error*`。调用方分配缓冲，调用期间供被调用方写入；成功时将 `length` 置零，失败可写入至多 256 字节的有效 UTF-8，也可用零长度只返回状态。不得写越界、截断 UTF-8 字符或要求调用方释放任何内存。文本按长度读取，不要求末尾零；未计入长度的字节无意义。调用方先校验长度再使用，错误文本不应包含凭据、请求头或整份配置。未知非零状态一律按失败处理。

每个模块自行捕获自己的 C++ 异常并转为状态，`destroy` 和 `diagnostic` 也不得抛出异常。该约定不提供原生崩溃隔离；同进程插件仍须可信。

### 字符串与资源归属

- `dfy_string_view` 是 UTF-8 字节视图，长度不含额外终止符；长度非零时指针必须指向足够的可读内存，零长度允许空指针。配置必须为非空 JSON 对象文本，字段含义由插件校验。
- 配置视图只保证在 `create` 调用期间有效，插件保留值必须自行复制。宿主可以让自己的有效配置快照与实例一起存活，但插件不得依赖这个额外寿命。
- `dfy_event*` 只在当前事件回调中有效；诊断文本只在 `diagnostic` 调用期间有效。需要保留的内容由接收方复制。
- `dfy_host_context*` 是当前实例绑定的不透明宿主句柄，插件只可原样回传，不得解引用、伪造或释放。宿主服务表的地址和上下文必须稳定到插件停止、撤销注册并销毁完成。
- `dfy_plugin_instance*` 由插件创建和销毁，宿主不得解引用或释放。插件分配的资源由插件释放，宿主分配的错误缓冲、事件和配置内存由宿主管理。

### 生命周期与失败恢复

全部 ABI 入口、宿主服务和事件回调在同一宿主线程串行执行。首版不允许插件自建后台工作线程，也不提供会话操作、模型调用或工具执行服务。

| 操作 | 前提与成功结果 | 失败处理 |
|---|---|---|
| `create` | 提供稳定宿主表和配置视图，成功输出唯一非空实例 | 输出空句柄并自行回收部分分配；不能留下宿主订阅 |
| `start` | 对已创建实例调用一次，成功后可接收事件 | 宿主关闭事件入口，调用 `stop` 处理部分启动 |
| `stop` | 可处理未启动、活动、启动失败或上次停止失败的实例；成功进入已停止状态 | 保留实例、DLL 和宿主服务，维持入口关闭，只允许再次停止及清理所需服务 |
| `destroy` | 仅在停止成功且宿主已撤销全部注册后调用一次 | 无可恢复返回状态，不得抛错；返回后句柄立即失效 |

`stop` 成功后的重复调用必须返回 `DFY_OK`；已经停止的实例不重新 `start`，重新加载应创建新实例。停止失败可以在外部条件修复后显式重试，不能强制销毁、重新启动或继续卸载。

v1 宿主必须给所有进入插件的调用及回调计数。卸载时若有活动调用，立即返回忙碌且不调用 `stop`；否则先关闭新入口，再停止。停止成功后撤销全部订阅和登记项，确保没有仍会调用插件或依赖其资源的回调，再销毁实例，最后释放宿主持有的模块引用。宿主服务表、上下文和配置所有者应覆盖这一清理过程。

### 宿主服务与事件

- `subscribe` 只能在当前实例的 `start` 或活动阶段调用；失败输出订阅标识零，成功返回当前上下文内唯一的非零标识。实例尚在启动时不投递事件，启动成功后才开放通知。
- `unsubscribe` 可在启动、活动、停止及停止重试过程中清理当前实例的订阅，其他实例或未知标识返回 `DFY_NOT_FOUND`。取消立即阻止尚未执行的通知，但回调和 `user` 资源必须保留到已开始的调用返回；自取消不能使当前调用使用悬空资源。
- `diagnostic` 在上下文存活期间可尽力输出，不承诺写出成功，也不产生递归事件。创建、停止、销毁期间可用于报告问题。
- 订阅只属于宿主绑定的当前实例；SDK 不接收插件自行指定的所有者 ID。插件可以传入自己的 `user` 指针，宿主只在回调时原样传回，不负责释放。

事件按订阅顺序同步通知；分发中新订阅下次生效，取消后尚未调用的订阅本次跳过。一个回调返回失败不阻断其他观察者、不回滚会话历史。回调不能重入问答或清空，也不能在执行中卸载自身；SDK 不提供这些操作的入口。

`dfy_event.struct_size` 为 24；`kind` 的 1、2、3、4 分别表示问答开始、完成、失败和会话清空，与宿主内部 C++ 枚举需显式映射。事件携带会话号和回合号，清空的回合号为零。未知事件种类应忽略并返回成功，不读取未知数据。`include/dafeiyu/plugin_abi.h`

### 查询样例与冻结契约验证

`dfy_query_example` 只有查询能力：提供完整非空函数表，但 `create` 明确返回 `DFY_UNSUPPORTED` 且不产生实例。生命周期函数是查询样例的占位实现，不是可安装运行的 observer 插件。可安装的观察包遵循本手册的 v2 契约。

`sdk.abi` 在 C/C++ 两侧检查布局和打包设置，实际通过固定导出名查询 DLL，验证版本拒绝、重复查询、失败输出和调用方错误缓冲。宿主使用 平台模块引用封装（`modules/platform/include/dafeiyu/dynamic_library.hpp`），其中 PluginModule（`modules/plugin_host/include/dafeiyu/plugin_module.hpp`）复用它完成查询校验；`plugins.module` 使用可控真实 DLL 验证返回状态、畸形表和失败回收，查询过程不调用生命周期函数。平台搜索方式参见 [LoadLibraryExW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw)。

`PluginModule` 不读取或回显查询错误正文，只报告状态码及宿主识别的契约错误；错误长度越界和成功时携带错误均被拒绝。成功接口复制到宿主保存，但函数地址仍依赖 DLL 引用；关闭前必须结束所有借用和调用，接口关闭后不可访问。非法指针、越界写入和跨 ABI 异常不属于可恢复的状态失败，仍受同进程可信插件边界约束。

## 验证与排错

在源码树配置 `windows-tests`，构建对应目标后运行 `ctest --preset windows-tests -R '^sdk\.' --output-on-failure`。`sdk.abi` 检查冻结 v1，`sdk.query_v2`、`sdk.handles_v2`、`sdk.operations_v2`、`sdk.notifications_v2`、`sdk.tool_abi` 分别检查独立导出、布局、借用、状态、通知和工具票据。跨 DLL 用例位于 `tests/plugins/`，独立 SDK 和运行包验证入口为 `scripts/verify-agent-package.ps1`。
