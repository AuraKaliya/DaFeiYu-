# MC伙伴设计

适用范围为 Java 版 1.21.4 的同场陪玩。玩家面对同一位大肥鱼，本体提供人格、会话和通用服务，MC 插件持有游戏中的约定、事实和实效。基线为主线 `8fce20e`。功能进度见[MC 伙伴开发计划](../开发计划/MC伙伴开发计划.md)。

## 职责与关系

| 参与方 | 拥有的数据与决定 |
| --- | --- |
| 本体与主 Agent | 宿主管理人格、子会话、模型请求、权限、信箱、取消与 Trace。主 Agent 可处理明确转交的求助。专用游戏宿主在自己的数据目录创建应用实例。[会话托管](../../apps/host/src/subagents.cpp) · [游戏入口](../../apps/terminal/src/companion_host.cpp) |
| 局内伙伴 | 由本体托管的子会话依据玩家原话、已有分工、最新事实和可用工具决定接话、行动、补查、追问或等候。玩家提出建议时，原约定仍由局内任务持有。[玩家回合](../../plugins/mc/src/partner_loop.cpp) |
| MC 插件 | 同进程可信 DLL 管局内任务修订、授权范围、待答、读回及角色资源。收件将新输入交到决策边界，插件核验动作并保存结果。[插件入口](../../plugins/mc/src/native.cpp) · [玩家收件](../../plugins/mc/src/partner_feed.cpp) |
| 游戏桥接 | 独立 Node/Mineflayer 进程持有游戏角色，接收协议事件、采样、执行和查原票据。服端的可选只读旁证用于核清物品来源。验收所用的独立协议玩家另行观测世界、库存和实际收到的消息。[桥接入口](../../plugins/mc/bridge/start.cjs) · [工作协议](../../plugins/mc/src/world_protocol.cpp) |

一局中应能从原消息一直找到玩家实际看见的结果。消息号记录一次输入及来源，任务和执行修订记录当前约定，观察号固定一次采样，工作号记录一次游戏操作，投递身份关联实际发言及收件。不论本轮模型是否发言，已接纳的工作继续持有自己的身份。系统关系与通用工具执行见[项目架构设计](项目架构设计.md)及[Agent 循环与上下文设计](Agent循环与上下文设计.md)。

## 现场观察与原话指向

玩家发言时记录对象、玩家姿态、视线、世界和出生代次。观察可引用原消息，也可按当前伙伴或玩家位置重新采样。位置、朝向和距离在送模时最多保留两位小数，准星命中与目标格从原值计算。例如高度 `-60.000041050085805` 的展示值可为 `-60`，实际格仍是 `-61`。搜索结果给出覆盖、遗漏和未知，执行前核验具体格。[现场观察](../../plugins/mc/bridge/partner-observe.cjs) · [玩家指向](../../plugins/mc/bridge/player-focus.cjs) · [送模数值](../../plugins/mc/src/partner_model_view.cpp)

- 玩家说“这两个开口都补”时，原话给出范围。插件将同一帧内的候选、尺寸、准星命中和库存交给模型。两个开口各需两块、当前只有两块时，可以先说明还缺两块。玩家说“只补左边”时，仅该侧进入授权范围。详细地形可沿观察号查回同一帧。[区域读回](../../plugins/mc/bridge/block-survey.cjs) · [目标绑定](../../plugins/mc/src/partner_task.cpp)
- 委托“把这一格挖掉”要求原对象与当前格一致。获准“就地备两块泥土”时，伙伴可以在约定内比较候选。查询准星的次数和某格可否采掘分别核算。受保护对象、未加载的格和材质变化各有回执。[采掘及实际读回](../../plugins/mc/bridge/collection.cjs)
- 本人生命、饥饿和余气分别来自相关游戏包，读数绑定当前角色实体、世界和采样时刻。水中的岸边查询只提供局部路径证据。掉落观察覆盖客户端实际追踪到的实体，原 UUID、物品和数量可用于稍后重查。实体消失时须另有证据才能归属拾取。[本人状态](../../plugins/mc/bridge/self-vitals.cjs) · [岸边站位](../../plugins/mc/bridge/shore.cjs) · [地面物品](../../plugins/mc/bridge/dropped-items.cjs)

## 工具范围与渐进披露

游戏 API 封装读写，插件工具为当前回合提供有边界的操作，插件 Skill 说明一类任务怎样选证据、组合工具、判断完成及处理受阻。“就近取材”在相关回合展开，覆盖查库存、选定或自选来源、等待实际入包及缺证补查。人格和固定同场约定进入稳定系统段，当前任务、原话、最近的在途工作与 `mcGuidance` 进入正文。各入口的实际消息和工具以 `model.prepared` 为查证入口。[技能定义](../../plugins/mc/src/partner_skills.hpp) · [指引与回合装配](../../plugins/mc/src/partner_loop.cpp) · [请求断言](../../tests/mc-companion/partner-context.cjs)

| 入口 | 当前约束 |
| --- | --- |
| 直调 | `observe`、`start_move`、`follow`、`collect`、`dig_block`、`gather_ground`、`pickup_drop`、`give_item`、`store_item`、`withdraw_item`、`place` 等由当前工具范围决定是否提供。定向放置还需已绑定目标。`skills` 查能力，`knowledge` 查版本化规则。 |
| 普通顺序队列 | `queue_actions` 可以排移动、跟随、采集、地面补库存和放置。类别、队列操作及该入口支持的形态均在接纳时检查。 |
| 有依赖的短计划 | 最多四个节点，可声明原话观察、精确移动、闭环路线、采掘、拾取、给物、放置及木板合成等。观察节点只接受其计划形态的参数。首批合成为原木或菌柄到相应木板，期望新增 1～32 件，按配方批量检查实际耗料、产出和库存。 |
| 控制与表达 | `reply`、`ask_player`、`task_update`、`stop_motion`、`withdraw_confirmation` 各有投递、局内事项、任务、移动或审批作用范围。委托和内部结算回合使用各自的输出目的地。 |

`skills` 每次可要求展开最多三类，目录区分能力是否已实现、此轮能否看见、支持哪种提交方式和执行所缺条件。显式展开的原工具回执只记录这次新增的独立工具及其 SDK 契约，后续模型请求再显示实际可用的工具。目录已有物品使用、游戏内攻击、方块及实体交互分类，这些分类的可执行范围仍取决于已注册工具。入口、运行时条件及用例见[技能注册与参数](../../plugins/mc/src/partner_skills.hpp)、[顺序队列](../../plugins/mc/src/partner_queue.cpp)和[短计划](../../plugins/mc/src/partner_plan.cpp)。

## 目标、待答与动作结算

同一原话中的指定对象、数量、允许替换范围和完成条件分别保存。进度询问可在原任务进行中得到答复。补充线索使受影响的步骤重验现场。用户纠正任务时，`begin_correction` 保留原输入并停止失效步骤，已开工的动作沿原号跟到退出。`commit_correction` 再用纠正原话和新取证的格切换任务修订。失效的批准说明原事项的决定，动作仍须依据当前现场核验。[任务修订](../../plugins/mc/src/partner_task.cpp) · [计划调度](../../plugins/mc/src/partner_plan.cpp)

局内追问区分“应回答哪句玩家原话”和“哪些后续消息有资格答题”。多事项按事项号、玩家、任务修订和操作范围配对，倒序回答仍仅解锁对应步骤。候选在开问时固定，玩家可以先收到编号提示再收到长问题，归属还需核对实际呈现。普通观察、聊天和原授权下的独立步骤可以继续。超时保留待答约束。需要额外授权时，直接 ASK 或经主 Agent 的回信带原事项回插件，再检查执行条件。[追问与到期](../../plugins/mc/src/partner_question.cpp) · [确认回执](../../plugins/mc/src/partner_confirm.cpp)

| 决策依据 | 受理、实效与退出怎样核对 |
| --- | --- |
| 角色资源和替换 | 移动、挖掘、放置共享同一前台槽，独立观察、交谈可并行。相冲突的变更须等原工作实际退出。跟随可用同一逻辑号续接，桥接执行段另有编号。[游戏工作](../../plugins/mc/src/game_work.cpp) · [跟随执行](../../plugins/mc/bridge/follow.cjs) |
| 采掘、合成、放置 | 破坏格、生成掉落、本人拾取和净入包分别记录。依赖材料的后继等入包，依赖腾空或落块的后继等方格读回。补四格墙时，前两格已成功、其余被占，清障后只补剩余格。门的上下格和玩家保留的支撑都在作用范围校验内。[步骤效果](../../plugins/mc/src/partner_effect.hpp) · [放置](../../plugins/mc/bridge/placement.cjs) |
| 指定堆拾取 | 首次须有原范围观察和整堆 UUID、物品、数量。本人拾取与库存净增相符才算入包。续取限已退出的受阻工作，按原堆扣除本人、他方已核实的份额后复查。旁堆、编号复用、合堆或缺证导致的未知不得计入。[续取](../../plugins/mc/bridge/pickup-drop.cjs) · [原实体证据](../../plugins/mc/bridge/drop-tracker.cjs) |
| 生存交物 | `observe(mode=handoff)` 查指定玩家与普通库存，投物前重验身份、距离和槽位。玩家离开三格范围则停止当次投物，需要时沿同一分工重新会合。“已投出”“对方已拾取”“尚未核实”分别结算。缺少服务端旁证时保留未知，迟到收件沿原号补记。[动态会合](../../plugins/mc/bridge/navigation.cjs) · [投物与收件](../../plugins/mc/bridge/handoff-evidence.cjs) |
| 普通单箱 | 原话指向固定箱格，复核世界、触及和窗口，读取箱内 27 格及伙伴普通背包与快捷栏 36 格。存取按双方实测数量对应。原窗口中断可沿原工作只读复核。取出再交本人须引用原取箱号，只能给该笔实取量。缺料、满包、拆栈不安全均保留实际量。[单箱观察](../../plugins/mc/bridge/single-chest.cjs) · [转移](../../plugins/mc/bridge/chest-transfer.cjs) |

## 消息、唤醒与控制

`chat.read` 读取聊天，`partner.listen` 申请或续期角色执行持权。桥接在线、能读取消息和持有角色执行权分别报告。当前实例持权且处于 `partner/ready` 时可开子回合并提交工作。普通退出以 `control.detach` 释放本实例，显式角色级 `control.stop` 关闭执行入口并保留读口。短断线后按原游标和原工作核查，未证实实际退出时保留资源占用。玩家自然语言提出接手进入对话，明确控制请求由实际执行入口处理。[角色持权](../../plugins/mc/bridge/controller.cjs) · [桥接分派](../../plugins/mc/bridge/pipe.cjs)

玩家问进度时可以读原工作的新鲜样本并回复。显式发言、最终文本按原消息或回合及投递身份防重，独立原话可以收到相同文字。受理、桥接提交、玩家实际收到和宿主归档可能发生在不同时刻。等待收件时若后来已经核实实收，就按最新结果发言。未知投递沿原号查询。[游戏聊天](../../plugins/mc/bridge/chat.cjs) · [同批发言验收](../../tests/mc-companion/batch-replies.cjs)

- **持续跟随。** 桥接约每 125 毫秒取样。距离长期大于期望值 2 格且 3 秒未缩短至少 1 格、至少 2 格高差并连续 2 秒明确无路、失去实体 5 秒等条件分别形成异常。同次异常只唤醒一次，恢复需回到范围内并持续可达，现场变化后才续接原跟随。[采样窗口](../../plugins/mc/src/follow_attention.hpp)
- **本人缺氧。** 归并同一角色、世界和耗尽过程的空气样本，普通续行额度用完仍可有独立只读复查。自主复查至少间隔 5 秒，插话能带入期间积累的事实，并在低优先级读口实退后接替。岸边采样可报告可达、受阻和未确认。当前已验证到只读复查。危险分类与伙伴自主选择动作见[生活目标与权限](#生活目标与权限)。[空气样本](../../plugins/mc/bridge/self-vitals.cjs) · [只读岸边](../../plugins/mc/bridge/shore.cjs)
- **选定玩家试点。** `factPlayer` 匹配并协商成功时，事实帧绑定玩家、工作和任务执行修订。目标可撤样，历史冻结快照仍可按原号、同实例观察授权查原值。等待审批按原工作持续关注，未执行的终态在信箱接纳后以原消息号创建一次性关注。取材环境和已核实的拾取实效也可沿原工作进入冻结快照。普通绑定沿用原渠道。[领域状态声明](../../plugins/mc/resources/agent/status.json) · [产生与撤回样本](../../plugins/mc/src/partner_facts.cpp) · [宿主快照验收](../../tests/mc-companion/mc_status_sample.cpp)

## 生活目标与权限

以下为已采纳的产品设计，功能接入进度见[权限与生活的开发项](../开发计划/MC伙伴开发计划.md#mc-权限-02)。

- **没有共同分工时**，伙伴以生存与生活为目标。她可以自行决定怎样活下去、探索世界和改善身边环境，例如在天黑前返回已知的安全地点。主人建立共同分工后，任务保留原话、范围和修订。别的玩家说“跟我走”或“河边有怪物”属于带来源的环境事件，伙伴可以回应或核实现场。其他玩家的发言不能授权动作、接管或改变主人的分工。产品不提供多人共同授权。
- **动作以游戏内的生存能力为限。** 实际采掘、携带、按材料放置和修复构成改善环境的途径。创造取物和特权世界编辑不设接口或执行入口，也不在能力目录、工具说明和模型发现结果中出现。不得以通用服务器命令绕过这条边界。当前放置实现对创造模式有免扣材料的成功条件，该路径仍须按生存约束验收。[当前判定](../../plugins/mc/bridge/placement.cjs#L116) · [落实范围](../开发计划/MC伙伴开发计划.md#mc-权限-01)
- **危险是供伙伴作决定的现场事实。** 缺氧、火、跌落属于环境危险，敌对生物接近或追逐属于生物危险。被动事件可唤醒，主动观察可补证，两类信息均保留对象、世界、时刻和覆盖范围。一次现场可同时出现两类危险。由大肥鱼决定避开、上岸、求助、再观察或继续原事，执行器复核已有授权和当前现场，随后记录实际效果。危险标签本身不触发预设动作。

当前桥接按本局配置的 `owner` UUID 识别配对玩家。主体绑定主人、旁人发言进入环境事件、由插件专用启动器初始化身份，均是后续交付。[现有收件](../../plugins/mc/bridge/chat.cjs#L59) · [主体身份](项目架构设计.md#主人身份与游戏绑定) · [启动器](../开发计划/MC伙伴开发计划.md#mc-连接-04)

## 边界与验证

当前技术边界是独立 Mineflayer 角色和可验证的 Java 版场地。普通服务器只给出角色可见的事实。Paper 可选旁证能补充投掷、合堆和收件归属，证据缺失时原工作保留未知。固定圆石场景用于核验配对、领工、实物、信箱和交还等链路。产品新增能力由主题计划逐项立项。[游戏侧证据](../../plugins/mc/bridge/stone-evidence.cjs) · [MC 伙伴使用说明](../使用说明/MC伙伴使用说明.md)

验收按玩家原话串起实际送模、工具裁定、动作、游戏读回、退出和玩家实收。发言快慢用玩家端同一时钟测量首条有用反馈，持续工作按原工作号查看实际进展。开发和回归使用固定响应，不同初始位置、材料、授权和回复顺序应得到相应的确定结果。复跑和诊断有独立操作入口。[MC 本地验收说明](../使用说明/MC本地验收说明.md) · [MC 轨迹查看器说明](../使用说明/MC轨迹查看器说明.md)
