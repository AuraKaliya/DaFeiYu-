## 立项理念与原始需求

计划起点为 2026 年 11 月 19 日的 `26eb36b`，原始方案为 `44d1a3b`。用户说“去窗边等我”后，大肥鱼应从书桌真实移动，确认到达才答复，随后能够一边等候一边聊天。“隔着屏风问台灯”则要求她知道自己能看见和听见什么。两个场景都应在关闭房间视图后继续成立，运行主体是本体与身体。

## 目标与范围

一间原生书房包括书桌、窗边、台灯和屏风。先验收空插件聊天和感知，再接原生动作、主会话授权与端到端答复；视图可替换。主动读周围、身体移动、询问主 Agent 及观察面板分别遵循各自权限，长期记忆及通用多 Agent 协作由其他主题独立评审。[内置书房设计](../设计/内置书房设计.md) · [管理中心开发计划](管理中心开发计划.md)

## 实施顺序与整体验收

依赖栏中的数字均指本计划。14 从原生停止、改向与等候开始，15 接入灯的可验证状态变化，16 提供正式会话的受限读口。17 先接一项具名目标移动，再逐项接停止、等候与设灯。18 绑定原委托和抵达后的答复。19 用真实视图读回效果和持续动作，20 从空插件安装包执行联合验收。

| 场景 | 必须能核对的证据 |
|---|---|
| 首次进入与普通问答 | 空插件目录、打开时模型调用数为零。页面真实提交后观测固定模型输入与完整回答。桌面首版另验关闭后继续运行及重启后消息补读。 |
| 去窗边等我 | 原指令、获准参数、动作号、至少一次在途查询、同一角色的到达读回、等候状态、最终答复按顺序关联。回合退出后继续等待，再发消息可正常交谈。 |
| 隔着屏风问台灯 | 离开前亲见亮，之后灯灭。被遮挡且超听距时只可返回上次确认及其时刻。处于听距内仅有声音，重新走近才可见当前灯态。检查工具输出和实际送给模型的上下文。 |
| 被告知与环境隔离 | 用户说“灯亮了”可收到并标明来源，环境原值不随消息改变。另一个同名房间及已撤销来源产生的事件，在被动记录和主动查询里均不可见。 |
| 忙时消息与停止 | 慢模型、在途工具和刚好结算三种时机分别发送。逐条核对已接收、已带入请求、排队到新轮或未带入。停止时已发生效果可查、迟到完成不重启旧轮。 |
| 受阻、断开与重建 | 阻塞路径、途中停下、旧视图重复命令、观察断档和实例更换均有明确结果。重连沿用进程内回执，重新采样保持相同感知限制。 |
| 表现可替换 | 文字视图与替换组件读取同一组房间事实。隐藏窗口、减少动效、中文组合输入、键盘操作及窄布局均保留相同业务行为。 |

使用固定模型响应、可控传输、可注入时钟和原生窗口。不同措辞能否自然听懂、真实模型会否选对工具、语言风格是否符合期望均“仅记录，不执行”。最终验收在 Debug、Release 和安装后的普通入口核对结果。主线 `88d8324` 的既有全量仅截至书房-13，未来端到端条件须分别取证。[原生书房回归](../../apps/host/tests/room_perception.cpp) · [桌面窗口回归](../../apps/desktop/tests/ui_main_panel.cpp) · [桌面管理中心说明](../使用说明/桌面管理中心说明.md)
